# Dark SaaS Design

검정 배경 + 포인트 하나의 한국어 B2B SaaS 시각 언어로 화면을 만든다.
취향이 아니라 계산된 토큰·격자·모션 규칙을 따른다.

## 이 시각 언어의 근거

**값은 외우는 것이 아니라 계산되는 것이다.** 팔레트는 WCAG 대비 하한과 OKLCH
좌표에서, 간격은 8pt 사다리에서, radius는 `컨테이너 높이 × 0.125`에서, 활자는
`크기 4의 배수 · 행간 8의 배수`에서 나온다. 파생 절차의 정본은 `references/derive.md`다.

그래서 이 스킬은 **구조를 고정하고 값을 교체하는** 방식으로 쓴다. 포인트 hue,
컨테이너 폭, 서체는 프로젝트마다 바뀔 수 있고, 바뀌어도 시스템은 그대로
성립한다. 바뀌면 안 되는 것은 값이 아니라 규칙이다 — 포인트가 하나라는 것,
면을 선으로 나눈다는 것, 굵기를 가변축으로 준다는 것.

특정 사이트를 그대로 흉내 낸 룩얼라이크를 만들어 달라는 요청은 거절하고,
이 시각 언어로 독립된 화면을 만든다. 로고·상호·카피·미디어 에셋은 이 스킬에
없고 재현 대상도 아니다.

## 모듈 라우팅

본문은 항상 로드한다. 아래는 조건이 맞을 때만 연다.

| 언제 | 연다 |
| --- | --- |
| 색·타이포·간격·radius 수치 | `references/tokens.css` |
| 값을 바꿔야 할 때, 값의 근거를 물을 때 | `references/derive.md` |
| 페이지 구성·섹션 순서·블록 선택 | `references/pages.md` |
| 섹션·컴포넌트 레시피, 비주얼 에셋, 제품 UI | `references/patterns.md` |
| 등장·스티키·리빌·글로우·페이지 전환·접근성 | `references/motion.md` |

온톨로지 보강은 별도 조건이다. `~/.ontology/ontology.db`가 있고, 증명 축·브랜드
확정값·목업에 넣을 실제 도메인 어휘가 필요할 때만 `references/ontology-boost.md`를
편다. **온톨로지가 없어도** 이 스킬은 파생 규칙만으로 완결된다.

| 산출물 | 적용 |
| --- | --- |
| 다크 랜딩·마케팅 페이지 | 필수 — 이 시스템이 가장 단단한 영역 |
| 제품 소개·기능 상세·요금 페이지 | 필수 — `pages.md`에서 증명 축을 먼저 정한다 |

| 카피·문구만 | 범위 밖 → `ux-writing` |
| 슬롭 진단만 (수정 없음) | 범위 밖 → `design-slop-audit` |
| Day0 / `@day0/ui` 신호 있음 | 범위 밖 → `day0-design` |

## 한 줄 아이덴티티

**검정 위 1px 보더 + Pretendard 가변축 위계 + 포인트 하나 + 그림자 0.**

- **면 색이 섹션을 나눈다.** 랜딩은 전부 검정, 제품·요금 페이지는 다크 히어로로
  열고 라이트 본문으로 읽힌다. 면 전환은 페이지당 3~4회.
- 면을 띄우지 않는다. 카드도 배경도 같은 검정이고, 구분은 1px 보더가 한다.
- 굵기는 `font-variation-settings: "wght"`로 준다. `font-weight`가 아니다.
- 포인트는 하나. 강조가 하나 더 필요하면 같은 hue의 밝은 칸을 쓴다.
- 세로 리듬 128px, 컨테이너 1200px, radius는 12/8/6 세 값뿐.
- 움직임은 등장·스택·리빌·마퀴·글로우·전환 여섯 가지. 이징은 하나.

## 구현 규칙

1. **바닐라 CSS + CSS 변수(`--ds-*`).** Tailwind 유틸로 화면을 짜지 않는다.
   `tokens.css`를 그대로 가져다 쓰고, 값은 하드코딩하지 않는다.
2. **클래스 프리픽스 `ds-`.** 상태는 `data-*` 속성으로 표현한다
   (`data-visible`, `data-open`, `data-variant`).
3. **폰트는 Pretendard Variable 한 벌.** 라틴 전용 서체를 두 번째로 들이지 않는다.
4. **브레이크포인트 3단**: `≤767` / `768~1279` / `≥1280`. 그 사이에 새 단을
   만들지 않는다.
5. **8pt 사다리 밖 간격과 세 값 밖 radius를 만들지 않는다.** 필요해 보이면
   이웃 칸을 고르고, 둘 다 틀려 보이면 문제는 값이 아니라 내용의 양이다.

## 금지

넣으면 다른 디자인이 된다.

| 금지 | 대신 |
| --- | --- |
| `box-shadow`로 카드 띄우기 | 1px 보더 |
| `backdrop-filter` 글래스모피즘 | 불투명 검정 |
| CSS `linear-gradient` 히어로 배경 | blur 글로우 레이어 또는 미디어 에셋 |
| `border-radius: 999px` 알약 | 계산된 radius (12/8/6) |
| `font-weight: bold` | `font-variation-settings: "wght" 700` |
| 포인트 hue 2개 이상 | 하나. 강조는 같은 hue의 밝은 칸 |
| hover 시 확대·이동 | 색 전환만 (160ms) |
| 대문자 변환 + 자간 확대 라벨 | 한국어 원문 그대로 |
| 텍스트에 알파 색 쌓기 | 대비로 정의한 불투명 값 |

## 작업 순서

1. `tokens.css`를 프로젝트에 넣고 `:root`를 연결한다. 브랜드 색이 이미 있으면
   `derive.md` §1의 대비 계산부터 돌린다.
2. `pages.md`에서 **증명 축을 한 문장으로 쓴다.** 그다음 블록 목록을 확정한다.
   아키타입의 순서를 복제하지 말고 그 페이지가 증명할 것에 맞춰 고른다.
3. 격자부터 잡는다 — 컨테이너 1200, 세로 리듬 128, gap 48.
4. 타입 스케일을 `patterns.md` §1 표대로 심는다. 굵기는 축으로, 행간은 px로.
5. 컴포넌트를 레시피에서 고른다. 새 radius·새 간격 값을 만들지 않는다.
6. 모션은 마지막에, `motion.md`의 여섯 가지 안에서만 얹는다.
7. `prefers-reduced-motion` 대응을 반드시 넣는다.

## 자가 점검

산출물을 내기 전에 확인한다.

**계산**

- [ ] 포인트가 흰 글씨 4.5:1과 검정 면 3:1을 함께 통과하는가
- [ ] 라이트면 포인트가 흰 배경에서 4.5:1인가
- [ ] 보더가 검정 대비 1.4~1.6 창 안인가
- [ ] radius가 12/8/6 밖으로 나가지 않았는가
- [ ] 간격이 8pt 사다리 안에만 있는가
- [ ] 크기가 4의 배수, 행간이 8의 배수인가
- [ ] 정의하지 않은 `--ds-*` 변수를 쓴 곳이 없는가
      (행간 토큰이 빠지면 제목 행간이 통째로 풀린다)

**구조**

- [ ] `box-shadow`·`backdrop-filter`·`linear-gradient`가 0인가
- [ ] 굵기를 `font-variation-settings`로 줬는가
- [ ] 포인트 hue가 하나인가
- [ ] 텍스트 색에 알파를 쌓지 않았는가
- [ ] 페이지마다 증명 축이 한 문장으로 적혀 있는가
- [ ] 같은 면(흰색·밴드·검정)을 세 블록 넘게 연속하지 않았는가
- [ ] 면 전환이 페이지당 3~4회인가
- [ ] 밴드가 페이지당 하나인가
- [ ] 섹션 순서를 다른 페이지에서 그대로 복제하지 않았는가
- [ ] 내비의 모든 항목이 실제로 그 내용이 있는 곳으로 가는가
      (`요금`이 CTA 밴드로 가면 안 된다 — 요금은 앵커가 아니라 페이지다)

**렌더**

- [ ] 목업 패널이 `scrollHeight > clientHeight`인 곳이 하나도 없는가
      (1440·1280·1024·860·768·390 여섯 폭 전부. 잘린 값 하나가 화면을 싸 보이게 한다)
- [ ] 회색 액자 안에 흰 카드를 띄우지 않았는가 (프레임이 곧 패널이다)
- [ ] 카드 비주얼 컬럼에 배경색과 패딩이 없는가 (있으면 카드가 쪼개 보인다)
- [ ] 카드 제목이 두 줄 안에 들어가는가
- [ ] 라우트마다 h1이 64px인가 (40px이면 그 라우트의 CSS가 안 붙은 것이다)
- [ ] 해시를 주소창에 직접 넣고 새로고침해도 같은 화면이 나오는가

**모션**

- [ ] 글로우가 히어로 면적의 1/3 이하인가 (화면 대부분은 검정)
- [ ] 글로우가 20~40초 주기로 표류하는가 (정적이면 죽은 배경이다)
- [ ] 리빌 문장이 화면 가운데 왔을 때 절반쯤 채워지는가
- [ ] 페이지 전환 커튼이 내비를 덮지 않는가 (z-index가 내비보다 아래인가)
- [ ] `prefers-reduced-motion` 분기가 있는가
