# Dark SaaS Design

검정 배경 + 바이올렛 포인트의 한국어 B2B SaaS 시각 언어로 화면을 만든다.
취향이 아니라 실측된 토큰·격자·모션 규칙을 따른다.

## 출처와 신뢰도

운영 중인 한국어 B2B SaaS 사이트 한 곳의 랜딩·제품 허브·기능 상세·가격
페이지를 2026-09-04에 실측해 만들었다. 페이지가 내보낸 CSS 변수 정의 회수 +
Chromium 1440/390 `getComputedStyle` + 목업 픽셀 샘플링. `tokens.css`의 `[정본]`은 실측값 그대로, `[샘플]`은 이미지
근사치다.

**가져온 것은 색·간격·위계·모션 규칙뿐이다.** 로고·상호·카피·미디어 에셋,
섹션 문구, 브랜드 마크는 이 스킬에 없고 재현 대상도 아니다. 특정 사이트를
그대로 흉내 낸 룩얼라이크를 만들어 달라는 요청은 거절하고, 이 시각 언어로
독립된 화면을 만든다.

## 한 줄 아이덴티티

**검정 위 1px 보더 + Pretendard 가변축 위계 + 바이올렛 하나 + 그림자 0.**

- **면 색이 섹션을 나눈다.** 랜딩은 전부 검정, 제품·가격 페이지는 다크 히어로로
  열고 라이트 본문으로 읽힌다. 같은 면을 세 블록 넘게 잇지 않는다.
- 면을 띄우지 않는다. 카드도 배경도 같은 검정이고, 구분은 `#333` 1px이 한다.
- 굵기는 `font-variation-settings: "wght"`로 준다. `font-weight`가 아니다.
- 포인트는 `#622eec` 하나. 라임(`#c9fd21`)은 배지 한두 개까지만.
- 세로 리듬 120px, 컨테이너 1224px, radius는 10/12/8 세 값뿐.
- 움직임은 등장·스티키·리빌·마퀴·글로우·페이지 전환 여섯 가지. 이징은 하나.

## 구현 규칙

1. **바닐라 CSS + CSS 변수(`--ds-*`).** Tailwind 유틸로 화면을 짜지 않는다.
   `tokens.css`를 그대로 가져다 쓰고, 값은 하드코딩하지 않는다.
2. **클래스 프리픽스 `ds-`.** 상태는 `data-*` 속성으로 표현한다
   (`data-visible`, `data-open`, `data-variant`).
3. **폰트는 Pretendard Variable 한 벌.** Poppins는 푸터 컬럼 제목 같은 라틴
   라벨에만 쓴다. 두 벌을 넘기지 않는다.
4. **브레이크포인트 3단**: `≤809` / `810~1439` / `≥1440`. 그 사이에 새 단을
   만들지 않는다.
5. **모든 텍스트에 자간 -0.02em.** 14~16px 컨트롤만 0.

## 금지 (실측 근거)

원본에서 0회 등장한다. 넣으면 다른 디자인이 된다.

| 금지 | 대신 |
| --- | --- |
| `box-shadow`로 카드 띄우기 | 1px 보더 |
| `backdrop-filter` 글래스모피즘 | 불투명 `rgba(0,0,0,0.85)` |
| CSS `linear-gradient` 히어로 배경 | blur 레이어 또는 미디어 에셋 |
| `border-radius: 999px` 알약 | radius 8px |
| `font-weight: bold` | `font-variation-settings: "wght" 750` |
| 포인트 컬러 2개 이상 | 바이올렛 하나 |
| hover 시 확대·이동 | 색 전환만 (`.4s`) |
| 대문자 변환 + 자간 확대 라벨 | 한국어 원문 그대로 |

## 작업 순서

1. `tokens.css`를 프로젝트에 넣고 `:root`를 연결한다.
2. `pages.md`에서 아키타입을 고르고 블록 목록을 먼저 확정한다.
   순서를 복제하지 말고 제품이 증명해야 할 것에 맞춰 고른다.
3. 격자부터 잡는다 — 컨테이너 1224, 섹션 120px, gap 64px.
4. 타입 스케일을 `patterns.md` §1 표대로 심는다. 굵기는 축으로.
5. 컴포넌트를 레시피에서 고른다. 새 radius·새 gap 값을 만들지 않는다.
6. 모션은 마지막에, `motion.md`의 여섯 가지 안에서만 얹는다.
7. `prefers-reduced-motion` 대응을 반드시 넣는다.

## 자가 점검

산출물을 내기 전에 확인한다.

- [ ] `box-shadow`·`backdrop-filter`·`linear-gradient`가 0인가
- [ ] 굵기를 `font-variation-settings`로 줬는가
- [ ] radius가 10/12/8 밖으로 나가지 않았는가
- [ ] 포인트 컬러가 하나인가
- [ ] 데스크톱 섹션 제목 행간이 1.0em인가
- [ ] 모바일에서 세로 리듬이 60px, 거터가 20px인가
- [ ] 글로우가 히어로 면적의 1/3 이하인가 (화면 대부분은 검정)
- [ ] 글로우가 20~40초 주기로 표류하는가 (정적이면 죽은 배경이다)
- [ ] 리빌 문장이 화면 가운데 왔을 때 절반쯤 채워지는가
- [ ] 카드 비주얼 컬럼에 배경색과 패딩이 없는가 (있으면 카드가 쪼개 보인다)
- [ ] 목업 패널이 `scrollHeight > clientHeight`인 곳이 하나도 없는가
      (1440·1180·1024·860·390·360 여섯 폭 전부. 잘린 값 하나가 화면을 싸 보이게 한다)
- [ ] 회색 액자 안에 흰 카드를 띄우지 않았는가 (프레임이 곧 패널이다)
- [ ] 정의하지 않은 `--ds-*` 변수를 쓴 곳이 없는가
      (line-height 토큰이 빠지면 제목 행간이 통째로 풀린다)
- [ ] 라우트마다 h1이 60px인가 (32px이면 그 라우트의 CSS가 안 붙은 것이다)
- [ ] 해시를 주소창에 직접 넣고 새로고침해도 같은 화면이 나오는가
- [ ] 카드 h3가 두 줄 안에 들어가는가
- [ ] 같은 면(흰색·밴드·검정)을 세 블록 넘게 연속하지 않았는가
- [ ] 밴드가 페이지당 하나인가
- [ ] 내비의 모든 항목이 실제로 그 내용이 있는 곳으로 가는가
      (`가격`이 CTA 밴드로 가면 안 된다 — 가격은 앵커가 아니라 페이지다)
- [ ] 섹션 순서를 다른 페이지에서 그대로 복제하지 않았는가
- [ ] 페이지 전환 커튼이 내비를 덮지 않는가 (z-index가 내비보다 아래인가)
- [ ] `prefers-reduced-motion` 분기가 있는가
