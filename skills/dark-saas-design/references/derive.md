# 파생 규칙 — 값은 어디서 나오는가

이 시각 언어에는 외운 값이 없다. 팔레트도 격자도 활자도 제약에서 계산된다.
그래서 **브랜드 색이 정해져 있어도, 컨테이너 폭이 달라도 같은 시스템이 성립한다.**

교체되는 것과 고정되는 것을 먼저 나눈다.

| 교체 가능 (프로젝트마다) | 고정 (교체하면 다른 디자인) |
| --- | --- |
| 포인트 hue | 포인트가 하나라는 것 |
| 컨테이너 폭 | 12칼럼 정수 분할이 떨어질 것 |
| 서체 | 한 벌일 것, 굵기를 가변축으로 줄 것 |
| 기준 글자 크기 | 크기가 4의 배수, 행간이 8의 배수일 것 |
| 세로 리듬 값 | 8pt 사다리 밖 값을 만들지 않을 것 |
| 모션 지속 시간 | 이징이 하나일 것 |

왼쪽 열을 바꿀 때는 이 문서의 계산을 다시 돌려 `tokens.css`를 새로 만든다.
값 하나만 손으로 고치면 그 값만 시스템 밖으로 떨어진다.

## 1. 포인트 — 대비 창이 색을 고른다

포인트는 두 가지를 동시에 해야 한다.

- CTA 면으로 깔렸을 때 그 위 **흰 글씨가 읽힌다** → 흰색 대비 ≥ 4.5:1
- 검정 배경에서 **면 자체가 도드라진다** → 검정 대비 ≥ 3:1

이 둘은 서로를 밀어낸다. 밝히면 흰 글씨가 무너지고, 어둡히면 검정에 잠긴다.
둘을 함께 만족하는 구간은 **OKLCH L 0.50 ~ 0.58** 하나뿐이고, 이 창의 위치는
hue를 어디에 두든 거의 움직이지 않는다. 그래서 **hue는 취향으로 고르고 명도는
계산으로 고른다.**

```python
# 대비 창 확인 — hue를 바꿔도 이 스크립트가 답을 준다
def srgb_to_lin(c):
    c = c / 255
    return c / 12.92 if c <= 0.04045 else ((c + 0.055) / 1.055) ** 2.4

def luminance(hex_color):
    h = hex_color.lstrip("#")
    r, g, b = (srgb_to_lin(int(h[i:i + 2], 16)) for i in (0, 2, 4))
    return 0.2126 * r + 0.7152 * g + 0.0722 * b

def contrast(a, b):
    l1, l2 = sorted((luminance(a), luminance(b)))
    return (l2 + 0.05) / (l1 + 0.05)

assert contrast("#863ad2", "#ffffff") >= 4.5   # 5.92 — CTA 위 흰 글씨
assert contrast("#863ad2", "#000000") >= 3.0   # 3.55 — 검정 위 면
```

포인트 하나가 정해지면 나머지 넷은 같은 hue의 L만 옮겨 만든다.

| 토큰 | L | 쓰는 자리 | 지켜야 할 대비 |
| --- | --- | --- | --- |
| `--ds-accent` | .53 | 다크면 CTA·강조 면 | 흰 4.5:1 · 검정 3:1 |
| `--ds-accent-ink` | .42 | 라이트면 텍스트·아이콘 | 흰 배경 4.5:1 |
| `--ds-accent-hi` | .72 | 다크면 링크 hover·배지 글자 | 검정 4.5:1 |
| `--ds-accent-glow` | .60 | 글로우 레이어 | 없음 — 텍스트로 쓰지 않는다 |
| `--ds-tint` | .97 | 라이트 틴트 밴드 | 없음 — 면이다 |

**두 번째 hue를 들이지 않는다.** 강조가 하나 더 필요하면 `--ds-accent-hi`를 쓴다.
색을 하나 더 넣는 순간 사용자는 두 색의 관계를 해석하려 하고, 관계가 없으면
그 화면은 규칙이 없는 것으로 읽힌다.

**브랜드 색이 이미 정해져 있으면** 그 색의 L을 재서 창 안에 있는지 본다. 밖이면
브랜드 색은 로고와 강조 글자에 두고, 면으로 깔리는 자리에는 같은 hue에서 창 안으로
끌어온 값을 쓴다. 브랜드 색을 창 밖에서 면으로 쓰면 그 위 글자가 읽히지 않는다.

## 2. 잉크 — 대비로 정의하고 알파를 쓰지 않는다

다크면 텍스트를 `#ffffffbf` 같은 알파로 쌓으면, 같은 토큰이 검정 위와 띠 위에서
서로 다른 대비를 갖는다. 카드 위에 놓았을 때만 안 읽히는 회색이 이렇게 생긴다.
**불투명 값으로 고정하고 대비로 정의한다.**

| 다크면 | 검정 대비 | 라이트면 | 흰 배경 대비 |
| --- | --- | --- | --- |
| `--ds-ink` #fff | 21:1 | `--ds-graphite` #1b1b1b | 17.2:1 |
| `--ds-ink-2` #a4a4a4 | 8.4:1 | `--ds-slate` #525252 | 7.8:1 |
| `--ds-ink-3` #7a7a7a | 4.9:1 | `--ds-slate-2` #747474 | 4.7:1 |

세 단이면 충분하다. 네 번째 회색을 만들려는 순간, 필요한 것은 대개 색이 아니라
크기나 굵기의 차이다.

`--ds-ink-mute`(#525252, 2.69:1)만 예외로 하한 아래에 있다. 스크롤 리빌의 **대기
상태**라 최종 상태가 아니고, 모션이 꺼진 환경에서는 처음부터 `--ds-ink`로 둔다.

## 3. 선 — 보이되 면이 되지 않는 창

검정 위 보더는 검정 대비 **1.4 ~ 1.6** 안에 둔다. 1.4 아래면 경계가 사라져
카드가 배경에 녹고, 1.6 위면 선이 한 단 밝은 면으로 읽혀 카드가 떠 보인다.
`#2b2b2b`가 1.48:1로 이 창의 가운데다.

띠 섹션 안쪽처럼 배경이 이미 밝아진 자리에만 알파(`--ds-line-soft`)를 쓴다.
그 자리는 배경이 하나로 고정되어 있어 알파가 대비를 흔들지 않는다.

## 4. 간격 — 8pt 사다리

`8 · 16 · 24 · 32 · 48 · 64 · 96 · 128`  (`--ds-space-1` ~ `--ds-space-8`)

사다리 밖 값을 만들지 않는다. 54px이 필요해 보이면 48이나 64 중 하나가 맞는
값이고, 둘 다 틀려 보이면 문제는 간격이 아니라 그 자리에 든 내용의 양이다.

- 세로 리듬 128 (모바일 64) — 사다리의 맨 끝. 섹션 사이에만 쓴다
- 섹션 헤더와 본문 48
- 2열 그리드 48
- 카드 안쪽 패딩 48 (모바일 32)
- 요소 사이 8·16·24

## 5. 형태 — radius는 계산한다

```text
radius = 컨테이너 높이 × 0.125, 짝수로 반올림, 상한 12px
```

높이 48px 컨트롤은 6px, 96px을 넘는 면은 전부 상한 12px에 걸린다. 그래서 값이
셋밖에 나오지 않는다.

**중첩된 면은 바깥보다 한 단 작게 둔다.** 카드 12 → 안쪽 패널 8 → 컨트롤 6.
같은 값을 쓰면 두 모서리가 겹쳐 보여 안쪽 면이 카드 밖으로 밀려난 것처럼 읽힌다.

완전 원형은 쓰지 않는다. 알약 버튼은 이 시스템의 다른 모서리와 계보가 다르다.

## 6. 활자 — 크기는 4의 배수, 행간은 8의 배수

크기를 4의 배수로 두면 행간을 8의 배수로 떨어뜨릴 수 있고, 그래야 글 덩어리의
높이가 세로 격자에 맞아 **두 컬럼의 첫 줄과 마지막 줄이 나란히 선다.**

| 역할 | 크기 | 행간 | wght | 자간 |
| --- | --- | --- | --- | --- |
| display (h1) | 64 / 40 | 72 / 48 | 700 | -0.03em |
| section (h2) | 48 / 32 | 56 / 40 | 600 | -0.03em |
| block (h3) | 36 / 28 | 44 / 36 | 600 | -0.02em |
| card (h4) | 24 | 32 | 600 | -0.02em |
| lead | 20 / 18 | 32 / 28 | 450 | -0.02em |
| body | 16 | 28 | 450 | -0.01em |
| meta | 14 | 20 | 400 | 0 |

**자간은 크기에 따라 달라진다.** 큰 글자일수록 자간이 벌어 보이므로 더 조인다.
한 값을 전 크기에 걸면 제목이 헐겁거나 캡션이 뭉친다.

**굵기는 가변축으로 준다.** `font-weight: 700`이 아니라
`font-variation-settings: "wght" 700`이다. 축을 쓰면 600과 700 사이 중간값을
잡을 수 있고, 한글 본문에는 그 중간이 필요하다 — 400은 얇고 500은 무겁다.
그래서 본문이 **450**이다. 이 값은 100단위 웨이트로는 낼 수 없다.

## 7. 컨테이너 — 정수 분할이 떨어지는 폭

1200px을 쓰는 이유는 12칼럼 격자의 분할이 전부 정수로 떨어지기 때문이다.

```text
1/2 = 600   1/3 = 400   2/3 = 800   1/4 = 300   5/12 = 500   7/12 = 700
```

나누는 자리마다 소수점이 나오면 컬럼 폭이 브라우저마다 1px씩 어긋나고, 그
1px이 두 카드의 보더를 서로 다른 두께로 보이게 한다.

**다른 폭으로 바꿀 때**는 쓰려는 분할이 전부 정수인지 먼저 확인한다.
데스크톱 브레이크포인트도 함께 움직인다 — `컨테이너 + 거터 × 2`가 들어가는
최소 폭이 그 경계다 (1200 + 64 = 1264 → 1280).

## 8. 모션 — 이징 하나

`cubic-bezier(0.22, 1, 0.36, 1)`. 앞이 빠르고 끝이 길어서 요소가 도착한 자리에
얹히는 느낌을 준다. 지속 시간만 두 단으로 나눈다 — 위치가 바뀌면 320ms,
색만 바뀌면 160ms.

이징을 하나로 묶는 이유는 취향이 아니다. 화면마다 다른 이징을 쓰면 같은 제품의
움직임이 서로 다른 물리 법칙을 따르는 것으로 읽히고, 그 어긋남은 이유를 짚기
어려운 채로 남는다.

## 9. 교체 체크리스트

팔레트나 격자를 바꿨으면 아래를 다시 확인한다. 하나라도 못 지키면 값을 바꾼
것이 아니라 시스템을 깬 것이다.

- [ ] 포인트가 흰 글씨 4.5:1과 검정 면 3:1을 함께 통과하는가
- [ ] 라이트면 포인트가 흰 배경에서 4.5:1인가
- [ ] 잉크 세 단이 각각 21 / 8 / 4.5:1 근처인가
- [ ] 보더가 검정 대비 1.4~1.6 창 안인가
- [ ] radius가 계산식에서 나온 세 값뿐인가
- [ ] 간격이 8pt 사다리 안에만 있는가
- [ ] 크기가 4의 배수, 행간이 8의 배수인가
- [ ] 컨테이너의 12칼럼 분할이 전부 정수인가
- [ ] 데스크톱 브레이크포인트가 `컨테이너 + 거터 × 2` 이상인가
- [ ] 포인트 hue가 하나인가
