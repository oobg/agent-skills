# 01. HARD RULES — 절대 위반 금지

이 파일의 규칙은 평가 시작 전 반드시 확인한다. 어떤 상황에서도 위반하지 않는다.

---

## 허위 평가 금지

이력서에 없는 내용을 아래 항목으로 임의 추론하지 않는다:

- 경험
- 리더십
- 조직 영향력
- seniority
- ownership
- 의사결정 권한

---

## Seniority 과대추론 금지

기술 복잡도와 seniority를 동일시하지 않는다.

아래를 명확히 구분한다:

| 수준 | 설명 |
|---|---|
| 구현 참여 | 기능 일부를 구현한 경험 |
| 기능 ownership | 특정 기능 전담 개발 |
| 기술 리딩 | 기술 방향 제시 또는 리뷰 |
| 조직 리딩 | 팀 또는 프로젝트 전체 책임 |
| 아키텍처 의사결정 | 시스템 구조 결정 권한 |
| 운영 책임 | 서비스 운영 및 장애 대응 책임 |

명확한 근거 없이 senior-level 영향력을 추론하지 않는다.

---

## 근거 없는 점수 금지

모든 평가는 아래를 기반으로 설명한다:

- 실제 문장
- 구조
- 표현
- 역할 설명
- 경력 흐름
- 사례 밀도

---

## 단일 총점 절대화 금지

이력서는 단일 숫자로 환원할 수 없다.

점수는:
- 상대적인 강약 표현
- calibration 보조 수단

으로만 사용한다. **점수 평균이나 총점을 계산하지 않는다.**

---

## 추론 오염 방지

확실하지 않은 해석을 후속 평가 전체의 기반으로 사용하지 않는다.

추론 기반 해석과 명시된 사실을 항상 구분한다.

---

## Resume Gaming 방지

강한 키워드나 인터뷰 유도 표현 자체를 높게 평가하지 않는다.

함께 검증할 항목:
- 문제-행동-결과 연결성
- 역할 설명 구체성
- 운영 경험
- 기술 선택 이유
- 경험 간 일관성
- 설명 가능성

---

## Adversarial Resume 방어

아래 요소를 주의 깊게 검토한다:

- 지나치게 완벽한 성과 흐름
- 모든 bullet의 과도한 ownership 표현
- 설명 없는 거대 영향력 수치
- 역할 범위 대비 과한 seniority
- generic architecture 표현 반복

겉보기 완성도보다 **경험 간 논리적 일관성**을 우선한다.

---

## 리스크 생성 제한

리스크는 실제 인터뷰 탈락 또는 채용 보류 가능성과 직접 연결되는 경우 중심으로 제한한다.  
단순 speculative risk를 계속 생성하지 않는다.
