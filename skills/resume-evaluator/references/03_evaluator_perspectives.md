# 03. Multi-Evaluator 관점 기준

각 관점은 독립적으로 평가하되, 최종 판단에서 consensus를 종합한다.

---

## 1. ATS 관점

ATS(Applicant Tracking System)가 이력서를 어떻게 파싱·스코어링할지 평가한다.

**평가 요소:**

| 항목 | 확인 내용 |
|---|---|
| 직무명 표준화 | 표준 직무명 사용 여부 |
| 날짜/경력 파싱 안정성 | 날짜 포맷 일관성, 파싱 오류 가능성 |
| PDF/문서 구조 안정성 | 이중 컬럼, 표 기반 레이아웃 위험 |
| acronym 검색 가능성 | 약어 풀어쓰기 병행 여부 |
| semantic matching | JD 키워드와의 의미적 일치도 |
| 기술명 표기 일관성 | React vs ReactJS 등 혼용 여부 |
| JD keyword alignment | JD 주요 키워드 포함 여부 |

---

## 2. 리크루터 관점

채용 담당자가 30초~1분 내 빠르게 스크리닝할 때 어떻게 읽히는지 평가한다.

**평가 요소:**

| 항목 | 확인 내용 |
|---|---|
| 경력 흐름 | 직무 연속성, 성장 방향의 논리성 |
| 이직 패턴 | 재직 기간, 이직 횟수, 간격 |
| 첫인상 | 상단 정보의 명확성과 임팩트 |
| 인터뷰 호출 가능성 | 호기심을 유발하는 요소 존재 여부 |
| 시장 적합성 | 포지션과의 표면적 매칭 |
| 설명 명확성 | 역할과 성과의 이해 가능성 |

---

## 3. 실무자 관점

함께 일하게 될 시니어 개발자 또는 팀장이 기술적 신뢰도를 어떻게 판단할지 평가한다.

**평가 요소:**

| 항목 | 확인 내용 |
|---|---|
| 실제 수행 가능성 | 기술 스택과 경험의 현실성 |
| 기술 깊이 | 표면 키워드 vs 실제 활용 근거 |
| 운영 경험 | 서비스 운영, 장애 대응, 유지보수 |
| 문제 해결 경험 | 구체적 문제-행동-결과 흐름 |
| 역할 범위 | 실제 담당 범위의 명확성 |
| 유지보수 현실감 | 레거시, 마이그레이션, 기술 부채 경험 |
| 협업 구조 | 팀 규모, 역할 분담, 협업 방식 |

> 실무자 평가 역시 조직 문화와 평가자 경험에 영향받을 수 있음을 고려한다.

---

## 4. 임원 관점

조직 기여 가능성과 성장 잠재력, 리스크 관리를 중심으로 평가한다.

**평가 요소:**

| 항목 | 확인 내용 |
|---|---|
| 사업 기여 가능성 | 비즈니스 임팩트 연결 가능성 |
| 성장 가능성 | 커리어 궤적의 방향성과 속도 |
| 조직 적합성 | 조직 규모·문화와의 match |
| 커뮤니케이션 안정성 | 명확한 전달력, 협업 신호 |
| 영향력 가능성 | 조직 내 영향 범위 확장 가능성 |
| 리스크 관리 가능성 | 불확실한 이력, 반복 이직 등 리스크 요소 |

---

## Multi-Evaluator Consensus 분석

각 관점 평가 후 아래를 종합한다:

- **어느 그룹이 강하게 긍정하는가**
- **어느 그룹이 주요 리스크를 제기하는가**
- **실제 프로세스에서 누가 veto 영향력이 큰가**

모든 평가 관점을 동일 weight로 취급하지 않는다.  
실제 채용 프로세스에서 veto 영향력이 큰 관점(보통 실무자 또는 리크루터)의 우려를 더 무겁게 다룬다.
