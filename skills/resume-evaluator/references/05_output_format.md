# 출력 구성

요청 범위와 입력량에 맞춰 필요한 섹션만 사용한다. 고정된 섹션 수를 채우기 위해 근거가 약한 분석을 늘리지 않는다.

## 입력이 부족한 경우

이력서나 JD처럼 요청 수행에 필수인 입력만 요청한다.

- 이력서가 없으면 평가를 시작하지 않는다.
- 파일이 판독되지 않으면 읽을 수 있는 텍스트나 파일 형식을 요청한다.
- JD가 없더라도 일반 문서 진단을 요청했다면 가독성, 구체성, 내부 일관성과 확인 질문으로 범위를 제한한다.

## JD가 있는 기본 표

| JD 요구사항 | 이력서 원문 근거 | 상태 | 부족·불일치 설명 | 확인 질문 |
|---|---|---|---|---|

원문 근거에는 섹션명이나 bullet 위치를 붙인다. 인용은 판단에 필요한 짧은 범위만 사용한다. 근거가 없으면 "원문 근거 없음"이라고 쓰며 이를 역량 없음으로 바꾸지 않는다.

표 뒤에는 필요할 때만 다음을 덧붙인다.

- 실제 명시 불일치
- 정보 부족 또는 모순
- 관찰과 구분한 추론
- 해석을 바꿀 수 있는 반증
- 수정 우선순위

## JD가 없는 기본 출력

- **가독성**: 섹션, 날짜, 역할과 핵심 정보의 탐색 가능성
- **구체성**: 문제, 행동, 결과와 역할 범위가 드러나는지
- **내부 일관성**: 기간, 직함, 기술과 성과 서술의 충돌
- **면접 확인거리**: 문서만으로 판단할 수 없는 핵심 질문
- **수정 우선순위**: 오해 가능성과 정보 가치가 큰 순서

직무 적합성, 시장 위치, 성장 가능성이나 채용 가능성은 결론 내리지 않는다.

## 관점별 요청

사용자가 요청한 관점만 추가한다. 관점별로 관찰한 근거, 해석 가능성, 불확실성과 확인 질문을 쓴다. 여러 관점을 독립 검증이나 합의로 묘사하지 않는다.

ATS 항목은 관찰한 텍스트와 포맷으로 제한한다. 실제 파서 시험이 없으면 통과나 안정성을 보장하지 않는다.

## 복합 평가·수정 요청의 근거 패킷

수정 단계에 전달할 내용은 다음으로 제한한다.

- 대상 요구사항
- 원문 위치
- 관찰된 부족 또는 불일치
- 불확실성
- 수정 우선순위

새 경력이나 성과를 만들어 내지 않는다. 필요한 사실은 사용자에게 질문한다.

## 마무리

핵심 요구사항과 원문 근거가 연결되고, 불확실성이 표시되며, 수정 우선순위가 정해지면 종료한다.
