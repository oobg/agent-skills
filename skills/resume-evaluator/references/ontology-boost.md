# 선택 모듈: 온톨로지 입력 보강

`~/.ontology/ontology.db`가 있고 동일 지원자의 과거 기록으로 입력을 보강할 필요가 있을 때만
사용한다. DB가 없으면 이 파일을 무시하고 제공된 자료만으로 계속한다. 일반 평가의 필수 단계는
아니며, 상위 domain-ontology 스킬 자체의 자동 조회 트리거를 제한하지 않는다.

## 조회 규율

domain-ontology 스킬에 조회를 위임하고 `~/.ontology/AGENTS.md`와 `~/.ontology/docs/recall.md`의 정본 절차를 따른다. 이 파일에서 SQL이나 별도 조회 규약을 지어내지 않는다.

- 사용자 본인의 이력서임을 확인한 경우에만 personal과 현재 작업에 허용된 shared 범위를 조회한다.
- 제3자의 이력서에 사용자의 personal 경력을 섞지 않는다.
- 대상 동일성이나 허용 범위를 확인할 수 없으면 온톨로지를 조회하지 않고 제공된 자료만 사용한다.
- 다른 tenant로 조회 범위를 자동 확장하지 않는다.
- 과거 기록은 현재 사실로 확정하지 않고 입력 후보로만 다룬다.

DB, 정본 문서 또는 domain-ontology 스킬에 접근할 수 없는 경우 제공된 자료만으로 계속하고 조회하지 못했음을 알린다. 정상 조회가 0건인 경우는 접근 실패와 구분해 기록이 없다고 처리한다.

**`recall.md`가 없으면 SQL을 지어내지 말고 이 선택 모듈을 닫는다. 상위 스킬은 온톨로지
없이 기본 경로를 계속한다.**

**회수는 무엇을 봐야 하는가를 알려주는 것이고, 지금 어떤 상태인가의 증거가 아니다.**
과거 기록은 현재 이력서와 사용자 설명으로 다시 확인한 뒤에만 평가 입력으로 쓴다.

## 사용 범위

회수한 내용은 이력서의 누락 가능성을 확인하고, 모순이나 시점 차이를 표시하며, 필요한 질문을 구체화하는 데만 사용한다. 온톨로지는 판정 권한을 확대하지 않는다. 시장 위치, 직무 적합성이나 채용 결론의 단독 근거로 사용하지 않는다.

## 바뀌지 않는 것

- 온톨로지는 입력만 보강한다. 이 스킬의 발동 조건·게이트·판정 기준·실행 권한을 넓히지 않는다.
- 이 스킬은 온톨로지에 쓰지 않는다. 이력서와 평가 결과를 자동 적재하지 않는다.
- 스코프 밖 tenant의 문서·claim·건수는 평가 입력이나 보고에 넣지 않는다.
- 정보 충분성, 불일치, 확인 질문을 진단하는 범위와 Hire/No Hire를 단정하지 않는 경계는 그대로다.

## 적재 경계

이력서, 평가 결과나 대화 로그를 자동 적재하지 않는다. 새 정보를 저장하려면 별도의 사용자 동의와 문서별 tenant 확인이 필요하며 실제 적재는 domain-ontology 절차를 따른다. 실제 기록이나 조회 결과를 공개 저장소에 보관하지 않는다.
