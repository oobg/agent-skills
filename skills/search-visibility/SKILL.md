# Search Visibility

사이트를 검색·인용의 1차 소스로 만든다. 절차는 `진단 → 우선순위 승인 → 구현 →
크롤러 검증 → 측정 예약`이며, 측정 계획 없이 완료를 주장하지 않는다.

## 다섯 레인

| 레인 | 상대 | 상세 |
| --- | --- | --- |
| SEO | 검색 크롤러와 색인 | [seo.md](references/seo.md) |
| AEO | 검색 결과 상단의 AI 답변 박스 | [aeo.md](references/aeo.md) |
| GEO | 웹을 읽는 생성 AI | [geo.md](references/geo.md) |
| LLMO | 브라우징 없는 모델의 지식 | [llmo.md](references/llmo.md) |
| NEO | 네이버 검색과 AI 브리핑 | [neo-naver.md](references/neo-naver.md) |

측정은 레인이 아니라 모든 레인의 종료 조건이다. [measure.md](references/measure.md)를 따른다.
인용은 자리 다툼이므로 우리 사이트만 봐서는 왜 밀리는지 알 수 없다. 점유 상태를 볼 때는
[citation-competition.md](references/citation-competition.md)를 읽는다.

## 시작할 때

1. 대상을 확인한다. 배포된 도메인인지, 로컬 코드베이스인지, 둘 다인지.
2. 한국 시장 대상인지 확인한다. 맞으면 NEO를 선택이 아니라 필수 레인으로 둔다.
3. 코드 수정 권한이 있는지 확인한다. 없으면 고칠 위치를 파일·라인 수준으로 특정해 넘긴다.
4. Phase 0 진단을 먼저 실행한다. 진단 없이 개별 레인 작업으로 들어가지 않는다.
5. 축적된 도메인 지식이 필요한 국면이면 [ontology-boost.md](references/ontology-boost.md)를
   연다. 온톨로지가 없으면 이 스킬은 관측만으로 완결된다.

## 불변 원칙

1. **정공법만 한다.** 백링크 구매, 링크 품앗이, 자동화된 서로이웃·댓글, 클로킹,
   숨긴 텍스트, 문서 대량 복제는 사용자가 요청해도 수행하지 않는다. 거절 사실과
   이유를 보고에 남기고 대신 할 수 있는 정공법을 제시한다.
2. **화면이 사실 아닌 것을 말하게 하지 않는다.** 과장 메타, 근거 없는 구조화 데이터,
   가시 텍스트와 다른 JSON-LD는 인용 신뢰를 깎는다.
3. **크롤러의 눈으로 검증한다.** 판정 기준은 "코드에 있다"가 아니라 "자바스크립트 없이
   받은 HTML에 있다"이다. `curl` 증빙 없이 완료로 보고하지 않는다.
4. **1차 소스가 되는 것이 전략의 본체다.** 어떤 숫자·사실의 원출처가 될 수 있는지
   먼저 묻는다. 남의 데이터를 요약한 페이지는 원출처에 인용을 넘긴다.
5. **측정 없는 최적화는 주장이다.** 기준선을 찍지 않은 변경은 효과를 증명할 수 없다.
6. **유료 도구 없이 완결한다.** 공개 응답, 검색 결과 화면, 사용자의 검색 콘솔, 무료 관측
   소스만으로 진단과 구현이 끝난다. 유료 SEO 도구가 없다는 이유로 작업을 미루거나
   구독을 전제로 계획을 세우지 않는다.
7. **치명 항목은 다른 항목으로 상쇄되지 않는다.** 본문이 크롤러에게 보이지 않거나,
   `noindex`가 걸려 있거나, 가시 텍스트와 구조화 데이터가 어긋나면 그 레인은 나머지가
   아무리 좋아도 `미흡`이다. 좋은 항목을 세어 평균을 내지 않는다.
   단 **의도된 색인 제외는 결함이 아니다.** 스테이징, 파라미터 변형, 중복 억제처럼
   일부러 뺀 URL이면 사용자에게 확인하고 판정 대상에서 제외한 뒤 그 사실을 근거에 적는다.
   확인 전에는 `확인 불가`로 두고 `미흡`으로 내리지 않는다.

## 승인 게이트

사용자가 승인하기 전에는 다음 게이트를 넘지 않는다.

1. 진단 결과와 레인별 점수표
2. 우선순위와 이번에 손댈 범위
3. 코드 변경 계획 (파일 단위)
4. 배포 후 크롤러 검증 결과
5. 재측정 일정

보고를 확정하기 전에 [visibility-auditor](agents/visibility-auditor.md)로 결과만 보고
채점한다. 관측 없는 완료 주장은 검색 결과가 며칠 뒤에야 드러나므로 그때까지 들키지 않는다.

사용자가 특정 레인만 요청하면 그 레인에서 멈춘다. 진단만 요청받았으면 고치지 않는다.
계정 접속이 필요한 작업(서치어드바이저·Search Console 등록, 소유 확인)은 대신 하지 않고
절차를 안내한다.

## Phase 0 — 진단

다섯 레인을 훑어 점수표를 만든다. 배포된 도메인이면 크롤러의 눈으로 먼저 본다.
`scripts/crawl_audit.py`가 robots.txt, 사이트맵, llms.txt, 404 처리, 페이지별 메타와
구조화 데이터를 한 번에 관측한다.

```bash
python3 scripts/crawl_audit.py https://example.com --pages /pricing,/faq
```

이 스크립트는 **관측만 하고 레인 점수를 판정하지 않는다.** 기계적으로 갈리는 항목만
OK/FAIL로 찍고 나머지는 CHECK로 남기므로, CHECK를 양호로 올리지 않는다. 스크립트가 없는
환경이거나 개별 항목을 확인할 때는 직접 요청한다.

**무엇이 자동이고 무엇이 사람 몫인지는 스크립트에게 묻는다.**

```bash
python3 scripts/crawl_audit.py --coverage
```

이 목록을 문서에 옮겨 적지 않는다. 두 곳에 적으면 스크립트가 바뀔 때 문서가 남아
거짓말을 한다. 자동 항목을 손으로 다시 확인하느라 시간을 쓰지 말고, `--coverage`가
사람 몫이라고 표시한 것에 시간을 쓴다.

```bash
curl -sL https://example.com | grep -c "<h1"                          # 본문이 SSR로 나오는가
curl -sL https://example.com/robots.txt                                # 크롤러 정책
curl -sL https://example.com/sitemap.xml | head                        # 사이트맵 존재와 규모
curl -sL https://example.com/llms.txt                                  # GEO 준비 여부
curl -s -o /dev/null -w '%{http_code}\n' https://example.com/nonexistent  # 404가 404인가
```

점수표는 레인별 상태와 한 줄 근거로 낸다. 근거는 관측한 결과여야 하고 추정이면 추정이라고
적는다.

| 레인 | 상태 | 근거 |
| --- | --- | --- |
| SEO | 주의 | 본문은 SSR이나 상세 페이지가 사이트맵에 없음 |
| AEO | 미흡 | FAQ 구조화 데이터 0건 |

상태는 `양호 / 주의 / 미흡 / 확인 불가`로 적는다. 확인하지 못한 항목을 양호로 적지 않는다.
진단 후 우선순위를 제안하고 승인을 받아 진행한다.

## 산출물 템플릿

llms.txt, robots.txt의 AI 크롤러 블록, JSON-LD, 의도 랜딩 골격, 진단 리포트, 측정 로그는
[templates.md](references/templates.md)에 기본형이 있다. 채울 수 없는 칸은 지우거나
`미확인`으로 남기고 그럴듯한 값으로 메우지 않는다.

## Phase 1 — SEO 기반

[seo.md](references/seo.md)를 읽고 실행한다. 순서는 콘텐츠 SSR 노출 → 사이트맵 →
메타 → 구조화 데이터 → canonical과 응답 위생 → 성능 → 색인 가속이다. 콘텐츠가 크롤러에게
보이지 않으면 그 아래 작업은 전부 무의미하므로 순서를 바꾸지 않는다.

## Phase 2 — 질문 선정과 의도 랜딩

먼저 질문을 고르고, 그다음 페이지를 만든다. 순서를 바꾸면 이길 수 없는 질문에 페이지를 쌓는다.

1. 사람들이 실제로 치는 질문을 목록화한다. 검색 콘솔 검색어, 검색 결과의 연관 질문 블록,
   경쟁 페이지의 FAQ, 고객 문의가 출처다.
2. 질문마다 지금 누가 그 답 자리를 점유하고 있는지 관측한다.
   절차는 [citation-competition.md](references/citation-competition.md)에 있다.
3. 질문을 `대체 가능 / 차별화 가능 / 포기`로 판정한다. **포기도 결과다.** 아무도 인용되지
   않는 질문은 페이지를 만들어도 인용이 생기지 않으므로 우선순위에서 내린다.
4. 남은 질문에 질문 하나당 페이지 하나를 배정한다. 각 페이지는 URL과 h1이 질문을 반영하고,
   첫 문단이 직답이고, 그 아래에 근거 데이터가 온다.

판독은 인용 경쟁만 본다. 제품 비교, 가격 포지셔닝, 시장 규모 분석은 이 스킬 밖이다.

질문 목록을 지어내지 않는다. 검색 콘솔의 검색어 목록, 고객 문의, 사용자 인터뷰처럼
출처가 있는 질문에서 시작하고, 출처가 없으면 가설이라고 표시한다. 사용자가 질문 목록을
갖고 있지 않으면 [ontology-boost.md](references/ontology-boost.md)로 후보를 회수하되,
회수한 질문에도 근거를 붙여 관측된 질문과 구분한다.

## Phase 3 — AEO, GEO, LLMO

[aeo.md](references/aeo.md) → [geo.md](references/geo.md) → [llmo.md](references/llmo.md)
순서로 읽고 실행한다. 세 레인은 구조화 데이터와 인용 가능한 문단을 공유하므로 작업은
한 번만 하되 검증은 레인별로 각각 통과시킨다.

## Phase 4 — NEO

한국 시장 대상이면 [neo-naver.md](references/neo-naver.md)를 읽고 실행한다.
서치어드바이저 등록은 사용자 계정이 필요하므로 절차를 안내하고, 사이트맵 제출 형식과
모바일 최적화, AI 브리핑 인용 요건은 직접 구현한다.

## Phase 5 — 측정 루프

[measure.md](references/measure.md)를 읽고 기준선 기록, 재측정 일정, 지표 3종
(노출·클릭·인용) 추적을 세팅한다.

완료는 두 단계이고 이름이 다르다. 섞어 쓰면 이 스킬이 막으려는 바로 그 주장이 통과한다.

| 단계 | 조건 | 주장할 수 있는 것 |
| --- | --- | --- |
| 작업 완료 | 변경 + 크롤러 눈 검증 증빙 + 재측정 날짜 명시 | 무엇을 바꿨고 언제 잰다 |
| 측정 완료 | 재측정 결과를 기록하고 해석 | 효과가 있었다 / 없었다 |

**효과는 측정 완료 전까지 주장하지 않는다.** 작업 완료만으로 보고를 닫을 수는 있으나,
그때 보고에 적히는 것은 효과가 아니라 예약된 날짜다.

기준선과 재측정 일정은 **프로젝트에 파일로 남긴다.** 대화에만 적으면 다음 세션이 기준선을
처음부터 다시 찍는다. 형식은 [templates.md](references/templates.md)의 측정 로그와
인용 프로브 시트를 쓴다.

재측정 결과와 되돌리기 어려운 결정은 적재 후보로 제안할 수 있다. 제안만 하고,
적재 자체는 사용자 동의와 tenant 확인을 거쳐 `domain-ontology` 스킬이 수행한다.

## 보고 형식

작업 후 보고에는 항상 다음 네 가지를 넣는다.

1. 바꾼 것: 파일과 before/after
2. 크롤러 눈 검증 결과: 실행한 명령과 출력
3. 다음 측정 일정: 날짜와 볼 지표
4. 하지 않은 것과 이유: 거절한 요청, 계정이 필요해 넘긴 절차, 확인하지 못한 항목

효과를 예측 수치로 적지 않는다. "노출이 몇 배 오른다"는 재측정 결과가 나오기 전까지
쓰지 않는다.

## 이 스킬을 사용하지 않는 경우

- 광고 집행, SNS 운영, 인플루언서 섭외처럼 유료·채널 마케팅
- 문구와 어체만 다듬는 작업 (ux-writing 소관)
- 검색 알고리즘에 대한 일반 지식 질의응답
- 검색 가이드라인 위반 요청. 이 경우 스킬을 쓰지 않는 것이 아니라 요청을 거절한다

## 온톨로지 보강 (선택)

`~/.ontology/ontology.db`가 있으면 [ontology-boost.md](references/ontology-boost.md)를 연다.
질문 목록, 1차 소스 정의, 서비스명 표기, 과거 결정처럼 코드베이스에도 `curl` 응답에도
없는 입력을 메운다. 없으면 열지 않고 본문대로 진행한다.

**회수는 사이트의 현재 상태가 아니다.** 온톨로지에 무엇을 만들었다는 기록이 있어도
`curl`로 확인되기 전까지는 없는 것으로 판정한다. 진단 점수표의 근거 칸에는 관측 결과만 적는다.
