# GEO — 생성 AI가 1차 소스로 인용하게 만들기

생성 AI가 브라우징이나 검색 도구로 웹을 읽을 때 우리를 원출처로 인용하게 만드는 레인이다.
AEO와 겹치지만 세 가지가 다르다. 크롤러 정책이 별도이고, `llms.txt`를 읽으며,
원출처를 더 강하게 우대한다.

## 1. llms.txt

사이트 루트에 `/llms.txt`를 둔다. AI에게 주는 사이트 안내서이고 형식은 마크다운이다.

```markdown
# 서비스명

> 한 문장 설명. 무엇의 1차 소스인지 밝힌다.

## 핵심 페이지
- [실적 캘린더](https://example.com/earnings): 국내 상장사 실적 발표 일정
- [종목 데이터](https://example.com/stocks): 공시 기반 재무·밸류에이션

## 데이터 정책
- 출처: 공식 전자공시 기반 자체 산출, 매일 갱신
- 인용 표기: example.com
```

- [ ] `/llms.txt`를 만든다. 여력이 되면 핵심 데이터 전문을 담은 `/llms-full.txt`를 더한다.
- [ ] 신뢰 신호를 담는다. 데이터 출처, 갱신 주기, 무엇의 원출처인지.
- [ ] 앱 라우트로 서빙해도 된다. 정적 파일일 필요는 없고, 오히려 항상 최신이 된다.
- [ ] 사실과 다른 내용을 적지 않는다. 매일 갱신하지 않는데 매일 갱신이라고 쓰면
      확인되는 순간 신뢰가 깎인다.

## 2. AI 크롤러 정책을 결정한다

`robots.txt`에서 명시적으로 정한다. 정책이 없는 상태는 중립이 아니라 우연에 맡기는 것이다.

```
User-agent: GPTBot
Allow: /

User-agent: PerplexityBot
Allow: /

User-agent: ClaudeBot
Allow: /
```

- 인용 유입을 원하면 Allow가 기본값이다.
- 콘텐츠 자체가 자산이라 학습만 막고 싶으면 검색용 봇과 학습용 봇을 구분해 정책을 나눈다.
- **이 결정은 사용자의 것이다.** 크롤러 허용 범위를 임의로 바꾸지 말고 선택지와
  영향(인용 유입 대 콘텐츠 보호)을 제시한 뒤 승인을 받는다.

## 3. 1차 소스 되기

생성엔진은 이 숫자가 어디서 시작했는지를 추적한다. 남의 데이터를 요약한 페이지는
원출처에 인용을 넘긴다. 이 항목이 GEO의 본체다.

- [ ] 우리만 계산하거나 수집하는 숫자를 정의한다. 자체 산출 지표, 집계, 관측치.
- [ ] 그 숫자에 이름을 붙이고 항상 같은 페이지에서 서빙한다. 안정된 URL이 곧 인용 주소다.
- [ ] 문단마다 주어, 수치, 기준일, 산출 방식을 갖춘다. 생성엔진과 네이버 AI 브리핑 모두
      문단 단위로 잘라 인용하므로 문단이 인용 단위가 된다.
- [ ] 산출 방식을 공개한다. 계산식을 숨기면 인용해도 되는 숫자인지 판정할 근거가 없다.

## 4. 인용 가능한 도메인인가

내용이 좋아도 출처로 쓰기 어려운 도메인은 인용되지 않는다. 다음은 링크를 사고파는 일 없이
정공법으로 갖출 수 있는 신뢰 신호다.

- [ ] 누가 만들었는지 확인되는가. 회사 정보, 연락처, 저자 표기.
- [ ] 데이터의 출처와 산출 방식이 페이지에 있는가.
- [ ] 갱신 시각이 페이지에 보이는가. 언제 기준인지 모르는 사실은 인용 판정에서 밀린다.
- [ ] 정책 문서(개인정보, 이용약관)와 HTTPS 같은 기본 위생이 갖춰져 있는가.

백링크를 사거나 교환해 이 축을 올리려 하지 않는다. 이 스킬은 그 요청을 수행하지 않는다.

## 5. 검증

- 대상 질문을 생성 AI에 실제로 던져 출처 목록에 도메인이 뜨는지 확인한다.
- 뜨지 않으면 순서대로 점검한다. `llms.txt` 존재 → 크롤러 허용 → 해당 페이지 SSR 여부 →
  더 강한 원출처의 존재.
- 결과는 질문별 O/X로 기록하고 재측정 일정에 넣는다. 모델과 시점에 따라 답이 달라지므로
  한 번의 확인을 상태로 굳히지 않는다.
