# NEO — 네이버 검색과 AI 브리핑

한국 시장 대상 서비스면 검색 유입의 상당 부분이 네이버에서 온다(업종·타깃에 따라 갈리므로
실제 비중은 서치어드바이저와 검색 콘솔로 확인한다). 글로벌 SEO 가이드는 네이버를 다루지
않으므로 이 레인은 따로 실행한다. 목표는 두 개다.
네이버 검색 노출, 그리고 **AI 브리핑이 우리 페이지를 출처로 무는 것.**

## 1. 서치어드바이저

- [ ] 사이트 등록과 소유 확인. 사용자 계정이 필요하므로 대신 하지 않고 절차를 안내한다.
- [ ] 사이트맵 제출과 `robots.txt` 확인. 네이버 크롤러는 `Yeti`다.
- [ ] 웹마스터도구 지표를 주간 리듬으로 읽는다. 콘텐츠 노출과 클릭 추이, 검색어별 클릭,
      CTR, 순위. 어떤 질문이 유입을 만드는지가 여기서 보인다.
- [ ] 중요한 신규 페이지는 등록 직후 수동 수집 요청으로 가속한다.

## 2. 구조화 데이터 — 네이버 표는 구글 표와 다르다

네이버는 구조화 데이터 가이드를 타입별로 14개 문서로 운영하고, **필수 속성을 구글과 다르게
건다.** 한쪽 표로 양쪽을 맞출 수 없으므로 이 레인의 판정을 따로 받는다.

```bash
python3 scripts/crawl_audit.py https://example.com --engine naver
```

- [ ] 형식은 Microdata나 JSON-LD를 쓴다. 네이버는 둘을 나란히 권장한다(구글은 JSON-LD 권장).
- [ ] 타입이 네이버 지원 목록 안에 있는지 본다. 이동 경로, 주소, 소프트웨어, 평점, 리뷰,
      레시피, 음식점, 영화, TV 시리즈, 동영상, 채용, 캐러셀, 사용법, 사이트 연관채널이다.
      **FAQPage는 없다.** 반대로 사용법(HowTo)은 구글이 리치 결과를 내린 뒤에도 네이버는 쓴다.
- [ ] 필수 속성이 갈리는 자리를 확인한다.

| 타입 | 구글 필수 | 네이버 필수 |
| --- | --- | --- |
| BreadcrumbList의 ListItem | `name`, `position` | `name`만 (`position`은 필수아님) |
| SoftwareApplication | `name`, 가격, 평점 또는 리뷰 | `name`, `applicationCategory` |
| Article · Organization | 없음 (문서가 "필수 속성은 없습니다"로 명시) | 해당 가이드 없음 |

  양쪽을 다 만족시키려면 합집합을 넣는다. 한쪽만 맞춘 마크업은 다른 쪽에서 탈락한다.
  네이버 공식 예제의 `applicationCategory: "유틸리티"`는 구글 열거값에 없어 그대로 쓰면
  구글에서 걸린다.
- [ ] 채용(JobPosting)과 동영상(VideoObject)은 마크업만으로 성립하지 않는다. 네이버 제휴와
      수집요청 API 연동이 전제다. 계정과 제휴 절차는 안내하고 대신 하지 않는다.
- [ ] 검증은 네이버가 지정한 schema.org 검증기로 한다. 구글 리치 결과 테스트와 다른 도구다.

**정상 마크업이 노출을 보장하지 않는다.** 네이버 문서가 직접 그렇게 적는다 — "구조화된
데이터를 정상적으로 마크업했을 경우라도 검색결과에 반영된다고 보장하지 않습니다."
마크업은 자격 조건이지 노출 사유가 아니다. 작업 완료 보고에 노출을 예고하지 않는다.

## 3. 사이트 연관채널

네이버가 사이트와 SNS·네이버 서비스 채널을 하나로 묶어 인식하는 별도 규칙이다.
다른 타입과 달리 **위치 요건이 붙는다.**

- [ ] `Person` 또는 `Organization`에 `name`·`url`·`sameAs`를 **셋 다** 넣는다.
      하나라도 빠지면 인식되지 않는다.
- [ ] **루트 페이지에 선언한다.** 네이버 문서는 "사이트의 루트 페이지에 기입된 구조화
      데이터"만 분석 대상으로 적는다. 하위 페이지 선언은 이 용도로 세지 않는다.
- [ ] `sameAs`에 네이버가 인식하는 채널을 넣는다. 네이버 서비스는 네이버TV·블로그·
      스마트스토어·지식iN·치지직, 웹 채널은 당근·스레드·인스타그램·유튜브·카카오스토리·
      카카오톡 채널·티스토리·틱톡·페이스북·X다.

**LLMO의 `sameAs`와 목표 집합이 다르다.** [llmo.md](llmo.md) 1절은 위키·앱스토어·GitHub를
든다. 그중 네이버 인식 목록과 겹치는 것은 유튜브 정도다. 같은 배열 하나가 두 레인을
상대하므로 건수로 판정하지 말고 **어느 표면이 들어 있는지**로 본다. `crawl_audit.py`가
`네이버 연관채널`과 `LLMO 표면` 두 줄로 나눠 찍는다.

인식 채널은 문서가 이름만 적고 도메인을 적지 않는다. 스크립트의 도메인 대응표에는 추정이
섞여 있어 `CHECK`까지만 내고 `FAIL`로 쓰지 않는다.

## 4. AI 브리핑 인용 요건

네이버 AI 브리핑은 문단 단위로 출처 칩을 달아 인용한다. 아래는 **공식 문서로 확정된 요건이
아니라 관측에서 추린 가설**이다. 각 항목은 대상 키워드로 실제 인용 여부를 확인해 검증하고,
검증 전에는 처방이 아니라 시험 대상으로 다룬다.

- [ ] **구조화된 사실.** 항목과 값이 짝지어진 구성이 산문 덩어리보다 인용된다.
- [ ] **1차 소스 신호.** 공식 출처 기반임을 페이지가 밝히고 원문 링크를 함께 둔다.
- [ ] **신선도.** 사건 발생 후 빠르게 페이지가 서는 쪽이 인용을 가져간다.
      분 단위 파이프라인을 만들 수 있으면 만든다.
- [ ] **모바일 최적화.** 네이버는 모바일 우선이다. 모바일 첫 화면에 핵심이 보여야 한다.
- [ ] 검증은 대상 키워드를 모바일에서 실제로 검색해 출처 칩을 확인하고 기록한다.

## 5. 블로그와 자기 도메인의 투트랙

네이버는 자기 생태계 안의 콘텐츠를 우대하는데, 정확한 데이터는 우리 도메인에 있다.
어느 한쪽만 고르지 않고 역할을 나눈다.

- **블로그**는 네이버 생태계 안에서 신뢰와 체류를 쌓는다. 검색 상위와 스마트블록에
  잡히는 것은 블로그 글인 경우가 많다.
- **자기 도메인**은 사실의 원장이다. 2절의 가설대로라면 AI 브리핑이 무는 것도 구조화된
  데이터 페이지 쪽이지만, 그 역시 검증 대상이다.
- 블로그 글에서 데이터 페이지로 자연스럽게 연결하되 링크 도배는 하지 않는다.

## 6. 하지 않는 것

네이버는 조작 신호에 특히 민감하고, 걸리면 최대 유입 채널을 통째로 잃는다.
사용자가 요청해도 다음은 수행하지 않는다.

- 서로이웃과 댓글 품앗이 자동화. 스팸 필터의 대표 감지 대상이고 저품질 판정으로 이어진다.
- 같은 문구를 대량 반복하는 포스팅이나 댓글. 반복 자체가 스팸 신호다.
- 발행 후 잦은 수정과 삭제. 문서 신뢰 점수를 깎는다.

거절할 때는 이유와 함께 대신 할 수 있는 정공법을 제시한다. 예를 들어 품앗이 대신
검색어 목록에서 전용 랜딩이 없는 질문을 찾아 페이지를 만든다.

## 7. 측정

- 웹마스터도구의 노출과 클릭을 주 1회 스냅샷으로 남긴다. 공개 API가 없으므로
  수동 기록이나 자체 수집으로 처리하고, 어느 쪽인지 보고에 밝힌다.
- 주말 하락은 정상이다. 비즈니스나 금융처럼 평일성 주제는 주말에 노출이 꺼지고,
  그 패턴 자체가 실수요의 증거다. 주말 데이터를 이상치로 착각해 되돌리지 않는다.
