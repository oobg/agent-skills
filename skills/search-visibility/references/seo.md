# SEO — 크롤러가 읽을 수 있게 만들기

크롤러가 읽지 못하는 콘텐츠는 존재하지 않는 콘텐츠다. 이 레인의 목표는 하나다.
**자바스크립트 없이 받은 HTML에 본문, 메타, 구조화 데이터가 전부 있게 만든다.**

판정은 항상 `curl -sL <url>`로 받은 응답에서 한다. 브라우저 개발자 도구의 DOM은
자바스크립트 실행 후 결과이므로 근거가 되지 않는다.

## 1. 콘텐츠 노출

- [ ] 핵심 페이지가 비로그인으로 열리는가. 로그인 뒤의 콘텐츠는 색인되지 않는다.
      전부 열기 어려우면 첫 문단과 핵심 수치만 티저로 노출하고 나머지를 게이트한다.
- [ ] `curl`로 받은 HTML에 본문이 있는가. 없으면 SSR·SSG·프리렌더 도입이 1순위다.
      이 항목이 미흡이면 아래 작업의 효과를 측정할 수 없다.
- [ ] CSR 바일아웃을 점검한다. SSR 프레임워크에서도 특정 훅이나 API를 쓰면 페이지 전체가
      클라이언트 렌더로 떨어진다. 배포마다 대표 페이지를 `curl`로 다시 확인하고,
      본문 글자 수가 갑자기 줄면 사고로 취급한다.

```bash
curl -sL https://example.com/page | wc -c        # 응답 크기
curl -sL https://example.com/page | grep -o "<h1[^>]*>[^<]*" | head
```

## 2. 사이트맵

- [ ] `sitemap.xml`이 있고 `robots.txt`가 이를 참조한다.
- [ ] 목록 페이지만이 아니라 상세 페이지가 전부 들어 있다. 목록만 넣는 실수가 가장 흔하다.
- [ ] URL 5만 개 또는 50MB에 근접하면 미리 샤딩한다. 한도를 넘는 순간 파일 전체가
      조용히 무시되고, 무시됐다는 신호는 어디에도 뜨지 않는다.
- [ ] 새 콘텐츠 유형을 만들면 사이트맵에 넣는 것까지가 출시다. 빠뜨린 유형은 몇 달씩
      색인 밖에 머문다.
- [ ] `lastmod`가 실제 갱신 시각을 반영한다. 전체를 매일 현재 시각으로 갱신하면
      신호가 아니라 잡음이 된다.

## 3. 메타

- [ ] 제목 50~60자. 핵심 키워드를 앞에, 브랜드를 뒤에 둔다.
      브랜드 홈처럼 짧은 제목이 맞는 페이지도 있으므로 `crawl_audit.py`는 15자부터 통과시킨다.
      스크립트가 OK를 줘도 이 항목의 권장 범위는 50~60자다.
- [ ] 설명 150~160자. 클릭할 이유가 있는 문장으로 쓴다. 면책이나 경고 문구를 설명에
      넣으면 CTR만 떨어진다.
- [ ] 페이지마다 고유하다. 템플릿 하나를 수백 페이지에 돌려 쓰면 중복으로 판정된다.
- [ ] OG 이미지가 있다. 페이지 유형별 동적 생성이 이상적이지만, 최소한 유형별로 다르게 둔다.

## 4. 구조화 데이터 (JSON-LD)

- [ ] 페이지 유형에 맞는 스키마를 쓴다. Article, Product, BreadcrumbList, Organization이
      기본이다. FAQPage는 두 엔진 모두 리치 결과를 내렸으므로 기본에서 뺀다([aeo.md](aeo.md)).
- [ ] **필수 속성을 채운다.** 구글 문서의 표현은 "필수 속성이 누락된 항목은 리치 결과로
      표시되지 않습니다"다. 필수가 빠진 마크업과 없는 마크업은 결과가 같다.
- [ ] **엔진별로 따로 통과시킨다.** 구글과 네이버는 필수 속성표가 다르다. BreadcrumbList의
      ListItem은 구글이 `position`을 필수로, 네이버가 필수아님으로 둔다. 한쪽만 맞추면 다른
      쪽에서 탈락하므로 합집합을 넣는다. 네이버 표와 연관채널 규칙은
      [neo-naver.md](neo-naver.md) 2·3절에 있다.

```bash
python3 scripts/crawl_audit.py https://example.com                    # 두 엔진 모두
python3 scripts/crawl_audit.py https://example.com --engine google     # 한쪽만
```

- [ ] 가시 텍스트와 내용이 같다. 구글 문서의 표현은 "페이지 독자에게 표시되지 않는 콘텐츠를
      마크업하지 않습니다"이고, 위반은 **수동 조치 대상**이다. 걸리면 리치 결과 자격을 잃는다
      (순위 자체는 영향받지 않는다고 문서가 밝힌다).
- [ ] 실제 사용자가 남기지 않은 리뷰나 평점을 넣지 않는다. 이것도 수동 조치 대상이다.
- [ ] `@id` 규약을 지킨다. 같은 엔티티는 사이트 전체에서 같은 `@id`를 쓴다.
      페이지마다 Organization을 새로 선언하면 엔티티가 갈라진다.
      **이 항목만 근거 등급이 다르다.** 구글 문서는 한 페이지에 여러 항목을 개별로 둘 때
      `@id` 연결을 권장할 뿐 사이트 전역 규약을 정하지 않는다. 엔티티 통합 추론이지
      공식 요건이 아니므로, 지키되 공식 요건인 것처럼 보고하지 않는다.
- [ ] 배포 후 검증은 엔진마다 도구가 다르다. 구글은 배포 전 리치 결과 테스트, 배포 후
      리치 결과 상태 보고서(Search Console)를 본다. 네이버는 schema.org 검증기를 지정한다.
      셋 다 브라우저나 계정이 필요해 `crawl_audit.py`가 대신하지 않는다. 결과를 보고에 남긴다.

## 5. URL과 응답 위생

- [ ] canonical이 파라미터 변형과 중복 경로를 하나의 정본으로 모은다.
- [ ] 다국어면 hreflang을 상호 참조한다. 한쪽만 걸면 무효다.
- [ ] **스니펫이 막혀 있지 않다.** `nosnippet`이나 `max-snippet:0`이 걸리면 색인이 되어
      있어도 AI 개요·AI 모드에 나올 수 없다. 구글 문서는 AI 기능의 자격을 "색인이 생성되어
      있고 검색 기술 요구사항을 충족하여 **스니펫과 함께** 검색에 표시될 수 있어야 한다"로
      적는다. `data-nosnippet`은 그 구간만 빠지므로 의도한 것인지 확인한다.
      지시어는 `robots`와 `googlebot` 두 메타 이름으로 갈려 들어오므로 둘 다 본다.
- [ ] 없는 페이지는 200이 아니라 404를 준다. soft 404는 색인 예산을 태운다.
- [ ] 404 베이크를 점검한다. ISR이나 CDN 캐시 계층에서 일시 장애로 생긴 404가 몇 시간씩
      구워질 수 있다. 데이터 조회 실패 시 404를 반환하지 말고 오류를 던져 재시도하게 한다.
      "없음"과 "못 가져옴"은 다른 상태다.
- [ ] 리다이렉트 체인이 1홉 이내다.

## 6. 성능과 자산

- [ ] 이미지가 WebP나 AVIF이고 width·height가 명시되어 있다.
- [ ] LCP 대상인 히어로 이미지와 폰트를 preload한다.
- [ ] 로고와 아이콘을 무손실 최적화한다. 수백 KB짜리 로고가 전 페이지에 실리는 낭비가 흔하다.

## 7. 색인 가속

- [ ] IndexNow로 신규·갱신 페이지를 발행 즉시 핑한다. Bing과 네이버 계열이 소비한다.
- [ ] Google은 IndexNow를 쓰지 않으므로 `lastmod` 정확성으로 대응한다.
- [ ] 대량 발행이면 핑을 발행 파이프라인에 넣는다. 손으로 하는 핑은 반드시 끊긴다.

## 검증

각 항목은 고쳤다가 아니라 관측했다로 닫는다. 보고에는 실행한 명령과 출력 요약을 넣는다.
확인하지 못한 항목은 `확인 불가`로 남기고 양호로 올리지 않는다.
