# 온톨로지 보강 (선택)

`~/.ontology/ontology.db`가 있을 때만 편다. **없으면 이 파일을 무시하고 본문대로
진행한다** — 커밋 메시지는 diff만으로 완결되어야 하고, 이 모듈은 거기에 표기 일관성과
`왜`의 근거를 보태는 보조 계층이다.

## 언제 여는가

| 국면 | 온톨로지가 메우는 것 |
| --- | --- |
| scope를 고를 때 | 이 저장소에서 실제로 쓰이는 표기 |
| 본문에 `왜`를 쓸 때 | 그 변경을 부른 결정과 근거 |
| 커밋이 되돌리기 어려운 결정을 담을 때 | 적재 후보로 제안할지 판단 |

메시지 형식·SemVer·언어 규칙은 온톨로지와 무관하다. 그 부분에는 열지 않는다.

## 1. scope 표기를 갈라놓지 않는다

**concept는 흔한 것일수록 같은 이름을 재사용한다. 표기가 갈리면 그게 곧 그래프 단절이다.**
같은 모듈이 커밋마다 `점주앱`·`owner-app`·`owner`로 갈리면 이력을 개념으로 되짚을 수 없다.

- scope 후보를 정한 뒤 `concepts`에서 같은 대상의 실제 표기를 확인한다.
- 표기가 있으면 그쪽에 맞춘다. 없으면 **새 표기를 만들지 않는다** — scope는 선택 사항이고,
  저장소에 안정된 모듈명이 없으면 만들지 않는다는 본문 규칙이 그대로 이긴다.
- 최근 커밋의 관례와 온톨로지 표기가 다르면 저장소 관례가 이긴다. 커밋 메시지의 독자는
  저장소이지 그래프가 아니다.

## 2. `왜`의 근거를 결정에서 가져온다

본문은 무엇을 반복하기보다 왜 바꿨는지 설명한다. 그 `왜`가 과거 결정에 있으면 회수해 쓴다.
되돌리기 어려운 결정의 근거를 남겨 두면 이후 탐색과 리뷰가 같은 제안을 반복하지 않는다.

- 회수한 결정은 본문 한두 줄로 요약한다. claim 원문을 그대로 붙이지 않는다.
- **실제 변경보다 회수한 결정을 우선하지 않는다.** diff가 결정과 다르면 diff가 사실이고,
  그 차이 자체가 보고할 내용이다.
- 이슈 번호가 있으면 `Refs`로 남긴다. 온톨로지 문서 제목을 꼬리말 토큰으로 만들지 않는다 —
  Conventional Commits 규격 밖이다.

## 3. 조치 사실을 남길지 제안한다 (역방향)

**발견만 적히고 조치가 안 적히면 그 결함은 그래프에서 영구히 미해결로 보인다.**
이 커밋이 온톨로지 claim에 적힌 결함을 실제로 고쳤다면, 조치 사실을 적재 후보로 제안한다.

- 제안만 한다. **적재는 사용자 동의와 문서별 tenant 확인이 있을 때만** 하고, 그 절차는
  `domain-ontology` 스킬 소관이다. 이 스킬은 온톨로지에 쓰지 않는다.
- 커밋 실행 권한과 적재 권한은 별개다. 커밋 승인이 적재 승인을 뜻하지 않는다.

## 절차

1. **스코프를 먼저 고정한다.** 회사 저장소 → `company` + `shared` · 개인 →
   `personal` + `shared` · 스킬·도구·방법론 저장소 → `shared` · 원고 저장소 →
   `novel` + `shared`.
2. **`~/.ontology/docs/recall.md`를 읽고 그대로 따른다.** 단계별 SQL과 근거 표기 형식이
   거기 있다. 여기 복제하면 갈라진다. **`recall.md`가 없으면 SQL을 지어내지 말고 이 모듈을
   닫는다** — 온톨로지가 없는 것과 같이 취급하고 diff만으로 메시지를 만든다.
3. 회수 0건이면 조용히 본문 규칙으로 돌아간다. 커밋 메시지에 `KB에 없음`을 적지 않는다 —
   메시지는 변경 이력이지 회수 보고서가 아니다. 회수 결과를 사용자에게 보고할 때만 밝힌다.

## 회수 결과를 그대로 믿지 않는다

**회수는 무엇을 봐야 하는가를 알려주는 것이고, 지금 어떤 상태인가의 증거가 아니다.**
과거 결정이 지금 코드에 살아 있는지는 diff와 최근 커밋으로 확인한다. 확인하지 않은 결정을
본문에 `왜`로 적으면, 이미 뒤집힌 이유를 새 커밋이 다시 주장하게 된다.

## 바뀌지 않는 것

- **메시지 작성 요청만으로 `git commit`·`push`를 실행하지 않는다.** 온톨로지 회수는 읽기이고
  실행 권한을 넓히지 않는다.
- stage 범위 가드, 공유 워킹트리 확인, 커밋 후 `git show --stat --oneline HEAD` 검증은 그대로다.
- 스코프 밖 tenant의 문서·claim은 메시지에도 보고에도 넣지 않는다.
