# Domain Guide — 직군 · 경력단계 · ATS · 특수케이스

직군/경력단계 맞춤, ATS 최적화, 포트폴리오, 자기소개서 작업 시 참조한다.

---

## 직군별 경험 구조

직군에 따라 경험을 드러내는 방식이 달라진다.

| 직군 | 중심축 |
|------|--------|
| 엔지니어 | 구조 / 문제 해결 |
| 디자이너 | 맥락 / 의도 / 사용자 경험 |
| 운영 | 안정성 / 조율 / 프로세스 |
| 마케팅 | 메시지 / 반응 / 전환 흐름 |
| PM | 의사결정 / 우선순위 / 조율 |

정량 성과만 우선하지 않는다.

유효한 정성적 영향:
- 의사결정 기여 / 운영 안정화 / 커뮤니케이션 개선
- 고객 반응 변화 / 조직 효율 개선

---

## 경력 단계별 강조 기준

| 단계 | 강조 포인트 |
|------|------------|
| 신입 | 학습력, 프로젝트 완성도, 기본기 |
| 주니어 | 실무 적응력, 구현 범위, 협업 경험 |
| 미드레벨 | 독립 수행, 문제 해결, 운영 경험 |
| 시니어 | 설계 판단, 영향 범위, 의사결정 |
| 리더 | 조직 성과, 조율, 전략, 사람·프로세스 영향 |

커리어 전환자는 **전이 가능성**을 기존 직무 깊이보다 우선한다.

## ATS 최적화 원칙

ATS 최적화는 단순 키워드 삽입이 아니다.

고려 항목:
- 직무 타이틀 정렬
- 최근 경험 우선순위
- 기술 키워드 일치
- 산업 용어 정렬
- 섹션 구조
- 검색 가능성

충돌 시: **키워드 유지 + 사람 중심 읽기 흐름 우선**  
ATS 통과만을 위한 부자연스러운 키워드 나열은 제한한다.

| 관점 | 초점 |
|------|------|
| ATS | 키워드, 구조, 검색 가능성 |
| 리크루터 | 직무 적합성, 경력 흐름, 가독성 |
| 실무자 | 실제 수행 능력, 깊이, 문제 해결 |
| 임원 | 영향력, 사업 이해, 조직 적합성 |

## 인터뷰 유도력 원칙

리스크를 줄이되, 지원자의 강점과 차별성까지 제거하지 않는다.

**좋은 이력서**: "이 사람이 실제로 어떤 사람인지 더 듣고 싶다"는 생각으로 이어져야 한다.

차별화는 아래에서 찾는다:
- 반복적으로 나타나는 문제 해결 방식
- 남들과 다른 경력 전환/경험 조합
- 특정 산업/도메인 이해
- 강점이 드러난 프로젝트 패턴
- 협업 또는 의사결정 방식

---

## 레이아웃 원칙

- 장식보다 가독성 우선
- 그래픽 요소, 아이콘, 과도한 컬러 제한
- ATS 제출용은 단순한 텍스트 구조 우선

---

## 포트폴리오 작업 시

중심 구성 요소:
- 프로젝트 맥락
- 본인 역할
- 문제 해결 과정
- 결과물 링크
- 이미지/데모/코드 증거

이력서보다 더 중요한 것:
- 결과물보다 **문제 해결 과정**
- 의사결정 이유
- 시행착오
- 본인 기여 범위

---

## 자기소개서 작업 시

이력서보다 더 중요한 요소:
- 경험의 맥락
- 선택과 판단
- 지원 동기
- 조직 적합성
- 성장 서사

비중을 더 높이는 것:
- 동기 / 선택 이유 / 가치관 / 성장 흐름
