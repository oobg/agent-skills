# Quality Check — 우선순위 · 체크리스트 · 출력 규칙

최종 출력 전, 또는 전체 문서 수정 시 참조한다.

---

## 우선순위 규칙

충돌 시 아래 순서를 따른다:

1. **사실성**
2. **검증 가능성**
3. **역할 명확성**
4. **채용 적합성**
5. **가독성**
6. **자연스러움**
7. **표현 세련됨**

---

## 상황별 우선순위 조정

| 상황 | 우선 적용 |
|------|-----------|
| ATS 중심 요청 | ATS 정렬 > 자연스러움 |
| 헤드라인 작성 | 기억 가능성 > 완전성 |
| 경력 기술 | 사실성 > 표현 세련됨 |
| 리더급 | 영향력·의사결정 > 기술 상세 |
| 주니어 | 성장 가능성 > 성과 과시 |
| 커리어 전환 | 전이 가능성 > 기존 직무 깊이 |

---

## 최종 품질 체크리스트

출력 전 아래 항목을 확인한다:

- [ ] 사실을 추가하지 않았는가?
- [ ] 역할 강도를 과장하지 않았는가?
- [ ] 수치를 임의 생성하지 않았는가?
- [ ] 문장이 너무 추상적이지 않은가?
- [ ] 각 주장에 원문 또는 사용자 보충 근거가 있는가?
- [ ] 원문과 보충 정보의 모순을 숨기지 않았는가?
- [ ] 제출용 문안에서 미확정 주장을 제외하거나 보수적으로 낮췄는가?
- [ ] 채용담당자가 10초 안에 핵심을 파악할 수 있는가?
- [ ] 인터뷰에서 방어 가능한가?
- [ ] 사용자의 강점과 차별성이 남아 있는가?
- [ ] 지나치게 장황하지 않은가?
- [ ] 한 bullet이 너무 많은 메시지를 담고 있지 않은가?

---

## 공통 실행 규칙

- 필요한 정보만 최소 단위로 질문한다.
- 질문은 한 회차에 1~3개만 묶어서 한다.
- 답변 뒤에도 결과를 바꾸는 미확정 사실이 남으면 필요한 항목만 후속 질문한다. 같은
  질문을 반복하지 않고, 답을 얻을 수 없으면 확인된 정보로 보수적 초안을 작성한다.
- 이미 충분히 명확하다면 추가 질문보다 개선 작업을 우선한다.
- 사용자의 원래 톤과 경력 스타일을 유지한다.
- 사실보다 표현이 앞서지 않도록 한다.
- 사용자 경험을 지나치게 해체하지 않는다.
- 채용 시장의 실제 읽기 흐름을 고려한다.

---

## PREFERENCE RULES

- 사용자의 원래 문체를 유지한다.
- 과도하게 corporate한 말투를 피한다.
- 지원자의 인간적인 인상이 남도록 한다.
- 기술 나열보다 경험 흐름을 우선한다.
- 지나치게 AI처럼 완벽한 문장을 피한다.
