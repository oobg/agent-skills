# 온톨로지 보강 (선택)

이 모듈은 현재 이력서 대상자의 과거 경력 사실이나 이미 정한 표현을 회수할 필요가 있을
때만 연다. 순수한 문구 수정은 제공된 원문만으로 처리한다.

## 대상과 스코프

먼저 이력서 대상자가 사용자 본인과 같은 사람인지 확인한다. 제3자의 이력서를 다룬다면
사용자의 `personal` 경력을 섞지 않는다.

사용자 본인의 이력서는 기본적으로 `personal` + `shared`를 조회한다. 다른 tenant로 자동
확장하지 않는다. 더 넓은 조회가 필요하다고 판단되면 `domain-ontology` 스킬의 정본 절차에
맡긴다.

이 모듈의 좁은 사용 조건은 상위 `domain-ontology` 스킬 자체의 자동 조회 트리거를 제한하지
않는다.

## 회수 절차

1. `domain-ontology` 스킬에 조회를 위임하고 `~/.ontology/AGENTS.md`와
   `~/.ontology/docs/recall.md`의 정본 절차를 따른다. 이 파일에서 SQL이나 별도 조회 규약을
   만들지 않는다.
2. 회수한 경력, 성과, 직함, 기간, 표현 결정을 현재 원문 및 사용자 설명과 대조한다.
3. 과거 기록은 현재 사실의 증거로 자동 확정하지 않는다. 바뀌었을 가능성이 있거나 현재
   자료와 다르면 `[확인 필요]`로 두고 제출용 문안에서는 제외하거나 보수적으로 표현한다.
4. DB, 정본 문서 또는 `domain-ontology` 스킬에 접근할 수 없으면 SQL을 지어내지 않고
   제공된 자료만으로 계속하며, 온톨로지를 사용하지 못했다고 알린다. 정상 조회 결과가
   0건이면 사용 불가와 구분해 회수 결과가 없었다고 알린 뒤 제공된 자료로 계속한다.

온톨로지 회수는 입력 근거만 보강한다. 이 스킬의 작성 범위, 사실성 규칙, 판정 권한을
넓히지 않는다.

## 적재 경계

이 스킬은 온톨로지에 쓰지 않는다. 새 이력서나 보충 경력을 적재하려면 사용자의 별도
명시적 동의와 문서별 tenant 확인이 필요하며, 실제 적재는 `domain-ontology` 스킬의 절차를
따른다. 이력서 작성·수정 요청이나 온톨로지 조회 동의는 적재 동의로 간주하지 않는다.
