# 제작 워크플로우

현재 단계에 해당하는 절만 읽고 적용한다.

## 1. 조사와 대본

- 공식 자료와 신뢰할 수 있는 1차 자료에서 핵심 원리, 치수, 연도와 비교를 확인한다.
- 네 문장(핵심 질문, 메커니즘, 보이는 흐름, 차별점)을 먼저 제시한다.
- 제작용 대본에는 시간 구간과 시각 연출을, TTS용 텍스트에는 내레이션만 둔다.
- 매 문장은 원인·작용·결과 중 하나를 새로 전진시킨다.
- 대본까지만 요청받았으면 이미지 단계로 넘어가지 않는다.

승인본: `script/APPROVED_NARRATION_KR.md`

## 2. 장면표와 키프레임

실제 TTS 길이를 기준으로 4초 원본 클립을 배정한다. 새로운 물리 상태, 하중 경로,
시공 단계, 내부 단면, 매크로 메커니즘, 규모 비교 또는 강한 전환이 있을 때만 장면을
나눈다. 카메라 각도만 다른 중복 장면은 만들지 않는다.

각 행에 S ID, KF ID, 대본 구절, 장면 목적, CLEAN 내용, INFO 핵심, 예상 카메라
움직임을 기록한다. 55~70초는 16~22개, 90~110초는 26~36개가 출발점이지만 실제
물리 상태 수를 우선한다.

산출물: `manifests/IMAGE_SEQUENCE.md`

## 3. CLEAN 프롬프트

각 키프레임은 독립된 9:16 이미지다. 콜라주, 스토리보드, 콘택트 시트, 분할 화면으로
합치지 않는다. 포토리얼 시네마틱 3D 공학 다큐멘터리 스타일과 동일 대상의 형상,
시대, 재료, 색상, 환경 연속성을 유지한다. 전경·중경·배경의 깊이와 후속 5~15도
카메라 움직임 여유를 둔다.

CLEAN에는 글자, 숫자, 기호, 치수선, 화살표, 지시선, 공식, 차트, 지도, UI, HUD,
자막, 로고, 워터마크와 인포그래픽 발광을 넣지 않는다. 물리 현상 자체일 때만 공기,
물, 흙, 연기, 열과 먼지를 사실적으로 표현한다. 권장 해상도는 1080×1920 이상이다.

산출물: `prompts/CLEAN_KEYFRAME_PROMPTS.md`

## 4. CLEAN 검수

장면표와 실제 이미지를 비교해 수량, 화면비, 장면 내용, 형상 연속성, 대본 순서,
물리 상태, 카메라 깊이, CLEAN 상태, 중복과 누락을 확인한다. 문제가 없는 파일만 실제
내용에 맞춰 정렬 번호를 붙인다. 문제는 해당 ID와 재생성 이유만 보고한다.

## 5. INFO 2패스

INFO는 새 장면이 아니라 같은 CLEAN을 편집하는 두 번째 패스다. CLEAN의 카메라,
크롭, 렌즈, 형상, 부품, 인물, 물리 상태, 조명, 재료, 질감과 배경을 보존한다. 장면을
회전·이동·확대·축소·교체하지 않는다.

평면 HUD 대신 실제 3D 공간에 결합된 모델 렌더형 공학 그래픽을 쓴다. 지시선과
화살표는 구조와 현상에 고정하고 원근, 시차, 가림을 따른다. 장면당 작은 기술 라벨
1~3개와 중요한 수치 0~1개를 기본으로 한다. 특별한 결론 장면 외에는 거대한 타이틀과
문장형 헤드라인을 넣지 않는다.

후속 영상 조립을 위해 앵커, 선, 화살촉, 수치, 라벨, 이동 펄스를 분리한다. 권장 색상은
일반 흐름 청록, 압력·위험 주황~적색, 수분·냉각 흰색~옅은 청색, 핵심 수치 금색,
구조 지시선 청백색이며 프로젝트 전체에서 일관되게 쓴다.

산출물: `prompts/INFOGRAPHIC_KEYFRAME_PROMPTS.md`

## 6. INFO 검수

ID별 CLEAN–INFO를 1:1로 비교한다. 동일 구도 보존, 수치·단위, 지시선 종점,
힘·압력·유체 방향, 원근과 가림, 타이틀 크기, 한 장 한 개념, 누락·중복·ID를 확인한다.
문제가 있으면 ID와 수정할 요소만 제시한다.

## 7. CLEAN→INFO 4초 영상

CLEAN은 실제 시작 프레임이자 형상·카메라·조명·재료 원본이다. INFO는 마지막 문구,
수치, 색상, 위치와 구도의 목표 참조다. INFO를 첫 프레임이나 평면 이미지판으로 쓰지
않고 CLEAN 위에서 그래픽을 새로 조립해 마지막에 INFO 상태에 도달한다.

```text
0.0~0.4초  CLEAN과 실제 환경 움직임
0.4~0.9초  앵커점 점등
0.9~1.7초  지시선·파면·치수선·화살표 몸통 생성
1.7~2.6초  작은 라벨·수치, 마지막에 화살촉 생성
2.6~3.4초  하중·압력·유체·재료·공정 펄스 이동
3.4~4.0초  INFO 목표 구성에 수렴해 유지
```

각 결과는 독립된 4.0초 9:16 단일 숏이다. 카메라는 5~15도의 절제된 오비트,
돌리, 트래킹 중 하나만 사용한다. 카메라와 그래픽은 독립적으로 움직이고, 그래픽은
3D 공간에서 원근·시차·가림을 유지한다. 전체 동시 페이드인, 평면 HUD, 글자 떨림,
역방향 화살표, 과도한 네온, 판타지 에너지, 구조 모핑·복제, 360도 회전, 휩팬,
카메라 롤, 내레이션·음악·새 자막·로고·워터마크를 금지한다.

산출물: `prompts/VIDEO_GENERATION_PROMPTS.md`

## 8. MP4 검수와 정렬

대표 프레임과 INFO를 실제 화면으로 비교한다. 장면 대응, 대본 순서, 누락·중복,
길이·화면비, CLEAN 시작, 그래픽 순차 생성, 카메라·그래픽 독립 움직임, 형상 안정성,
힘과 흐름 방향, 마지막 INFO 가독성을 확인한다. 실제 내용에 맞춰 `01_`, `02_` 번호를
붙이되 설명형 파일명은 보존한다. 삭제는 승인 후에만 한다.

## 9. 편집과 게시

4초 원본 전체를 그대로 쓰지 않는다. 문제 제기와 전환은 보통 1.5~3초, 핵심
메커니즘과 보상은 3~4초를 사용하고 그래픽 완성 시점을 고려한다.

```text
TTS → 컷 길이 → 핵심 효과음 → 배경음악 → 최소 자막 → 음량·색상 → 최종 검수
```

게시 텍스트는 추천 제목 1개와 대체 제목 3개를 만든다. 설명은 공학적 미스터리,
핵심 메커니즘, 보이는 흐름이나 힘, 단순화 고지, 관련 한글·영문 해시태그 순서로 쓴다.
