# 프롬프트 템플릿

사용자에게 외부 생성 도구용 프롬프트나 새 Codex 세션용 지시를 제공할 때 필요한
템플릿만 골라 사용한다. 대괄호 항목은 프로젝트 값으로 바꾼다.

## 새 프로젝트 시작

```text
$engineering-shorts를 사용하세요.

주제: [제작할 주제]
목표 길이: [60초 / 100초]
작업 폴더: [주제별 전용 절대경로]
강조할 현상: [공기 / 물 / 흙 / 열 / 압력 / 하중 / 진동 / 에너지]
이미지·영상 생성 플랫폼: [플랫폼]
영상 생성 길이: 클립당 4초

현재는 새 프로젝트입니다. 먼저 주제를 공학적으로 심화하고 대본까지만 작성하세요.
내가 대본을 승인하기 전에는 이미지 단계로 넘어가지 마세요.

각 단계의 산출물은 작업 폴더에 MD 파일로 저장하고 대화에도 복사 가능한 코드 블록으로
제시하세요. 이미 완료된 단계가 있다면 다시 만들지 말고 현재 상태를 확인한 뒤 이어가세요.
```

진행 중이면 `현재 단계: [단계]`와 `기존 산출물을 먼저 확인하고 다음 필요한 단계만
수행하세요`를 사용한다.

## CLEAN 일괄 생성 요청의 핵심 문구

```text
각 이미지는 독립된 9:16 이미지입니다. 콜라주, 스토리보드, 콘택트 시트 또는 분할
화면으로 합치지 말고 지정된 전체 수량을 중간 확인 없이 생성하세요.

CLEAN에는 글자, 숫자, 기호, 치수선, 화살표, 지시선, 공식, 차트, 지도, UI, HUD,
자막, 로고, 워터마크와 인포그래픽 발광을 넣지 마세요.
```

각 장면에 ID, 정렬 가능한 출력명, 물리 상태, 시점, 렌즈감, 조명, 재료, 연속성,
장면별 오류와 금지 조건을 이어 붙인다.

## INFO 2패스 요청의 핵심 문구

```text
INFO는 같은 ID의 CLEAN을 편집하는 두 번째 패스입니다. CLEAN의 카메라, 크롭, 렌즈,
형상, 부품, 인물, 물리 상태, 조명, 재료, 질감과 배경을 보존하세요. 장면을 새로 그리거나
회전·이동·확대·축소·교체하지 마세요.

평면 HUD가 아니라 실제 3D 공간에 결합된 공학 그래픽을 사용하고, 지시선과 화살표가
원근·시차·가림을 따르게 하세요. 작은 기술 라벨 1~3개와 검증된 수치 0~1개만 기본으로
사용하세요.
```

같은 생성 대화에 CLEAN이 있으면 재업로드를 요구하지 말고 ID로 찾도록 지시한다.

## 4초 영상 요청의 핵심 문구

```text
같은 KF ID의 CLEAN은 실제 시작 이미지이고 INFO는 마지막 목표 상태 참고 이미지입니다.
INFO를 첫 프레임으로 사용하지 말고 CLEAN 장면 위에서 그래픽을 순차 재구성하세요.

0.0~0.4초 CLEAN과 환경 움직임 → 0.4~0.9초 앵커 → 0.9~1.7초 선과 화살표 몸통
→ 1.7~2.6초 라벨·수치와 마지막 화살촉 → 2.6~3.4초 이동 펄스 → 3.4~4.0초
INFO 목표 상태 유지.
```

각 클립에 CLEAN–INFO 쌍, 출력명, 카메라, 앵커, 생성 순서, 이동 펄스, 공간 가림과
물리 방향을 개별 지정한다. 새 대화라면 ID와 파일명을 보존한 CLEAN–INFO 쌍을 제공한다.
