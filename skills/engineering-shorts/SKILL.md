# Engineering Shorts

공학적 인과관계를 시각적으로 설명하는 세로형 쇼츠를 단계별 승인과 실제 자산 검수로
제작한다. 모델명보다 `대본 → CLEAN → INFO → 동영상`의 대응 관계를 우선한다.

## 시작할 때

1. 사용자가 지정한 프로젝트 폴더와 현재 단계를 확인한다.
2. 폴더 안의 대본, 장면표, CLEAN, INFO, MP4를 먼저 조사한다.
3. 기존에 승인되거나 완료된 산출물은 다시 만들지 않는다.
4. 다음 단계의 규칙이 필요할 때 [제작 워크플로우](references/workflow.md)를 읽는다.
5. 사용자 입력용 프롬프트를 만들 때는 [프롬프트 템플릿](references/prompt-templates.md)도 읽는다.

작업 폴더가 정해졌다면 그 안에서만 파일을 생성·수정한다. 다른 구조가 이미 있으면
무리하게 재배치하지 말고 기존 구조를 존중한다.

## 승인 게이트

다음 순서를 지키며 사용자가 승인하기 전에는 다음 게이트를 넘지 않는다.

1. 주제와 핵심 논지
2. 대본
3. 장면표와 키프레임 수
4. CLEAN 생성 프롬프트
5. CLEAN 결과 검수
6. INFO 2패스 프롬프트
7. INFO 결과 검수
8. 4초 동영상 생성 프롬프트
9. MP4 결과 검수와 파일명 정렬
10. 최종 편집 및 게시 텍스트

사용자가 특정 단계까지만 요청하면 그 단계에서 멈춘다. 테스트나 승인 게이트를
생략해 전체 생성을 명시한 경우에는 그 선택을 따른다.

## 공통 실행 계약

- 각 단계 산출물은 프로젝트 폴더의 MD 파일로 저장하고, 대화에도 복사 가능한 코드
  블록으로 제시한다.
- 장면 `S01A`, 키프레임 `KF-01A`, 영상 `CLIP01`처럼 일관된 ID를 사용하고 CLEAN,
  INFO, MP4를 1:1 대응시킨다.
- 파일명 앞에는 이름순 정렬용 0 채움 번호를 둔다.
- 원본 이미지와 영상을 덮어쓰지 않는다.
- 파일명이나 생성 시각만으로 장면을 판정하지 않고 실제 화면을 확인한다.
- 이미지를 볼 수 없으면 추측하지 말고 콘택트 시트나 대표 프레임을 요청한다.
- 중복 삭제는 근거를 먼저 보고하고 승인 없이 실행하지 않는다.
- 중요한 치수·연도·수치·비교는 공식 자료나 신뢰할 수 있는 1차 자료로 확인한다.
  확정 사실, 논쟁 중인 해석, 영상적 단순화를 구분하고 거짓 정밀도를 만들지 않는다.

## 이야기의 중심

대본 전에 다음 네 문장을 확정한다.

1. 시청자가 끝까지 알고 싶어 할 핵심 질문
2. 문제를 해결하는 구조·장치·물리 작용인 핵심 메커니즘
3. 화면에서 보이게 만들 공기·물·흙·열·압력·하중·진동·에너지의 흐름
4. 다른 구조물이나 기계와 구별되는 고유한 차별점

초반 약 3분의 1까지 제약과 실패 가능성을 키우고, 이후 설계 개입이 힘과 흐름을
어디로 바꿔 성능을 만드는지 해소한다. 인물사보다 `원인 → 작용 → 결과`를 전진시킨다.

## 기본 파일 구조

```text
[프로젝트]/
  script/APPROVED_NARRATION_KR.md
  clean/
  info/
  video/
  edit/
  manifests/IMAGE_SEQUENCE.md
  manifests/PROJECT_STATUS.md
  prompts/CLEAN_KEYFRAME_PROMPTS.md
  prompts/INFOGRAPHIC_KEYFRAME_PROMPTS.md
  prompts/VIDEO_GENERATION_PROMPTS.md
```

승인된 대본 뒤에는 추정 길이가 아니라 실제 TTS 길이를 기록한다.

## 종료 보고

현재 게이트에서 만든 파일, 검증 결과, 남은 문제와 다음 승인 항목만 간결하게 보고한다.
다음 게이트의 산출물을 미리 만들지 않는다.
