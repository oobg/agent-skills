# Question Design

질문을 더 선명하게 만들고, 중요한 산출물을 위험도에 맞게 검토하는 에이전트
스킬입니다. 좋은 표현을 만드는 데서 끝나지 않고 전제, 검증 기준, 리뷰 책임,
종료 조건까지 함께 다룹니다.

## 언제 사용하나요?

- 막연한 상황을 AI에게 물어볼 질문으로 바꾸고 싶을 때
- 기존 프롬프트의 전제와 사각지대를 점검할 때
- 기획안, 전략, 분석 문서를 적대적으로 검토할 때
- 사실 검증과 논리 검토의 순서를 분리해야 할 때
- 리뷰를 어디서 끝낼지 기준이 필요할 때

단순 사실 조회, 번역, 코드 디버깅, 확정된 계획의 실행에는 적용하지 않습니다.

## 두 가지 모드

### MODE A: 질문 설계

질문의 목적과 숨은 전제를 진단하고, 실행 가능한 프롬프트로 다듬습니다. 결과를
바꾸는 모호성만 확인하고, 낮은 위험의 세부사항은 가정을 표시한 뒤 진행합니다.

예시:

```text
이 시장 분석 질문의 전제와 사각지대를 찾아서 더 좋은 질문으로 바꿔줘.
```

### MODE B: 리뷰 사이클

산출물의 도메인 사실, 논리, 구조, 흐름을 순서대로 검토합니다. 일반 업무는 Lite로
시작하고, 법률·재무·외부 공개·비가역 결정처럼 위험이 큰 작업만 Full을 고려합니다.

같은 모델이 역할을 바꿔 검토한 결과는 구조화된 자체 점검이며 독립 검증은 아닙니다.
독립성이 필요하면 별도 세션, 다른 모델, 도메인 전문가를 추가합니다.

## 설계 원칙

- 사실과 도메인 기준을 창의성보다 먼저 확인합니다.
- 리뷰어는 문제를 진단하고 통합자는 최종본을 책임집니다.
- CLEAN은 결함이 하나도 없다는 뜻이 아니라 종료 조건을 통과했다는 뜻입니다.
- 구조적 난국이 없으면 `genius-thinker`를 호출하지 않습니다.
- 반복 검토보다 작은 실행과 빠른 학습이 더 저렴하면 실행으로 넘어갑니다.
