# Question Design 스킬

AI 시대, 기획(그리고 모든 지적 업무)의 핵심은 **무엇을 질문할 것인가**에 달려있다.

> **왜 질문인가 (해자 관점):** 실행이 커모디티화되는 시대엔 누구나 같은 AI로 그럴듯한 결과물을 뽑는다. 그래서 방어가능한 차별점(해자)은 도구가 아니라 **질문·프레이밍·판단력** — AI가 대신 해주지 않는 것들 — 으로 이동한다. 이 스킬이 다듬는 대상이 곧 그 해자다.

이 스킬은 두 가지 모드로 작동한다:

1. **MODE A. 질문 설계** — 질문/프롬프트를 진단하고 설계하거나 리라이팅 (입력 준비 도구). → 상세: `references/mode-a.md`
2. **MODE B. 리뷰 사이클** — 산출물을 다단계 에이전트 루프로 검증·강화 (출력 평가 도구). → 상세: `references/mode-b.md`

> **MODE A↔B 결합 순서**: 질문+산출물을 함께 받으면 **A를 완료한 뒤 B**로 진행한다
> (잘못된 질문 위의 산출물 검증은 기준이 흔들림). 사용자가 산출물에서 다음 질문을
> 도출해 달라고 명시한 경우만 **B → A**다. 어느 순서가 결과를 바꾸는 진짜 모호성이
> 있을 때만 확인하고, 단순히 둘 다 있다는 이유로 모드를 되묻지 않는다.

이 SKILL.md는 라우터다. 아래로 모드를 판단한 뒤, **해당 모드의 상세 파일을 읽고** 진행한다. 공통 규칙(핵심 원칙)은 여기 인라인으로 두어 어느 모드에서도 적용한다.

---

## 이 스킬을 사용하지 않는 경우 (역트리거)

키워드가 우연히 등장해도 다음 경우에는 호출하지 않는다.

- 단순 사실 조회·정의 질의
- 코드 디버깅·구현 요청
- **정리·요약 자체가 목적**인 회의록·세미나 노트 작업
- 번역·교정 등 기계적 변환
- 이미 합의된 의사결정의 단순 실행

적용 여부가 결과를 실질적으로 바꿀 때만 "질문 설계 스킬을 적용할까요?"를 한 줄로
확인한다. 단순히 더 정교해질 수 있다는 이유만으로 확인 절차를 추가하지 않는다.

## 핵심 원칙: 결과 경로를 바꾸는 모호성만 먼저 질문한다

**모든 모드, 모든 에이전트 단계에서 공통 적용.**

모호성이 **결론·성공 기준·검증 기준을 바꾸거나**, 잘못 진행했을 때 되돌리기
어렵고 비용이 큰 경우에만 사용자에게 먼저 확인한다. 각 질문에 선택지를 함께
제시한다.

질문이 필요한 상황: 성공 기준 자체가 갈림 / 외부 공개·법률·투자·비가역 결정 /
범위 차이가 결론을 뒤집음 / 리뷰 기준을 정할 핵심 독자·규제 환경이 불명.

질문하지 않아도 되는 상황: 요청이 명확하고 맥락 충분 / 앞선 대화에서 이미 답이
나옴 / 사소한 형식·문구 선택 / 가역적인 초안에서 안전한 기본값을 쓸 수 있음.
이때는 작업을 멈추지 말고 산출물 첫머리에 중요한 가정만 최대 3개까지 표시한다.

가정 형식: `가정: [내용] (근거: 대화/기본값, 위험: 낮음, 번복 시: [달라지는 범위])`

질문 형식:
```
진행 전 확인이 필요한 부분이 있습니다.

Q1. [애매한 부분]
   A) [선택지 1] — [한 줄 설명]
   B) [선택지 2] — [한 줄 설명]
   C) [선택지 3] — [필요 시]
```

**사용자 침묵 시 디폴트 (모든 confirm 지점 공통):**
- 가장 보수적인(범위가 좁고 가역적인) 선택지로 진행. (각 모드의 개별 디폴트는 이 원칙의 구체화다.)
- 채택한 가정을 산출물 첫 줄에 "가정: ~"으로 명시한다 (사후 번복 가능).
- "그대로 실행" 같은 확신 행동은 침묵이 아닌 **명시적 합의**에만 적용한다.

## 입력 유형별 모드 자동 판단

사용자 입력이 들어오면 아래 기준으로 모드를 먼저 판단하고, 해당 상세 파일을 읽는다:

| 입력 유형 | 자동 판단 | 읽을 파일 |
|----------|----------|----------|
| 질문·프롬프트·상황 설명만 있음 | MODE A로 진행 | `references/mode-a.md` |
| 문서·기획안·분석 결과물이 포함됨 | MODE B 제안 | `references/mode-b.md` |
| 짧은 메모 (200자 미만 단편) | MODE A 질문 코칭 권장, 리뷰 사이클 생략 | `references/mode-a.md` |
| 질문과 산출물이 모두 포함됨 | MODE A 완료 후 MODE B | `references/mode-a.md`, 그다음 `references/mode-b.md` |
| 유형이 불분명함 | 결과 경로를 바꾸는 모호성일 때만 확인, 아니면 A → B | 필요한 파일을 순서대로 |

## 구성 파일

- `references/mode-a.md` — MODE A 상세 (STEP 0 진단 → STEP 1 스코프 분해·상황 파악 → STEP 2A 리라이팅 / 2B 코칭(온톨로지 우선 질문), 진행 중 질문 준비도 게이트(모호성 체크) 통과 → 병렬 AI 보조)
- `references/mode-b.md` — MODE B 상세 (접수 게이트, Lite/Full 선택, PII 가드레일, 5단계 오케스트레이션, 호출 규칙, 수렴·폴백)
- `agents/domain-knowledge-reviewer.md` — AGENT 0 (도메인 지식 리뷰 / 필요시 리서치 + 뇌과학·심리학 렌즈)
- `agents/adversarial-reviewer.md` — AGENT 1·3 공용 (적대적 리뷰)
- `agents/genius-thinker.md` — AGENT 2 (구조적 난국 재프레이밍, 명시적 선택 또는 조건 충족 시만)
- `agents/flow-synthesizer.md` — AGENT 4 (전체 흐름 정리 + 최종 통합 + 모호어 스캔)
- `references/ontology-boost.md` — 선택 모듈. `~/.ontology/ontology.db`가 있을 때
  MODE A 상황 파악 전이나 MODE B 도메인·적대적 리뷰 착수 전에 편다. 온톨로지가 없어도
  두 모드는 그대로 동작하며, 이 모듈은 리뷰의 입력만 바꾸고 확인 정책과 판정 책임 분리는
  그대로 둔다.
