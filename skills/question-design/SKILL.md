# Question Design 스킬

AI 시대, 기획(그리고 모든 지적 업무)의 핵심은 **무엇을 질문할 것인가**에 달려있다.

> **왜 질문인가 (해자 관점):** 실행이 커모디티화되는 시대엔 누구나 같은 AI로 그럴듯한 결과물을 뽑는다. 그래서 방어가능한 차별점(해자)은 도구가 아니라 **질문·프레이밍·판단력** — AI가 대신 해주지 않는 것들 — 으로 이동한다. 이 스킬이 다듬는 대상이 곧 그 해자다.

이 스킬은 두 가지 모드로 작동한다:

1. **MODE A. 질문 설계** — 질문/프롬프트를 진단하고 설계하거나 리라이팅 (입력 준비 도구). → 상세: `references/mode-a.md`
2. **MODE B. 리뷰 사이클** — 산출물을 다단계 에이전트 루프로 검증·강화 (출력 평가 도구). → 상세: `references/mode-b.md`

> **MODE A↔B 결합 순서**: 질문+산출물을 함께 받으면 **A 먼저** (잘못된 질문 위의 산출물 검증은 기준이 흔들림). 산출물에서 다음 질문을 도출하고 싶다면 **B → A**.

이 SKILL.md는 라우터다. 아래로 모드를 판단한 뒤, **해당 모드의 상세 파일을 읽고** 진행한다. 공통 규칙(핵심 원칙)은 여기 인라인으로 두어 어느 모드에서도 적용한다.

---

## 이 스킬을 사용하지 않는 경우 (역트리거)

키워드가 우연히 등장해도 다음 경우에는 호출하지 않는다.

- 단순 사실 조회·정의 질의
- 코드 디버깅·구현 요청
- **정리·요약 자체가 목적**인 회의록·세미나 노트 작업
- 번역·교정 등 기계적 변환
- 이미 합의된 의사결정의 단순 실행

판단이 애매하면 "질문 설계 스킬을 적용할까요?"를 한 줄로 먼저 확인한다.

---

## 핵심 원칙: 애매하면 반드시 먼저 질문한다

**모든 모드, 모든 에이전트 단계에서 공통 적용.**

결과물의 방향이 2가지 이상으로 분기될 수 있을 때는 추측하거나 가정하지 말고,
작업 전에 사용자에게 먼저 확인한다. 각 질문에 선택지를 함께 제시한다.

질문이 필요한 상황: 결과물 방향이 2가지 이상으로 분기 / 대상 범위 불분명 / 목적이 여러 갈래(개선인지 신규 설계인지) / 산출물 형식 미지정 / 리뷰 대상의 독자·맥락 불명.

질문하지 않아도 되는 상황: 요청이 명확하고 맥락 충분 / 앞선 대화에서 이미 답이 나옴 / 사소한 문구 선택 수준.

질문 형식:
```
진행 전 확인이 필요한 부분이 있습니다.

Q1. [애매한 부분]
   A) [선택지 1] — [한 줄 설명]
   B) [선택지 2] — [한 줄 설명]
   C) [선택지 3] — [필요 시]
```

**사용자 침묵 시 디폴트 (모든 confirm 지점 공통):**
- 가장 보수적인(범위가 좁고 가역적인) 선택지로 진행. (각 모드의 개별 디폴트는 이 원칙의 구체화다.)
- 채택한 가정을 산출물 첫 줄에 "가정: ~"으로 명시한다 (사후 번복 가능).
- "그대로 실행" 같은 확신 행동은 침묵이 아닌 **명시적 합의**에만 적용한다.

## 입력 유형별 모드 자동 판단

사용자 입력이 들어오면 아래 기준으로 모드를 먼저 판단하고, 해당 상세 파일을 읽는다:

| 입력 유형 | 자동 판단 | 읽을 파일 |
|----------|----------|----------|
| 질문·프롬프트·상황 설명만 있음 | MODE A로 진행 | `references/mode-a.md` |
| 문서·기획안·분석 결과물이 포함됨 | MODE B 제안 | `references/mode-b.md` |
| 짧은 메모 (200자 미만 단편) | MODE A 질문 코칭 권장, 리뷰 사이클 생략 | `references/mode-a.md` |
| 둘 다 포함되거나 불분명 | 사용자에게 모드 확인 후 진행 | 확인된 모드의 파일 |
