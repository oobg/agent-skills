# MODE A. 질문 설계 (상세)

> question-design 스킬의 MODE A 상세 절차. SKILL.md에서 MODE A로 판단되면 이 파일을 읽고 진행한다.
> 공통 규칙(결과 경로를 바꾸는 모호성만 질문, 나머지는 가정 후 진행)은 SKILL.md
> "핵심 원칙"을 따른다.

## STEP 0. 질문 유형 진단 (선택적 선행 단계)

기존 질문/프롬프트가 있을 때, 리라이팅 전에 먼저 질문 유형과 목적 적합성을 분류한다.

| 진단 유형 | 증상 | 부적절한 조건 | 처방 방향 |
|----------|------|--------------|----------|
| 정리형 | "비교해줘", "정리해줘"로 시작 | 의사결정·전략이 목적인데 정리만 요청 | 변화 감지형 또는 전제 점검형으로 전환 |
| 닫힌 전제형 | 결론이 이미 정해진 듯한 질문 | 탐색이 필요한 국면에서 결론을 가정 | 전제 점검형으로 전환 |
| 범위 초과형 | 너무 넓어 AI가 방향을 못 잡는 질문 | 제약·맥락 누락 | 제약 부여형으로 좁히기 |
| 검증 불가형 | 출처나 기준 없이 판단을 요구 | 사실·수치 판단이 핵심인데 근거 미지정 | 역할 지정 + 출처 요청 추가 |

> **정리형이 정당한 경우**: 회의록 요약·세미나 노트 정리처럼 "정리 자체가 산출물"이면 리라이팅하지 않고 그대로 둔다. 이 경우 본 스킬을 굳이 적용할 필요도 없다(역트리거 섹션 참조).

→ 진단 결과를 사용자에게 한 줄로 먼저 보여준 후 STEP 1로 진행한다.

## STEP 1. 상황 파악

**① 스코프 분해 점검 (선행 — 다듬기 전에 먼저)**

입력이 사실 **여러 개의 독립 질문/목적이 묶인 덩어리**인지 먼저 확인한다.
묶인 질문 위에서는 좋은 질문 하나를 설계할 수 없다.

판별: 서로 독립적으로 답할 수 있는 목적이 2개 이상 섞여 있는가?
(예: "신규 시장 진입 전략 + 가격 정책 + 조직 개편을 어떻게 할까?" → 독립 3개)

- **묶여 있으면** → 다듬기를 멈추고 하위 질문으로 **분해를 먼저 제안**한다.
  각 하위 질문이 무엇이고 서로 어떤 관계인지, 어떤 순서로 다룰지 한 줄씩 정리 후,
  **첫 하위 질문부터 개별로** STEP 0 → STEP 1 ② 분기부터 재적용한다(하위 질문마다 유형이 다를 수 있으므로).
- **단일 질문이면** → 아래 분기로 바로 진행.

**② 분기**

- **기존 질문/프롬프트가 있는 경우** → STEP 0 진단 후 리라이팅 (STEP 2A)
- **막막한 상황만 설명한 경우** → 질문 설계 코칭 (STEP 2B)

## STEP 2A. 프롬프트 리라이팅

**① 전제 해부** — 기존 질문에 숨어있는 전제를 꺼낸다.
**② 사각지대 탐색** — 그 전제가 틀렸을 때 생기는 blind spot을 짚는다.
**③ 리라이팅** — 아래 4가지 유형 중 적용 조건에 맞는 방향으로 변환한다.

| 유형 | 적용 조건 | 변환 방향 |
|------|----------|----------|
| 역할 지정형 | 도메인 전문성이 필요한 분석·판단 요청 시 | "당신은 [도메인] 전문가입니다. 내 접근 방식의 맹점을 찾아주세요." |
| 전제 점검형 | 결론이 이미 정해진 것처럼 질문이 닫혀 있을 때 | "A라는 가정이 틀릴 수 있는 조건은 무엇인가?" |
| 변화 감지형 | 시장·경쟁·트렌드 관련 현황 파악 요청 시 | "최근 [기간] 동안 이 시장에서 달라진 것은 무엇인가?" |
| 제약 부여형 | 방향이 너무 열려 있어 AI가 범위를 못 잡을 때 | "[제약] 안에서 가능한 옵션 3가지를 제시해줘." |

**④ 검증 방법 제안** — AI 답변을 받은 후 전제·프레임을 먼저 분석할 것.
공식 블로그, IR 자료, 컨퍼런스 발표 등 1차 소스 권장.

**출력 정책 (점진적 출력 — 블록 폭주 방지):**
기본은 핵심 3블록(`[질문 진단]`, `[리라이팅]`, `[사용법]`)만 출력. `[전제 분석]`은 사용자가 "자세히" 또는 "전제 분석 보여줘"를 요청할 때만 확장.

기본 출력 형식:
```
[질문 진단]
유형: (정리형 / 닫힌 전제형 / 범위 초과형 / 검증 불가형)
문제: ~

[리라이팅]
적용 유형: (역할 지정형 / 전제 점검형 / 변화 감지형 / 제약 부여형)
(변환된 프롬프트)

[사용법]
이 질문 후 AI 답변에서 [이런 것]을 확인하세요.
```

확장 출력 (요청 시):
```
[전제 분석]
숨겨진 전제: ~
사각지대: ~
```

**MODE A 종료 후 다음 행동 (3지선다):**
1. 그대로 실행 — 현 세션에서 리라이팅된 프롬프트 즉시 실행
2. 외부 도구로 이관 — 깨끗한 코드블록 1개로 정리해 출력
3. 결과 후 MODE B 예약 — 실행 결과 산출물에 자동으로 리뷰 사이클 적용

사용자가 명시 선택하지 않으면 침묵 디폴트(보수적 분기)를 따른다 — **즉시 실행하지 않고** 2번(텍스트 출력 — 추가 자동 작업을 걸지 않는 가장 가역적 선택)으로 마무리.

## STEP 2B. 질문 설계 코칭

**탐색 단계 (넓게)** — 가정을 흔드는 질문 3~5개 제안
- **(온톨로지 우선)** 이 개념/대상이 *정확히* 무엇인가? "어떻게 하지"보다 "이게 뭐지"를 먼저 묻는다 — 정의가 또렷해지면 재작업 한 종류가 통째로 사라진다. (예: "Task를 만들자" → "Task란 무엇인가? 삭제 가능한가? 혼자용인가 팀용인가?")
- 이 시장/문제의 구조를 내가 잘못 이해하고 있다면, 어떤 부분일까?
- 지금 당연하게 여기는 것 중 5년 뒤에는 달라져 있을 것은?
- 이 방향에 반대하는 사람의 가장 강력한 논거는?

**탐색 → 정리 전환 트리거**

다음 신호 중 2개 이상이 관찰되면 Claude가 먼저 제안한다:
- 새로운 가정이 더 이상 등장하지 않음 (답변이 반복됨)
- 사용자의 답이 "그건 이미 알고 있다" 류로 수렴
- 답변 간 충돌이 해소되어 일관된 방향이 잡힘

> "탐색이 충분한 것 같습니다. 정리 단계로 넘어갈까요?"

**정리 단계 (좁게)** — 형식 + 금지 조건을 동시에 건다

AI는 형식이 없으면 빈칸을 채우려 하고, 금지 조건이 없으면 익숙한 표현으로 빠져나간다.

```
[특정 결과물]을 작성해줘.
형식: [상황 → 동기 → 행동 → 결과] 순서 / 각 항목 3문장 이내
금지: 원론적 해결책 / 기술 난이도를 무시한 아이디어 / 추상적 표현
시작 문장: "어떤 사용자의, 어떤 상황에서, 왜 필요한가"로 시작
```

출력 형식:
```
[탐색용 질문 3-5개]
→ 각 질문의 의도를 한 줄로 설명

[정리용 질문 2-3개 (형식 + 금지 조건 포함)]
→ 어떤 산출물을 얻을 수 있는지 설명
```

## 질문 준비도 게이트 (모호성 체크 — 멈춤 기준)

질문을 얼마나 더 다듬을지는 감이 아니라 아래 축으로 판단한다. STEP 2A는 리라이팅을 확정하기 전, STEP 2B는 탐색 → 정리로 넘어가기 전에 이 게이트를 통과해야 한다.

- **목표 명확도** — 무엇을 얻으려는지 한 문장으로 구체적인가? (모호: "개선하고 싶다")
- **제약 명확도** — 예산·기간·범위·금지 조건이 정의됐는가?
- **성공 기준** — 결과가 측정 가능한가? (무엇을 보면 "됐다"고 하나)
- (기존 개선 맥락일 때 +) **맥락 명확도** — 기존 상태·이력을 이해했는가?

판정:
- 모호한 축이 결론·성공 판정·고비용 실행을 바꾸면 → 그 축을 겨냥해 먼저 질문한다.
- 가역적인 초안이나 낮은 위험의 형식 선택이면 → 중요한 가정을 표시하고 진행한다.
- 질문 준비도는 완벽한 입력을 만드는 시험이 아니라 **지금 실행해 학습해도 안전한지**
  판단하는 게이트다.

> STEP 2B의 "탐색 → 정리 전환 트리거"와 충돌하면 위험도를 먼저 본다. 핵심
> 성공 기준이 모호하면 질문하고, 나머지는 가정을 표시한 뒤 정리 단계로 넘어간다.

> **멈춤 기준**: 추가 질문의 답이 산출물 경로를 바꾸지 않거나, 작은 초안·실험으로
> 더 싸게 확인할 수 있으면 탐색을 끝내고 실행한다.

## 보조 행동: 병렬 AI 활용

외부 provider LLM을 호출할 수 있는 스킬이 현재 환경에 있으면
`cross-model-review.md`의 동의 게이트를 거쳐 직접 교차검토할 수 있다. 없거나 사용자가
실행에 동의하지 않으면 아래 프롬프트를 복사용으로만 제공한다. 산출물에 PII·기밀이
포함되면 직접 호출은 자동 보류한다.

→ 상세: `references/cross-model-review.md`

**탐색 단계 — 같은 질문을 여러 모델에 동시에 던진다**
- 모델마다 다른 답변이 나오는 지점 = 불확실한 영역 or 중요한 관점 차이
- 수렴하는 답변 = 공유된 프레임일 수 있음. 사실의 신뢰도 증거로 쓰지 않음

여러 provider에 직접 호출하려면 provider마다 별도 승인 manifest를 보여주고 동의를
받는다. 한 provider 승인을 팬아웃 승인으로 해석하지 않는다.

**심화 — 한 모델의 답변을 다른 모델로 해부한다**

팩트 체크가 아니라 **프레임 차이**를 보는 것이 목적이다.

```
"다음은 [다른 AI]가 정리한 분석이야.
이 분석의 전제 세 가지를 짚어줘.
그리고 그 전제들이 지금 시점에 흔들리고 있다면
결론이 어떻게 달라지는지 반박해줘."
```

두 답을 나란히 놓으면 내가 어떤 질문 프레임 안에 갇혀 있었는지 드러난다.
