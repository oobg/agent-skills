# 온톨로지 보강 (선택)

`~/.ontology/ontology.db`가 있을 때만 편다. **없으면 이 파일을 무시하고 MODE A·B를
그대로 진행한다** — 이 모듈은 리뷰의 입력을 바꾸는 보조 계층이지 필수 경로가 아니다.

> **용어 주의.** `mode-a.md`의 "온톨로지 우선"은 *이게 정확히 무엇인가*를 먼저 묻는
> 존재론적 질문 순서를 말한다. 이 파일의 온톨로지는 축적된 지식베이스(`ontology.db`)다.
> 둘은 다른 것이고, 이 모듈은 후자만 다룬다.

## 언제 여는가

| 국면 | 여는 이유 |
| --- | --- |
| MODE A STEP 1 상황 파악 전 | 이미 답이 나온 것을 다시 묻지 않기 위해 |
| MODE B AGENT 0(도메인 지식 리뷰) 착수 전 | 웹 리서치보다 1차 출처와 사용자 직접 진술이 먼저다 |
| MODE B AGENT 1·3(적대적 리뷰) 패킷을 만들 때 | 이미 판정된 제안을 다시 올리지 않기 위해 |

일반 상식·정의 질의, 코드 디버깅, 정리 자체가 목적인 작업에는 열지 않는다.

## 이 모듈이 실제로 바꾸는 것

### 1. 이미 판정된 제안을 리뷰가 다시 올리지 않는다

KB에는 거부 결정을 그 이유와 함께 남긴 문서가 있고, 그렇게 남긴 목적이 문서 안에 적혀 있다 —
같은 제안이 다시 올라올 때 실측 근거로 되짚기 위해서다. 그 목적을 리뷰 국면에서 쓰는 것이
이 항목이다. 리뷰 패킷을 만들기 전에 해당 주제의 `decision` claim을 회수해 **이미 판정됨**
목록을 만들고, 리뷰어에게 판정 근거가 아니라 판정 사실만 넘긴다.

이것은 KB에 그 주제의 거부·확정 결정이 실제로 적혀 있을 때만 작동한다. 회수가 0건이면 이
항목은 건너뛴다 — 과거 판정이 있었을 것이라고 가정하지 않는다.

되짚기는 막지 않는다. 다시 올리려면 **판정 당시와 달라진 근거**를 함께 대야 한다.

### 2. 도메인 검토가 KB부터 본다

AGENT 0은 외부 검색 전에 KB를 먼저 조회한다. 1차 출처와 사용자 직접 진술이 제3자 요약을
이기고, 독립 검증되지 않은 회상은 `reported fact`로 취급한다. 이 순서를 지키면 검색이
KB를 반복 재발견하는 비용이 사라진다.

### 3. 리뷰어 렌즈를 실제로 가른다

**같은 질문을 세 번 하면 네 배 비싼 한 표가 된다.** 렌즈를 갈라야 값이 나온다 —
산술 검산·도메인 현실성·스펙 대조로 나눈 실측에서 세 채점자의 발견은 거의 겹치지 않았고,
겹친 항목은 서로 다른 렌즈가 독립적으로 짚었다는 점에서 오히려 강한 신호였다.

- 판정이 엇갈리면 **근거의 종류**를 본다. 도메인 사실이 스펙 대조를 이긴다 — 채점표에
  없는 것은 채점표의 한계이지 산출물의 정당성이 아니다.
- 채점자에게 **구현 의도를 넘기지 않는다.** "이건 일부러 이렇게 했다"를 주면 그걸 채점
  기준으로 삼는다.
- 한 리뷰어의 1차 보고를 최종으로 취급하지 않는다. 리뷰어는 2차에서 스스로 뒤집을 수 있다.

## 절차

1. **스코프를 먼저 고정한다.** 회사 제품·전략·경쟁 → `company` + `shared` · 개인 →
   `personal` + `shared` · 방법론·도구론 → `shared` · 작품 세계·플롯 → `novel` + `shared`.
2. **`~/.ontology/docs/recall.md`를 읽고 그대로 따른다.** 단계별 SQL, 스코프 누수 금지,
   근거 표기 형식이 거기 있다. 여기 복제하면 갈라진다. **`recall.md`가 없으면 SQL을
   지어내지 말고 이 모듈을 닫는다** — 온톨로지가 없는 것과 같이 취급하고 두 모드를
   기본값으로 진행한다.
3. 회수 0건이면 `KB에 없음`이라고 쓰고 일반론임을 밝힌 뒤 진행한다.

## 회수 결과를 그대로 믿지 않는다

**회수는 무엇을 봐야 하는가를 알려주는 것이고, 지금 어떤 상태인가의 증거가 아니다.**
claim의 kind는 claim의 성격이지 현재 유효성이 아니다. 가변 산출물(코드·화면·스키마·설정)의
결함을 지목하는 claim을 리뷰 근거로 올리기 전에, 그 결함이 지금도 살아 있는지 확인한다.
확인 비용은 대개 조회 한 번이고 틀린 지적의 비용보다 훨씬 낮다.

## 바뀌지 않는 것

- **결과 경로를 바꾸는 모호성만 먼저 질문한다.** KB에 답이 있다고 질문을 늘리지 않는다.
  모든 모호성에 질문을 요구하면 사소한 확인이 늘어 실행과 학습 속도가 떨어진다.
- 회수 결과는 리뷰의 **입력**이지 판정이 아니다. 통합자 책임과 리뷰어 진단은 그대로 분리한다.
- PII·기밀 가드레일, Lite/Full 선택, 수렴·폴백 규칙은 그대로다.
- 스코프 밖 tenant의 문서·claim·건수는 리뷰 패킷에도 답에도 넣지 않는다.
