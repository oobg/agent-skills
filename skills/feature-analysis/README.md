# Feature Analysis

HTML/CSS/JS 프로토타입이나 프론트엔드 프로젝트에서 제품의 기능 구조를 역으로
복원합니다. 화면, 사용자 액션, 상태 전이, 업무 규칙, 워크플로우를 코드 증거와
함께 되살리고, 구현된 것과 의도만 있는 것과 운영 전환에 필요한 것을 구분합니다.

## 사용 시점

- 프로토타입이나 데모가 실제로 무엇을 하는지 기능 단위로 정리할 때
- 데모와 실제 코드의 격차를 개발 범위로 바꿀 때
- 기존 구현물에서 기능 명세나 화면 설계 문서를 뽑아 개발이나 외주에 넘길 때
- 화면은 있는데 어디까지 동작하는지 확인하고 싶을 때

버그와 코드 품질은 code-review, 시각적 완성도와 AI 슬롭은 design-slop-audit,
요구사항을 새로 정의하는 docx PRD는 prd-generator가 담당합니다. 이 스킬은
구현물에 있는 것을 읽고, 코드를 고치거나 없는 스키마를 만들지 않습니다.

## 핵심 원칙

- 제품 의미를 코드 구조보다 우선합니다. 상위 의미가 설명되면 하위 구현을 나열하지 않습니다.
- 화면에 있다고 기능으로 확정하지 않습니다. UI에서 handler, mutation, feedback까지 체인을 추적하고 끊긴 지점을 적습니다.
- 파일과 위치를 짚지 못한 판정은 사실로 세지 않습니다. 코드와 주석이 어긋나면 코드를 따릅니다.
- 상태는 업무 상태, UI 상태, 파생 상태 세 축으로 나눕니다.
- Priority, Level, Confidence, 누락 등급을 따로 매기고 축 사이 연결 규칙으로 견제합니다.
- 정적 증거와 런타임 증거를 구분하고, 실행해야 확인되는 동작은 코드만으로 확정하지 않습니다.
- 읽은 범위와 읽지 않은 범위, 실행하지 않은 것, 도구 실패를 결과에 함께 씁니다. 도구 실패는 제품 결함으로 적지 않습니다.
- 프로토타입이면 데이터 값, 스텁 정확도, 보안·성능·동시성, 선언되지 않은 뷰포트는 판정하지 않고, 체인 완결성과 상태·정의 일관성과 의도 대비 구현의 어긋남을 봅니다.

## 수집 스크립트

기계적으로 수집 가능한 항목은 `collect_inventory.py`로 모읍니다. 파일, 라우트 후보,
이벤트, 위임 속성, 상태 후보, API 호출, 부작용, 스텁 마커, destructive 함수, 상태
리터럴, CSS 토큰을 `파일:줄`과 함께 내고, 대상의 해시와 git 커밋과 생성 시각을
메타에 남깁니다. 원본은 읽기만 하고 산출물은 지정한 경로에만 씁니다. URL은 가져오지
않습니다.

```bash
python3 skills/feature-analysis/scripts/collect_inventory.py <대상> --json inventory.json --md inventory.md
```

결과는 Inventory이고 판정이 아닙니다. 항목을 기능으로 올리기 전에 원본 코드나 런타임과
대조하고, 어느 절의 0건도 부재의 증거로 쓰지 않습니다. 같은 입력과 같은 수집기 버전이면
결과가 같고, 실행 시각 같은 run metadata는 따로 두어 이전 분석과 비교할 때 제외합니다.

## 산출물

분석 리포트는 개요, 주요 기능, 구현 수준과 격차, 검증 결과, 종합 평가 다섯 절이
본문이고 상세 분석은 부록입니다. 핸드오프 문서는 요청할 때만 만들며, 본문에는
확인된 항목만 넣고 추론과 미확인은 오픈 이슈로 분리합니다. 확정되지 않은 값에는
(제안)을 붙입니다.

디자인 명세는 대상 디자인을 레퍼런스나 초안으로 쓰겠다는 요청이 있을 때만 만듭니다.
자사나 본인 산출물이면 토큰과 실측값을 그대로 남기고, 제3자 산출물이면 위계, 리듬,
상태 모델 같은 장르 문법만 남기고 색상 값, 서체, 로고, 카피는 뺍니다. 문서만으로
화면을 다시 그려 원본과 대조한 뒤에만 재현 가능이라고 씁니다.

리포트의 기능 평가는 P0과 P1 기능마다 장점, 단점, 변경 제안을 관찰된 사실 하나에
묶어 적습니다. 근거 유형은 체인 완결성, 규칙 일관성, 워크플로우 단축, 보호 장치,
누락 조건 다섯 가지로 제한합니다.

## 사용 예

```text
이 HTML 프로토타입이 어떤 기능을 지원하는지 기능 단위로 정리하고, 실제 동작하는 것과 UI만 있는 것을 구분해줘.
```

```text
데모 화면과 실제 프론트 코드를 대조해서 격차를 정리하고 개발 착수용 핸드오프 문서로 만들어줘.
```
