# 최초 설정 (온보딩)

이 스킬을 **처음 쓸 때** 어체와 도메인 단어를 한 번 물어서 정하는 절차다. 한 번
거치고 나면(설정했든 "그냥 기본으로"든) **다시 묻지 않는다.** 질문은
선택지(버튼)로 낸다.

**언제 도나:** 글쓰기나 윤문 작업을 시작하는데 셋이 모두 참일 때.

1. `register.md`의 어체가 (미지정)이고,
2. `glossary.md`의 표기도 비어 있고,
3. `register.md`의 **`온보딩 상태`가 `완료`가 아닐 때.**

3번이 핵심이다. 어체/글로서리가 비어 있어도 온보딩을 이미 한 번 거쳤으면(=상태가
`완료`) 다시 뜨지 않는다. 작업을 막지 않도록 한 번만 묻고, 답을 기록한 뒤 바로
본 작업으로 넘어간다. 사용자가 건너뛰면 기본값으로 진행한다. 단, 어체/단어를
묻기 전에 실행 기능이 있으면 **0단계(Python 3.8+ 확인)**를 먼저 한다. 셸이나
Python 실행 기능이 없으면 수동 점검 폴백으로 바로 선호 설정을 계속한다.

## -1단계 — 가능하면 파일 보기 전에 과거 대화부터 확인

`conversation_search` 기능이 제공되면 파일 세 조건(1·2·3)을 보기 전에
"ux-writing 어체", "선호 어투" 같은 키워드를 검색한다. 이전 대화에서 이미 정한
결과가 나오면 `register.md`에 그 값이 안 적혀 있어도 다시 묻지 않고 적용한다.
기능이 없거나 권한이 없으면 이 단계를 조용히 건너뛰고 파일 설정과 현재 대화의
사용자 선호를 사용한다. 검색 불가를 "선호 없음"으로 해석하거나 기존 선호를
초기화하지 않는다.

이렇게 하는 이유: `register.md` 파일 쓰기는 이 스킬 폴더 안에서만 유효하다.
다른 프로젝트, 다른 스킬 설치, 스킬 폴더가 읽기 전용인 환경에서는 파일에
남길 수 없다. 반면 과거 대화 검색은 폴더에 안 묶이고 그대로 따라온다.

- 검색 결과가 나오면: 그 값을 적용하고, **파일에 적는 건 선택이다**: 이후
  `ai_lint`/`register_check` 같은 **스크립트 게이트를 실제로 돌릴 상황**이면
  그때 `register.md`에 적어 스크립트가 읽게 하고, 순수 대화 안에서 글만
  다듬는 상황이면 파일을 안 건드리고 그냥 적용만 해도 된다.
- 검색이 비거나 애매하면: 아래 1·2·3 조건으로 넘어가 평소대로 온보딩한다.

**충돌 시 우선순위 — 대화 검색과 파일이 다른 값을 가리키면:** 더 최근
것이 이긴다. 대화 검색 결과에 날짜·순서가 있으면 그걸로 판단하고,
`register.md` 파일이 언제 마지막으로 갱신됐는지 알 길이 없으면(타임스탬프가
없어서) **대화 검색 쪽을 우선한다** — 사람이 최근에 직접 말한 것이 오래된
파일 값보다 신뢰도가 높다고 본다. 다만 확신이 안 서면(둘 다 오래돼 보이거나
상충이 애매하면) 추측하지 말고 "어체를 ~해요로 할지 합니다로 할지 확인
할게요"처럼 짧게 확인한다.

## 0단계 — 실행 기능이 있으면 Python 3.8+ 확인

출력 게이트 스크립트(`ai_lint`, `glossary_check`, `register_check`)는 **Python 3.8
이상**이 필요하다. 셸/명령 실행 기능이 제공될 때만 온보딩 맨 처음에 한 번
확인한다.

셸과 Python 실행이 가능하면 스크립트가 돌 환경에서 확인한다.

```
python3 -c "import sys; raise SystemExit(0 if sys.version_info >= (3,8) else 1)"
```

- 종료 코드 0 (3.8+ 있음) → 통과. 바로 1단계로 간다.
- 명령이 없거나(파이썬 미설치) 종료 코드 1 (3.8 미만) → 아래 선택지를 낸다.
- 셸 또는 명령 실행 기능 자체가 없음 → 설치 질문으로 작업을 막지 않는다.
  스크립트 검사는 생략하고 수동 점검 폴백을 적용한 채 1단계로 간다.

> 스크립트 게이트를 돌리려면 Python 3.8 이상이 필요해요. 지금 설치할까요?
> - 예, 설치할게요
> - 아니요, 수동으로 할게요

### "예" — 설치 플로우 → 이후 진행

1. OS를 확인해 맞는 방법을 고른다. 셸 실행이 가능한 환경이면 실행하고, 사용자
   본인 컴퓨터면 명령을 안내한다.
   - macOS: `brew install python@3.12` (Homebrew 없으면 python.org 설치 안내)
   - Debian/Ubuntu: `sudo apt-get update && sudo apt-get install -y python3`
   - Windows: `winget install Python.Python.3.12` (또는 python.org)
   - pyenv 사용 시: `pyenv install 3.12 && pyenv local 3.12`
2. `python3 --version`으로 3.8+를 다시 확인한다.
3. 확인되면 **1단계(어체)로 이어서 온보딩을 계속한다.**

### "아니요" — 수동 점검으로 계속

> Python 설치 전까지 스크립트 게이트 대신 HARD 항목을 눈으로 확인할게요.
> 어체와 도메인 단어 설정은 계속할 수 있어요.

1, 2단계로 이어간다. Python 부재나 셸 기능 부재는 사용자 선호 수집을 막지 않는다.
온보딩을 마치면 `온보딩 상태`와 선호는 평소대로 보존한다. 이후 스크립트를 실행할
수 있게 되면 그때 Python을 확인하되 온보딩 질문을 반복하지 않는다.

## 1단계 — 어체

> 기본적으로 `~해요`체를 써요. 문장 끝맺음을 바꿀까요?
> - 아니오, `~해요`로 (추천)
> - 예, 바꿀게요

"예"면 범위와 어체를 묻는다. 절차와 선택지는 `register.md`의 `어체 설정 대화`와
같다. 전역인지 이 프로젝트인지 고르고, 어체를 고른다. "내 어체를 분석해서 반영"도
여기서 된다. 결과는 register.md의 전역/프로젝트 표에 적는다.

## 2단계 — 도메인 단어

> 이 제품이나 도메인에서만 쓰는 고정 표기가 있나요? (예: "회원"을 "멤버"로)
> - 없음 / 나중에
> - 있음, 등록할게요

"있음"이면 전역인지 이 프로젝트인지 묻고, `일반 표현 → 이 표기`를 받아 `glossary.md`의
해당 표에 적는다. 프로젝트면 현재 작업 경로도 함께 적는다.

## 끝나면 — 기록한다 (파일 아니어도 됨)

어떤 답이 나왔든 그 결과를 남긴다. **꼭 `register.md` 파일일 필요는 없다** —
지금 대화 안에서 자연스럽게 언급된 것만으로도(예: "그럼 ~해요체로 할게요") 다음에
`conversation_search`로 찾아질 수 있다.

- **스크립트 게이트(`ai_lint`/`register_check`/`glossary_check`)를 이 작업에서
  실제로 돌린다면** — 게이트가 파일을 읽으므로 반드시 적는다.
  - 어체를 정했으면 register.md의 전역/프로젝트 표에,
  - 도메인 단어를 정했으면 glossary.md 표에,
  - **어느 쪽이든(건너뛰었어도) register.md `온보딩 상태`를 `완료`로.**
- **스크립트 게이트 없이 대화 안에서 글만 다듬는다면**: 파일에 안 적어도
  된다. 답을 대화 중에 자연스럽게 확인하는 문장으로 한 번 남기면(예: "네,
  ~해요체로 진행할게요") 그걸로 충분하다. 다음에 -1단계가 대화 검색으로
  찾아 쓴다.

파일에 적었다면, 그 뒤로는 출력 게이트(`ai_lint`, `glossary_check`,
`register_check`)가 그 설정을 자동으로 반영한다.

## 스킬 파일을 못 고치는 환경이면 (예: claude.ai)

스킬 폴더가 읽기 전용이면 `온보딩 상태`를 영구히 저장할 수 없다. 이땐 매번 물어
사용자를 괴롭히지 말고 이렇게 한다.

- **-1단계(대화 검색)가 제공되면 활용한다.** 파일에 못 적어도 과거 대화에서
  찾아지면 다시 안 묻는다. 검색 기능이 없으면 현재 대화에서 확인된 선호를 세션
  동안 유지한다.
- 검색도 비어 있으면 온보딩은 **한 세션에 최대 한 번**, 그것도 작업을 막지 않는
  가벼운 한 줄 제안으로만 낸다.
- 기록이 안 되면 **그냥 기본값**(`~해요`, 표기 강제 없음)으로 조용히 진행한다.
  표가 비었다는 이유로 매번 캐묻지 않는다.
- 사용자가 도메인 단어나 어체를 먼저 언급할 때만 설정을 다시 꺼낸다.

파일로 영구히, 확실하게 남기고 싶으면(특히 스크립트 게이트를 쓸 계획이면)
사용자가 스킬을 편집 가능한 곳(레포 안 스킬, Settings → Capabilities)에 두고
register.md / glossary.md를 직접 채우는 게 가장 확실하다.
