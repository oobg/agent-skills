# 딥모드 — 정서 보강 (더하기 축)

## 이건 뭐가 다른가

`ai-tells.md`, `translation-ese.md`는 전부 **빼기**다 — 티 나는 구절을 걷어
낸다. 딥모드는 반대다. **매끄럽고 문법도 맞는데 밋밋할 때**, 한국어 특유의
정서와 말맛을 일부러 더한다. 방향이 반대라 기본 흐름에 섞지 않고 여기 따로
둔다.

`/ux-writing:deep`은 앱에 등록된 슬래시 명령이 아니라 대화에 적는 모드 지정이다.
같은 메시지에 붙인 원문이나 사용자가 분명히 가리킨 현재 대상을 다듬는다. 대상이
없거나 여러 후보 중 무엇인지 알 수 없으면 원문을 요청한다.

## 언제 여나

**기본값은 항상 꺼져 있다.** 아래 중 하나에 해당할 때만 연다.

- `/ux-writing:deep` 텍스트 모드 지정: 가장 명확한 트리거다.
- 사용자가 자연어로 명시적 요청: "딥모드로", "정서까지 살려줘", "결까지
  다듬어줘", "더 깊게 봐줘" 등
- `ai-tells.md`의 글 전체 점검(리듬과 대칭)까지 다 했는데도 사용자가
  "그래도 뭔가 기계적이다"라고 재차 지적할 때

사용자가 그냥 "다듬어줘", "AI 티 빼줘"라고만 하면 **열지 않는다.** 기본
흐름(SKILL.md 표 → 필요시 ai-tells.md/translation-ese.md)으로 충분하다.

## 적용 순서와 가드

기본 모드로 명확성, 간결성, 번역투와 AI 문체를 먼저 고친다. 그 결과에 아래 패턴을
적용해 원문에 이미 있는 정서와 관점을 살린다.

1. **장르 가드** — 격식 보고서, 공문, 계약서, 공적 발표문에는 적용하지 않거나
   아주 약하게만. 칼럼, 에세이, 블로그, 후기, 브랜드 카피에 주로 쓴다.
2. **우선순위 가드** — `ai-tells.md`/`translation-ese.md`와 충돌하면 그쪽이
   이긴다. 정서를 살린다고 대명사를 다시 늘리거나 과장을 되살리지 않는다.
3. **의미 가드** — 원문의 사실, 주장, 수치, 확실성, 인과와 긍정과 부정을 그대로
   두고 말맛만 만진다. 사례, 장면, 감정은 원문에 있을 때만 쓴다.
4. **보이스 가드** — 프로젝트 glossary와 register가 딥모드보다 우선한다. 담백한
   브랜드를 감상적으로 바꾸거나 문서 장르를 에세이로 바꾸지 않는다.

딥모드는 정서 보강 모드이며 전면 재작성 허가를 뜻하지 않는다. 사용자가 전면
재작성을 함께 명시했다면 그 범위는 이미 승인된 것이므로 변경량만을 이유로 다시
묻지 않는다.

## 패턴

### K-1. 정서 온도 0 (추상과 일반론만 있음)

추상적 단언에 대응하는 구체적 장면이나 수치가 원문에 있으면 앞으로 가져온다.
정해진 비율은 두지 않는다. 실제 경험이 없으면 지어내지 말고 그대로 두거나
작성자에게 묻는다.

```
입력: 가입 경험을 개선해야 한다. 인터뷰 참가자 8명 중 3명이 가입 중 주소 입력에서 멈췄다.
❌ 가입 경험을 개선해야 한다.
✅ 가입 경험을 개선해야 한다. 인터뷰 참가자 8명 중 3명이 주소 입력에서 가입을 멈췄다.
```

### K-2. 과장

강조어를 원문이 뒷받침하는 사실로 바꾼다. 이중부정이나 완서법을 새로 넣어
확실성이나 평가 강도를 바꾸지 않는다.

```
입력 사실: 목표 1,000건, 실제 1,240건.
❌ 압도적인 성과를 거두었다.
✅ 목표 1,000건보다 240건 많은 1,240건을 기록했다.
```

### K-3. 빳빳한 완결형 (에세이, SNS, 후기)

후기나 에세이의 원문에 망설임이나 개인적 판단이 있으면 지나치게 공식적인
완결형으로 평탄화하지 않는다. 사람답게 보이려고 말끝을 임의로 흐리지 않으며,
격식 문서에는 적용하지 않는다.

```
입력: 써 보니 알림이 늦게 오는 점이 제일 걸리더라고요.
❌ 알림 지연이 문제입니다.
✅ 써 보니 알림이 늦게 오는 점이 제일 걸리더라고요.
```

### K-4. 공식적인 서두와 결말

"~에 대해 알아보겠습니다"로 열고 "~할 때입니다"로 닫는 정형화된 틀이
본문을 반복하면 덜어낸다. 원문에 있는 구체적 사실이나 결정으로 시작하고 끝낸다.
질문, 반전, 부정 대구를 장식으로 새로 만들지 않는다.

```
입력: 회의 뒤 결정 담당자가 기록되지 않아 같은 안건을 다음 주에 다시 논의했다.
다음 회의부터 결정 담당자를 회의록에 기록하기로 합의했다.
❌ 오늘은 효율적인 협업 문화에 대해 알아보겠습니다.
✅ 회의 뒤 담당자를 기록하지 않아 같은 안건을 다음 주에 다시 논의했다.

❌ 이제 소통 방식을 혁신할 때입니다.
✅ 다음 회의부터 결정 담당자를 회의록에 기록한다.
```

## 화계(말투 거리) 일관성

격식(합니다) / 정중(해요) / 친근(해체) 중 독자와 장르에 맞는 한 단계를
고르면, 글 전체에서 그 단계를 끝까지 유지한다. 정서는 문장 하나하나의
기교보다 이 거리를 얼마나 일관되게 지키느냐에서 더 크게 좌우된다.

# 참고표 — 영어 비즈니스 buzzword 번역

영어 원어를 그대로 음차해서 어색해지는 단어들. 이미 한국어로 옮겼는데 뜻이
어긋난 경우는 `translation-ese.md`의 `어휘 단위 직역`이 본다. 프로젝트 `glossary.md`에 이미
등록된 용어가 있으면 그쪽이 우선한다 — 이 표는 아직 온보딩 안 된 일반
buzzword에 대한 기본값이다.

| 영어 | 자연스러운 한국어 |
|---|---|
| leverage | 활용하다 / 기대다 / 끌어올리다 |
| seamless | 매끄러운 / 끊김 없는 |
| robust | 튼튼한 / 견고한 |
| scalable | 확장성 있는 |
| insight | 통찰 / 시사점 |
| impact | 영향 / 파장 |
| holistic | 전체적 / 총체적 |
| framework | 체계 / 틀 / 구조 |
| pipeline | 파이프라인(유지 가능) / 흐름 / 공정 |

일반 독자 대상 글이면 영어 원어는 처음 한 번만 괄호 병기하고 이후엔
한국어만 쓴다. 전문 독자 대상이면 영어를 유지해도 되지만, 매번 반복
병기하지는 않는다.
