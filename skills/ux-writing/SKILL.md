# UX 라이팅

사용자에게 보이는 모든 문장을 다듬는다. 코어밸류 5로 보이스를 잡고 프린시플
8로 행동으로 옮긴다.

원칙 자체는 상식(간결, 명확, 친근)이다. 이 스킬이 더하는 건 두 가지 — **이
프로젝트의 기본값**(`~해요`, 잡초 목록, 고유 표기)과 **멈춤 규칙**(언제 고치지
말고 물어야 하는가). 원칙은 가볍게, 이 둘에 무게를 둔다.

## 모듈 라우팅

본문은 항상 로드된다. 아래 모듈은 **조건이 맞을 때만** 편다(설명은 각 파일 안에).

| 언제                                                     | 연다                          |
| -------------------------------------------------------- | ----------------------------- |
| 글 쓰기·다듬기 전 — 비어 있지 않으면 **항상**, 일반 원칙보다 우선 | `references/glossary.md`      |
| 어체 확인·변경. `온보딩 상태` 마커도 여기                 | `references/register.md`      |
| 처음 쓰는데 어체·도메인 단어 미설정 + 온보딩 `완료` 아님  | `references/setup.md`         |
| **긴 산문**(README, 블로그, 릴리스 노트)                  | `references/ai-tells.md`      |
| 본문 번역투 행으로 안 잡히는데 어색할 때 (길이 무관)      | `references/translation-ese.md` |
| `/ux-writing:deep` 또는 "정서까지 살려줘" — **기본 꺼짐**  | `references/deep-mode.md`     |
| 화면 단위(다이얼로그, 빈 상태)를 통째로 손볼 때           | `references/worked-examples.md` |
| 배치, 고위험 문구, "검증 돌려줘"                          | `agents/copy-auditor.md`      |
| 이 스킬이 왜 이렇게 생겼는지, 근거·검증 상태             | `references/about.md`         |

스크립트 3개(`ai_lint.py`, `glossary_check.py`, `register_check.py`)는 **Python
3.8+** 필요. 실행법은 `작업 방식 > 출력 게이트`. 검사 패턴은 `scripts/patterns.json`에
데이터로 있다(코드 안 고치고 거기서 넣고 뺀다).

## 적용 대상

| 영역                                       | 적용 강도                       |
| ------------------------------------------ | ------------------------------- |
| 제품 UI 문구 (라벨, 버튼, 토스트, 빈 상태)  | 필수 (코어밸류 5 + 프린시플 8)  |
| 에러 메시지 / placeholder / 헬프 텍스트    | 필수                            |
| 컴포넌트 문서 / Storybook story 설명       | 필수                            |
| README, 가이드, docs/                      | 권장                            |
| 내부 개발 문서 / 코드 주석                 | 경량 (정확성, 명확성 위주)       |
| 커밋 메시지 본문                           | 영향 없음                       |

적용 강도는 산출물의 위험과 공개 범위로 정한다.

- **경량**: 내부 문서·주석. 의미 보존, 정확성, 명확성만 보고 전체 AI 티 카탈로그와
  스크립트 게이트는 생략할 수 있다.
- **표준**: 제품 UI·외부 README·가이드. 해당 유형 체크리스트와 출력 게이트를 적용한다.
- **고위험**: 결제·삭제·보안·법률·접근성. 정확성 게이트와 copy-auditor를 추가하고,
  결과를 바꾸는 모호성은 확인한다.

기본 어투는 **사용자에게 보이는 문구의 기본값**으로 한국어 `~해요` 친근체.
명령형보다 권유형을 쓴다. 단, 모든 문구에 기계적으로 적용하지는 않는다.

- **친근체보다 정확, 중립이 먼저인 문구**: 법적 고지, 보안, 결제 경고, 규제, 약관
  문구, 데이터 삭제처럼 되돌릴 수 없는 행동의 확인. 여기서는 오해 없이 정확한
  표현이 친근함보다 우선이다.
- **접근성 라벨(aria-label 등)**: 친근하게 바꾸기보다 스크린리더 관례와
  정확한 동작 명칭을 따른다.
- **개발 문서, 코드 주석**: 어투보다 정보 정확성이 먼저다. 평서체(`~한다`)도
  괜찮다. 이 스킬 문서 자체가 그 예시다.

## 이 문서의 용어

아래 단어는 본문과 모듈 전체에서 같은 뜻으로 쓴다. 모듈을 펼쳤을 때 같은
기준으로 판단하려면 정의가 공유돼야 한다.

- **잡초**: 넣든 빼든 의사 전달에 영향이 없는 단어.
- **AI 티**: 뜻은 맞지만 사람이 안 쓰는 질감. 번역투, 관용구, 기계적 대칭,
  시각 장식.
- **빼기 축 / 더하기 축**: 빼기는 티를 걷어내는 것(본문 표, `ai-tells.md`,
  `translation-ese.md`). 더하기는 정서를 보태는 것(`deep-mode.md`). **기본은
  빼기다.**
- **과윤문**: 티를 걷다 원문의 보이스나 의미까지 지운 상태.
  **저윤문** — 안 건드려서 티가 남은 상태. 둘 다 실패다.
- **장르 이탈**: 어체는 유지했는데 글의 성격 자체가 바뀐 것(리포트 → 에세이).
- **게이트**: 내보내기 직전에 정해진 항목을 의식적으로 한 번 보는 행위.
  스크립트는 그 자동화일 뿐이다.

## 코어밸류 5

보이스의 뼈대. 만든 사람이 아니라 **쓰는 사람** 기준으로 판단한다.

| 밸류 | 뜻 | 판단 기준 |
| --- | --- | --- |
| **Clear** 명확 | 한 번에 이해되는가 | 도메인 밖 사람도 읽자마자 아는가 |
| **Concise** 간결 | 필요한 만큼만 | 사용자는 안 읽고 스캔한다 |
| **Casual** 친근 | 쉽고 친절하게 | 기본 `~해요`. 도메인상 못 쓰면 register.md에서 바꾸되 임의로 말고 물어서 |
| **Respect** 존중 | 과장·은폐 없이 | 신뢰는 쌓기 어렵고 무너지기 쉽다 |
| **Emotional** 공감 | 감정에 한 번 닿고 | 이 문구를 보는 순간 사용자 기분을 떠올린다 |

## 프린시플 8

### 1. 다음 화면을 예상할 수 있는 힌트가 있는가? (Predictable hint)

사용자가 다음 화면으로 넘어갈 때 **충분한 힌트**를 준다. 버튼, 링크 라벨,
story title, 모달 헤더에서 다음 동작을 예고한다.
↳ 결과적 이익을 설명하느라 다음 화면에 뭐가 뜰지 안 쓰면 사용성을 해친다.

```
❌ "추천 정확도 높이기"  → 눌렀더니 관심사 설문. 당황.
✅ "관심 주제 고르기"    → 주제 선택 화면이 뜰 걸 예상.
```

### 2. 의미 없는 단어를 모두 제거했는가? (Weed cutting)

**잡초**(넣든 빼든 전달에 영향 없는 단어)를 뺀다. 모바일 사용자는 안 읽고 스캔한다.
↳ 대표적 잡초: `기본적으로`, `일반적으로`, `보통`, `~의 경우에는`, `앞으로`,
`또한`, `그리고`, `정말로`, `매우`, `너무`(강조가 의미를 안 더할 때).

```
❌ 기본적으로 size 속성을 통해 크기를 변경할 수 있습니다.
✅ 크기를 변경하려면 size 속성을 사용하세요.
```

### 3. 의미 없는 문장을 모두 제거했는가? (Remove empty sentences)

문장이 아니라 **문단·화면 단위**로 잡초를 뺀다. 같은 말 반복 금지, 빈 공간을
의미 없는 문구로 채우지 않는다.

```
❌ 제목 "저장됐어요" / 부제 "변경한 내용이 정상적으로 저장되었습니다."
✅ 제목 "저장됐어요" / 부제 생략 (또는 저장 시각 같은 새 정보)
```

### 4. 정말 중요한 메시지만 전달하고 있는가? (Focus on key message)

**사용자가 이미 아는 정보는 생략**하고 지금 확인할 것만 추린다.
↳ 만든 사람은 맥락을 많이 알아 과설명하기 쉽다. 생략이 더 친절할 때가 있다.

### 5. 이해하기 어려운 용어나 표현을 쓰지 않았는가? (Easy to speak)

`read`가 아니라 **`speak`**. 소리 내어 읽어 어색하면 고친다(한자어, 문어체, 긴 호흡).
한 문장 = 한 메시지.

```
❌ "당해 파일의 업로드가 정상적으로 완료되었음을 알려드립니다."
✅ "파일을 다 올렸어요."
```

**코드블록 앞뒤 문장은 각각 완결한다.** "아래 명령이나" 하고 코드블록으로
넘어가 다음 문장이 이어받는 구조는, 소리 내면 코드를 문장 성분으로 읽어야 해서
안 읽힌다.

```
❌ 아래 명령이나 / (코드블록) / "딥모드로" 요청에 켭니다.
✅ 아래처럼 호출합니다. / (코드블록) / 또는 "딥모드로" 요청에 켜집니다.
```

### 6. 특정 행동을 강요하거나 공포감을 주지 않는가? (Suggest over force)

**선택권이 있다**고 느끼게 한다. 손해·공포 프레임으로 유도하지 않는다.

```
❌ "이 혜택을 놓치면 손해예요"        ✅ "지금 가입하면 ○○ 혜택을 받을 수 있어요"
❌ "반드시 aria-label을 써야 합니다."  ✅ "이럴 때는 aria-label을 추가해 주세요."
```

### 7. 모두가 이해할 수 있고 모두에게 무해한가? (Universal words)

연령, 교육, 업계에 따라 갈리는 용어를 피한다. 유행어, 은어, 밈에서 자주 위반된다.
↳ 강도: UI 문구는 엄격, 개발 문서는 도메인 용어(`prop`, `state`) 허용.

```
❌ "님, 이거 ㄹㅇ 꿀팁이에요"         ✅ "이 기능은 자주 쓰는 분들에게 유용해요"
❌ "DOM mutation이 일어나면..."      ✅ "화면이 바뀌면..." (개발 문서는 예외)
```

**IT 영어 차용어**도 여기 해당한다. 뜻 통하는 한국어가 있는데 습관적으로 영어를
쓴 경우만 바꾼다.
↳ 바꾼다: `디폴트`→기본값, `옵트인`→선택해서 켜기, `레거시`→오래된.
↳ 둔다: `온보딩`, `커밋`, `배포`(대체어가 마땅찮게 굳음).

```
❌ 이 기능은 옵트인으로 나눴습니다.   ✅ 이 기능은 선택해야만 켜지게 나눴습니다.
```

### 8. 정보 뒤에 숨은 감정에 공감했는가? (Find hidden emotion)

사실만 던지지 않고 **감정에 한 번 닿았다가** 정보를 준다. 에러, 실패, 대기, 빈
상태에서 특히. 단, 한 마디면 충분하다(장황함 금지).

```
❌ "결제에 실패했습니다. 오류 코드: E-402"
✅ "결제가 안 됐어요. 카드 한도를 확인해 주세요. (E-402)"
```

## 원칙이 충돌할 때

```
정확 → 명확 → 간결 → 감정
```

앞이 뒤를 이긴다. 틀린 문구는 친근해도 소용없다. **AI 티 빼기는 이 사다리
아래쪽** — 뜻이 정확·명확하면 티가 좀 남아도 뜻을 흐리면서까지 고치지 않는다.
질감은 의미 다음이다.

## AI가 쓴 티 빼기

뜻은 맞지만 사람이 안 쓰는 질감이 있다. 아래가 보이면 고친다. (특히 UI 문구,
짧은 카피에서 거슬린다.)

| 유형          | 빼야 할 신호                                         |
| ------------- | ---------------------------------------------------- |
| 번역투        | `~를 통해`, `~에 대해`, `~에 있어서`, 이중 피동(`되어진다`), `가지고 있다` (문법 단위 세부는 `references/translation-ese.md`) |
| AI 관용구     | `결론적으로`, `손쉽게`, `원활하게`, `효율적으로`, `~을 제공합니다` |
| Hedging       | `~할 수 있을 것으로 보입니다`, `~인 것 같습니다`처럼 겹친 완곡 |
| 형식명사      | `~하는 것입니다`, `~할 필요가 있습니다`, `~라는 점`   |
| 시각 장식     | 가운뎃점(·) 사슬, 과한 **볼드**, 대시(—) 남발, 불필요한 이모지 |
| 기계적 병렬   | 모든 항목이 `첫째/둘째/셋째`로 균일, 같은 종결어미 반복 |

```
❌ "파일 업로드를 통해 손쉽게 공유할 수 있습니다."
✅ "파일을 올리면 바로 공유할 수 있어요."

❌ "오류가 발생한 것으로 보입니다. 다시 시도해 주시기 바랍니다."
✅ "문제가 생겼어요. 다시 시도해 주세요."

❌ "이름·이메일·연락처를 입력해 주세요."
✅ "이름, 이메일, 연락처를 입력해 주세요."
```

가운뎃점은 **둘 묶기(`보기·숨기기`)는 괜찮고**, 셋 이상 사슬만 쉼표·문장으로 푼다.

- **원칙: 의미는 그대로, 질감만.** 티 보이는 구간만 수술적으로, 멀쩡한 문장은 안 건드린다.
- **위 표는 짧은 단건 UI용.** 긴 산문(README, 릴리스 노트)엔 산문에서만 나는 티가
  더 있다 — 의미 과장, 3의 법칙, 부정 병렬, 동의어 돌려막기, 뻔한 결론. 24패턴
  전체는 `references/ai-tells.md`.
- **단어를 다 걷어도 글 전체에 AI 느낌이 남으면**(고른 리듬, 과한 대칭, 관점 부재,
  가짜 구체성) `ai-tells.md`의 `게슈탈트 점검`으로. 리듬·대칭은 편집으로 고치되,
  관점·구체 경험은 **지어내지 말고 작성자에게 묻는다.**

## 빠른 체크리스트

문장을 쓴 뒤 5초 안에 훑어본다.

- [ ] **Clear**: 도메인 밖 사람도 한 번에 이해되는가?
- [ ] **Concise**: 잡초 단어 없는가? (`기본적으로`, `~의 경우`, `또한`)
- [ ] **Casual**: 목표 어체에 맞는가? 명령형 대신 권유형인가?
- [ ] **Respect**: 강요, 공포 프레임 없는가?
- [ ] **Easy to speak**: 소리 내서 읽었을 때 자연스러운가? 한 문장 = 한 메시지인가?
- [ ] **Predictable hint**: 라벨이라면, 누른 뒤 무슨 일이 일어날지 예상되는가?
- [ ] **Find hidden emotion**: 사용자가 이 문구를 보는 순간의 감정을 떠올렸는가?
- [ ] **AI 티**: 번역투, 관용구, 과한 볼드, 가운뎃점 사슬 없는가?
- [ ] **과윤문 역점검**: 원안보다 밋밋하거나, 반대로 너무 많이 바꾸진 않았는가? (걸리면 `작업 방식 > 과윤문 상세 점검`과 `의미 보존 체크리스트`를 편다.)
- [ ] **장르 이탈 없음**: 격식체가 캐주얼체로, 담백한 안내문이 과한 에세이체로 옮겨가지 않았는가?
- [ ] **글 전체 느낌**: (긴 글) 리듬이 다 비슷하거나 항목을 다 똑같은 분량으로 다루지 않았는가?

## 작업 방식

### 출력 계약

받은 문구를 고칠 땐 이 순서로 보여준다. 결과만 던지지 않는다.

```
원안:    (받은 문구)
수정안:  (고친 문구)
이유:    (적용 프린시플 1줄)
대안:    (톤이 갈리면 1개 더 — 선택)
```

- 먼저 이 문구가 **어디에, 어떤 순간에** 쓰이는지 확인한다(모르면 묻는다).
- 이유를 주면 사용자가 다음부터 스스로 판단한다.
- 문구가 여럿이거나 빠른 답을 원하면 `원안 → 수정안` 한 줄로 압축한다.

### 직접 쓴 글에도 위험도에 맞게 적용한다

Claude가 직접 쓴 제품 UI·외부 README·가이드·산문은 내보내기 직전에 `출력
게이트`와 `빠른 체크리스트`를 통과시킨다. 내부 문서·주석은 경량 기준을 적용한다.
긴 산문이거나 사용자가 AI 티 제거를 요청했을 때만 `references/ai-tells.md`를 편다.
↳ 이쪽이 잘 새어나간다. 받은 문구는 "고쳐줘"가 트리거지만 직접 쓴 글은 트리거가
없고, `원안`이 없어 출력 계약 형식도 안 맞아 문서 전체를 건너뛰기 쉽다.
(단, 직접 쓴 글엔 출력 계약 블록 자체는 안 쓴다.)

### 출력 게이트 (내보내기 직전)

기계적 티는 "안다"고 안 잡힌다 — 생성 시점엔 내용에 집중하느라 안 떠오른다.
게이트의 본질은 스크립트가 아니라 *내보내기 직전에 의식적으로 한 번 보는 행위*다.

**표준·고위험 산출물 필수 (HARD 0이어야 통과)**

- 파일·긴 글이면: 먼저 이 `SKILL.md`가 있는 폴더를 확인하고
  `python3 <ux-writing 스킬 폴더>/scripts/ai_lint.py <파일>`을 실행한다. 채팅 출력은
  `printf '%s' "<텍스트>" | python3 <ux-writing 스킬 폴더>/scripts/ai_lint.py -`로
  검사한다. HARD 0이 아니면 고치고 재실행한다.
- 글로서리가 차 있으면
  `python3 <ux-writing 스킬 폴더>/scripts/glossary_check.py <파일>`도 실행한다. 비면
  자동 생략한다.

**ai_lint가 보는 것** (패턴은 `scripts/patterns.json`)

| 층 | 항목 |
| --- | --- |
| HARD | 이중 피동처럼 문법·의미가 거의 항상 깨지는 항목 |
| ADVISORY | 가운뎃점 사슬, 이모지, 곱슬따옴표, 어체 혼용, 볼드, 대시, 번역투, 의인화 주어, 연결어미+쉼표, 숫자 인덱싱, 문장 끝 콜론, 종결어미 연속, 리스트 라벨 대시 |

- **어체 혼용은 신호다.** 프로젝트 register가 정해진 산출물은
  `register_check.py`로 목표 대비를 검사한다. 장르상 의도된 혼용을 자동 실패시키지 않는다.
- **코드블록 안은 검사 제외.** 나쁜 예시·명령어가 거기 든다. 잡으면 예시 있는 문서는 영영 통과 못 해 게이트가 소음이 된다.
- **패턴 추가·삭제는 `patterns.json`만 고친다.** `status`: `verified`(실전 확인) / `experimental`(재현 못 봄, 가지치기 1순위).

**폴백** — 코드 실행이 안 돼도 표준·고위험 게이트를 건너뛰지 않는다. 통과 기준은
*스크립트 실행이 아니라 HARD 0*이다. HARD 항목을 눈으로 찾아 고치고 "수동 점검
완료"로 표시한다.

**경로 주의 (샌드박스)** — `glossary_check`·`register_check`는 대상 파일 경로로
프로젝트를 찾는다. claude.ai처럼 출력을 임시 폴더에 만들면 실제 경로와 안 맞아
**프로젝트 규칙이 조용히 안 걸린다.** 적용처를 알면 `--as <실제경로>`, 모르면 묻는다.

**권장** — 어체가 지정돼 있으면
`python3 <ux-writing 스킬 폴더>/scripts/register_check.py <파일>`을 실행한다.
미지정이면 자동 생략한다.

의미 과장·장르·보이스·인과 같은 판단형은 체크리스트와 필요 시
`agents/copy-auditor.md`로 본다.
HARD 0은 이중 피동 같은 결정적 기계 오류가 없다는 뜻일 뿐, 좋은 문장이나 의미 보존을
보증하지 않는다.

### 문구 유형별 먼저 보는 원칙

전부를 매번 적용하려 들지 않는다. 유형마다 가장 잘 어겨지는 원칙부터 본다.
(시작점일 뿐, 맥락이 우선이다.)

| 문구 유형          | 먼저 보는 원칙                          |
| ------------------ | --------------------------------------- |
| 버튼, 링크 라벨     | 다음 화면 예고 → 간결                    |
| 에러 메시지        | 명확 → 숨은 감정 공감 (사실 나열로 끝내지 않기) |
| 빈 상태 문구       | 핵심 메시지 집중 → 다음 행동 힌트        |
| 토스트, 완료 알림   | 빈 문장 제거 (새 정보 없으면 부제 생략)  |
| placeholder        | 간결 → 예시, 형식 힌트 위주 (placeholder만으로 라벨 대체 금지) |
| 개발 문서, 주석     | 정확성 → 명확 (톤은 후순위)              |
| 코드블록 포함 문서 (README 등) | Easy to speak — 코드블록 앞뒤 문장 완결 |

### 고치지 않는 것 (Do-Not-Touch)

다음은 다듬기 대상이 아니다. 그대로 둔다.

- 수치, 단위, 날짜
- 고유명사, 제품명, 사람 이름, 에러 코드
- 큰따옴표 안 직접 인용
- 법적, 약관, 규제 문구, 브랜드가 정한 고정 표기

### 과윤문 상세 점검

`빠른 체크리스트`의 "과윤문 역점검"이 걸리면 여기로 온다.

- 원안보다 밋밋하고 사무적이면, 수식을 빼다 사람 냄새와 의도된 보이스까지 지운
  것이다. 한 걸음 되돌린다.
- 문장 절반 이상을 다시 썼다면 윤문이 아니라 재작성이다. `멈추고 물어야 할
  때`로 돌아간다.
- 거의 안 건드렸는데 티가 남아있다면 놓친 것이다. `AI가 쓴 티 빼기` 표를 한 번
  더 훑는다.

구체적으로 이 세 신호를 본다.

- **문학화**: 원문에 없던 비유·수사를 임의로 넣었는가.
- **구어화 과다**: 격식체였는데 슬쩍 `~해요, ~네요`로 넘어갔는가.
- **어휘 바꿔치기 과다**: 원문 핵심어를 계속 다른 말로 바꿔 주제 추적이
  끊겼는가 (`동의어 돌려막기`, ai-tells.md 11번).

### 의미 보존 체크리스트

**문장을 고치면서도 뜻이 그대로인지** 본다. 구조를 바꾸는 처방(피동→능동,
완곡→단언)이 뜻을 슬쩍 바꾸기 쉬워서다.

- **주장의 확실성 방향**: "~일 수 있다"(가능성)를 "~이다"(단정)로 바꾸지
  않았는가? 원문이 가능성을 말하면 그 가능성이 남아 있어야 한다.
- **인과관계 순서**: A→B였던 게 B→A로 뒤바뀌지 않았는가?
- **피동→능동 전환 시 행위자 유지**: 주어 자리에 온 게 실제 행위자가 맞는가?
- **양화·한정 층위**: "대부분"을 "모든"으로, "일부"를 "많은"으로 슬쩍 키우지
  않았는가?
- **긍정·부정 극성**: 이중부정을 단순화하다 뜻이 반대로 뒤집히지 않았는가?
- **열거 순서**: 시간순·중요도순처럼 순서가 의미를 담고 있으면 유지했는가?

의심스러우면(확신이 5할 이하면) 원문 표현 쪽으로 되돌린다.

### 멈추고 물어야 할 때

아래는 혼자 고치지 말고 사용자에게 먼저 확인한다.

- 되돌릴 수 없는 행동(삭제, 결제, 전송)의 확인 문구
- 친근체가 부적절해 보이는 맥락(법적, 보안, B2B)
- 원문의 절반 이상을 새로 써야 할 때 (윤문이 아니라 재작성)
- 브랜드 고정 표기인지 일반 문구인지 모호할 때

> **예시는 패턴이지 정답 템플릿이 아니다.** 이 문서의 전후 예시를 그대로
> 복붙하지 말고, 맥락이 다르면 원칙으로 돌아가 판단한다.

### 최초 설정과 프로젝트 고유 어휘

- **처음 쓰는데** 어체·도메인 단어 미설정 + `온보딩 상태`가 `완료` 아니면
  `references/setup.md`로 한 번 묻고 시작. 대화 검색·셸·Python 확인은 해당
  기능이 있을 때만 하며, 없으면 수동 폴백으로 선호 설정과 본 작업을 계속한다.
- 건너뛰면 기본값(`~해요`, 표기 강제 없음)으로 가되 **`완료`로 기록**해 다시 안 묻는다.
- 폴더가 읽기 전용이면(claude.ai) 온보딩은 세션당 한 번만, 나머지는 기본값으로 조용히.
  setup.md는 `conversation_search`가 제공될 때 파일 보기 전에 과거 값을 먼저 찾는다.
- 고정 표기는 `references/glossary.md`에. **쓰기 전 먼저 읽고**, 일반 원칙보다 우선. 비면 무시.

## 검증 레이어 (선택)

평소 단건은 위 작업 방식대로 처리하고 끝낸다. 강제 파이프라인은 안 끼운다 —
가벼움이 장점이다. 아래일 때만 `agents/copy-auditor.md`(fresh-eyes 검증)를 발동한다.

- **배치**: i18n, 화면 전체 카피 등 대량 문구
- **고위험**: 삭제, 결제, 법적, 보안처럼 틀리면 손해 큰 문구
- **명시 요청**: "검증 돌려줘"

auditor는 새 기준 없이 이 문서의 `고치지 않는 것`, 과윤문, 멈춤 게이트, AI 티를
채점 항목으로 쓴다. 핵심은 **다른 시선이 결과만 보고 판정**하는 것.
↳ 패킷은 **원안 + 수정안 + 중립적인 문구 유형·사용 맥락**만 담는다. 수정 이유,
노린 프린시플, 기대 판정은 넘기지 않는다. 판정이 어긋나면 설득 말고 문구를 고친다.
↳ 서브에이전트가 없으면 메인 스레드가 순차로 밟는다(효과는 약해짐).
