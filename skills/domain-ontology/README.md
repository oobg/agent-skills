# Domain Ontology

대화마다 같은 배경을 다시 설명하지 않도록 회사, 개인, 공용, 소설, 블로그 지식을 SQLite
온톨로지에 연결하는 에이전트 스킬입니다. 관련 주제 신호가 있으면 먼저 조회하고,
오래 남길 자료는 사용자 동의를 받은 뒤 원문과 근거를 보존해 적재합니다.

## 사용 시점

**적용 여부가 애매하면 조회가 기본값입니다.** 판단 기준은 “조회하면 답이 바뀌는가”가
아니라 “주제 신호가 있는가”입니다. 앞의 것은 조회한 뒤에만 알 수 있어서 기준으로 쓰면
매번 발동하지 않는 쪽으로 기울고, 뒤의 것은 지금 관찰됩니다.

조회 신호는 하나만 있어도 충분합니다.

- 이전 결정이나 축적된 맥락을 참고해야 할 때
- 제품, 전략, 경쟁, 법률, 조직, 개인 우선순위에 관한 질문
- 일하는 방식(방법론, 도구론, 에이전트 하네스, 스킬과 프롬프트 설계)
- 작품 세계와 원고, 블로그 연재와 퇴고본
- “전에 정한”, “우리 방식”처럼 과거 맥락을 전제하는 표현
- 보고서, 연구 결과, 전략 문서처럼 재사용할 자료가 들어왔을 때
- “온톨로지에서 찾아줘”, “이거 적재해줘”라고 요청할 때

코드나 저장소 작업이라는 사실만으로는 제외하지 않습니다. 설계 근거, 규칙, 컨벤션,
이전 결정이 걸리면 조회합니다. 스펙이 확정된 구현과 리팩터링, 테스트와 빌드 실행,
포맷팅과 번역처럼 판단이 걸리지 않는 작업, 온톨로지와 무관한 일반 상식과 가벼운
대화만 조회 없이 진행합니다.

조회 신호가 있는데 건너뛰기로 했다면 그 판단을 한 줄로 밝힙니다. 밝히지 않으면
스킬이 아예 발동하지 않은 것과 구분되지 않습니다.

## 조회와 적재

### 조회

관련 주제 신호가 있으면 별도 확인 없이 읽기 전용으로 조회합니다. 개념, 토픽,
claim 근거를 연결해 기존 결정과 충돌, 보강점, 빈틈을 찾은 뒤 실제 질문에 답합니다.

### 적재

온톨로지 쓰기는 항상 사용자 동의가 필요합니다. 적재할 자료의 범위와 테넌트를
확인한 뒤 다음 순서로 진행합니다.

```text
원문 보존 → 기존 개념 조회 → claim 추출 → 증분 적재 → 그래프 연결 확인
```

침묵은 동의로 간주하지 않습니다. 조회 허용이 적재나 수정 권한까지 뜻하지도
않습니다.

## 테넌트

| 테넌트 | 담는 지식 | 예시 |
| --- | --- | --- |
| `company` | 회사 업무와 사업 맥락 | 제품, 전략, 경쟁, 법무 |
| `personal` | 개인의 삶과 우선순위 | 자기계발, 개인 기록 |
| `shared` | 여러 영역에 적용되는 일하는 방식 | 방법론, 도구론, 에이전트 하네스 |
| `novel` | 작품 단위의 창작 맥락 | 세계관, 인물, 설정, 플롯, 원고 |
| `blog` | 외부 발행용 글과 연재 맥락 | 연재 원고, 퇴고본, 발행본 |

주제가 “무엇을 만드는가”보다 “어떻게 일하는가”에 가깝다면 `shared`를 먼저
고려합니다.

소설은 기본적으로 `novel + shared`, 블로그 연재와 기존 원고는 `blog + shared` 범위에서
조회합니다. 작품별 원본은 `novel/sources/works/<work-slug>/`, 연재별 원본은
`blog/sources/series/<series-slug>/` 아래에서 서로 분리합니다.

## 핵심 원칙

- 원문은 불변 provenance로 보존합니다.
- 기존 개념 이름을 재사용해 그래프 분절을 막습니다.
- 사실, 추론, 추천, 미해결 gap을 서로 섞지 않습니다.
- 가능성을 단정으로, 상관을 인과로 바꾸지 않습니다.
- 외부 검증이 없는 회상과 제3자 평가는 그 한계를 표시합니다.
- lint 통과보다 tenant, path, 근거, 남은 불확실성을 먼저 확인합니다.
- 적재는 준비 단계입니다. 연결을 확인한 뒤 사용자의 원래 질문까지 처리합니다.

## 안전 규칙

- `docs.py load`에는 항상 `--tenant`를 지정합니다.
- 전체 `build.py` 리빌드는 실행하지 않습니다.
- 서로 다른 테넌트 사이에서 문서를 재적재해 이동하지 않습니다.
- 원문이 말하지 않은 claim을 만들지 않습니다.
- 모호한 테넌트나 원본 범위는 적재 전에 확인합니다.

온톨로지 저장소의 `~/.ontology/AGENTS.md`는 프로바이더와 무관한 구조 지도와 공통 명령
정본입니다. 실제 라우팅 워크플로와 세부 규칙은 그 문서가 가리키는 파일을
따릅니다. 이 README의 예시는 운영 명령을 대체하지 않습니다.

## 사용 예

```text
이 전략 질문에 답하기 전에 온톨로지에서 관련 결정과 근거를 찾아줘.
```

```text
이 보고서를 온톨로지에 적재해줘. 회사 자료야.
```

```text
이 에이전트 운영 방법론을 shared에 추가하고 기존 검증자 개념과 연결해줘.
```

## 구성

```text
domain-ontology/
├── SKILL.md
└── README.md
```

- [`SKILL.md`](SKILL.md): 트리거, 조회와 적재 라우팅, 품질 게이트, 안전 규칙
- [`README.md`](README.md): 사람을 위한 개요와 사용 안내

설치와 검증 방법은 저장소의 [루트 README](../../README.md)에서 확인할 수 있습니다.
