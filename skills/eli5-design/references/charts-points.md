# charts-points — 점 그래프(개별 점·스트립·벌집·산점)

점이나 산점·스트립을 실제로 고른 뒤에만 읽는다. 막대·막대 목록은 [diagrams/comparison.md](diagrams/comparison.md)다. 아래 `기본값`은 안전한 출발점이라 렌더에서 점·라벨·분포가 분명하면 넘을 수 있고, 표시가 없는 항목은 렌더가 읽혀도 지킨다.

## 주장에 형태를 맞춘다

점 하나하나가 의미 있을 때만 개별 점을 쓴다. 주장이 집단의 대표값이나 집단 사이 차이면 점구름에서 눈대중하게 하지 않고 집계를 먼저 보인다.

| 주장 | 기본 형태 | 개별 점 |
| --- | --- | --- |
| 집단 비교 | 그룹별 대표값 + n, 표본이 충분하면 가운데 50% | 분포가 중요한 작은 집단에서 보조로 |
| 추세 | 자연스러운 구간별 실제 대표값을 잇는 선, 또는 입력에 있는 추세값 | 원시 관측의 보조로 |
| 이상치 | 점·스트립·산점 + 필요한 기준선 | 먼저 쓴다 |
| 분포 | n이 작으면 스트립·벌집, 빽빽하면 요약 | 개별 분포가 읽힐 때 |

## 작은 집단과 점 수

- 그룹 n < 5이면 가운데 50%나 최솟값~최댓값 같은 범위 요약을 그리지 않는다. 개별 점과 n만 보인다.
- `기본값` n 5~7은 개별 점 + 필요하면 중앙값, n ≥ 8이면 중앙값과 가운데 50%를 쓸 수 있다.
- `기본값` page는 개별 점 40개까지(41~80은 렌더에서 읽힐 때만, 넘으면 집계), 범주 6개. deck은 24개까지(25~40은 렌더에서 읽힐 때만), 한 장 범주 4개.

## 겹침과 배치

- `기본값` 두 점 중심 거리가 2r + 2px보다 가까우면 겹친 것이다. 겹친 점이 10% 미만이면 그대로, 10~25%면 결정적 지터·벌집, 25%를 넘으면 집계를 먼저 검토한다.
- 지터와 벌집은 난수 없이 결정적으로 한다. 후보 위치를 0, +d, −d, +2d, −2d 순으로 검사하고(d ≥ 2r + 2px) 범주 축 방향으로만 비켜 놓는다. 값 축의 실제 값은 바꾸지 않는다.
- 연속 두 축 산점에서 겹침을 풀려고 x·y를 함께 움직이지 않는다. 심하면 구간으로 묶거나 집계한다.

## 계산값·축·기준선

- 계산한 선·점·범위는 무엇인지 차트 곁에 바로 적는다(`중앙값`, `가운데 50%`, `전체 중앙값`). 그룹 비교는 그룹마다 n을 적는다(`A팀 · 9건`).
- 회귀선·평활 곡선·임의 이동평균을 새로 계산하지 않는다. 관측 없는 구간을 보간하지 않는다. 원시 점만 보이면서 데이터가 뒷받침하지 않는 추세를 제목으로 단정하지 않는다.
- 수치 축에는 무엇을 잰 값인지와 단위를 화면에 보이는 글로 적는다(`첫 처리까지 걸린 시간(분)`). 기준선은 입력에 있거나 분명히 계산할 수 있는 값만 쓴다.
- `기본값` 연속 축 눈금 3~5개. 점·스트립은 0을 억지로 넣지 않고 실제 범위가 읽히게 잡는다.

## 이름표와 색

- 특정 점의 이름표는 그 점 바로 곁(렌더 약 4~8px)에 붙이고, 멀면 짧은 지시선으로 잇는다. `기본값` 직접 이름표는 주장에 중요한 사례 1~3개만.
- 강조는 blue 하나로 주장이 가리키는 점·그룹에 둔다. 강조가 점구름의 대부분을 덮으면 강조가 아니므로 대표값 표식을 강조하는 쪽을 검토한다.
- 집단·범주를 나누려고 새 색을 만들지 않는다. 위치, 채운 점과 빈 점(`data-fill`), 직접 라벨로 나눈다. 실제 상태일 때만 의미색(`data-tone`)을 쓴다.
- 강조할 점이 없으면 중앙값 표식에 `data-on`을 단다.

## 마크업

```html
<figure class="d0-fig" data-variant="dots">
  <svg viewBox="0 0 560 300" role="img" aria-labelledby="dc-t dc-d">
    <title id="dc-t">팀별 처리 시간</title>
    <desc id="dc-d">주간팀 기록 아홉 건을 점으로 찍고 중앙값과 가운데 50% 칸을 표시했다.</desc>
    <text class="d0-s-text d0-dot-axis" x="0" y="16">처리 시간(분)</text>
    <g class="d0-dot-group" data-n="9">
      <rect class="d0-s-iqr d0-dot-range" x="72" y="124" width="48" height="36"/>
      <line class="d0-s-line d0-dot-median" data-on x1="68" x2="124" y1="146" y2="146"/>
      <circle class="d0-s-node d0-dot" cx="96" cy="60" r="5"/>
      <circle class="d0-s-node d0-dot" cx="96" cy="146" r="5"/>
      <!-- 점마다 하나, 결정적 배치(0, ±d) -->
      <text class="d0-s-text d0-dot-label" x="106" y="65">가장 늦음</text>
      <text class="d0-s-text" x="132" y="151">중앙값</text>
      <text class="d0-s-text" x="96" y="290" text-anchor="middle">주간팀 · 9건</text>
    </g>
  </svg>
</figure>
```

- 점 `circle.d0-s-node.d0-dot`(빈 원 기본, `data-on`, `data-tone`, `data-fill`), 그룹 `g.d0-dot-group[data-n]`, 중앙값 `.d0-dot-median`, 가운데 50% `rect.d0-s-iqr.d0-dot-range`, 이름표 `text.d0-dot-label`, 축 이름 `text.d0-dot-axis`. CSS는 `assets/page.css`에 있다.
- deck은 viewBox 800, 점 r 7, 글자는 `g.d0-sl-label` 안 `text`(이름표·축 클래스를 함께 단다)다. 데이터 장 제목은 데이터가 뒷받침하는 만큼만 단정한다(차이가 분명하지 않으면 `세 팀의 처리 시간은 겹쳐 뚜렷한 차이가 없다`).
- 렌더를 볼 수 없으면 [render-unavailable.md](render-unavailable.md)의 점 그래프 상한을 따른다.
