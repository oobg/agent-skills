# faq — 용어·FAQ

**패턴: 이 용어는 무슨 뜻이고, 내 질문의 답은 무엇인가?** 페이지 타입이 아니라 이 질문에 답하는 섹션의 표현 방식이다. 다른 패턴 섹션과 한 페이지에 섞어 쓴다(섹션 `data-pattern="faq"`).

독자가 알고 싶은 것: 내 질문의 답은?
읽고 나서 할 수 있어야 하는 것: **특정 질문을 바로 해결한다.**

## 이 패턴이 답하는 질문

- 처음 보는 용어가 각각 무슨 뜻인가?
- 내가 가장 궁금한 질문의 답은 무엇인가?
- 여기서 답을 못 찾으면 어디로 가는가?

순서 없이 골라 읽는 페이지다. 본문을 대신하지 않고 보완하는 계층이다.

## 요청 신호

"용어 정리", "FAQ", "자주 묻는 질문", "이게 다 무슨 말이야", "용어집 쉽게".

## 섹션 구성

1. **범주별 묶음.** 질문을 독자가 찾는 범주(시작·요금·문제 등)로 묶는다. 범주가 하나면 묶음 제목을 생략한다.
2. **묻는 말 그대로의 질문.** 실제 독자가 묻는 문장을 질문으로 쓴다.
3. **첫 마디에 즉답.** 답의 첫 단어는 `네`, `아니요`, 숫자 또는 한 줄 결론이다.
4. **조건.** 즉답 다음에 예외·조건을 한두 문장으로 붙인다.
5. **못 찾았을 때.** 마지막에 "답을 못 찾았나요" 안내 한 줄로 다음 행동(문의할 곳·읽을 페이지)을 준다.
   문의 창구가 없으면 본문 문서(정본 페이지)나 관련 패턴 페이지(flow·guide 등)를 가리킨다. 없는 창구를 지어내지 않는다.

질문 하나에 답 하나다. "무엇인가요", "왜 좋은가요"는 FAQ가 아니라 본문(flow·preview)이다.

## 대표 도식

용어마다 작은 그림 하나(용어가 가리키는 사물의 모양: 줄 서기 = 점 여러 개가 한 줄, 묶음 = 상자 안 격자).

## 섹션으로 쓸 때

- 다른 패턴이 이끄는 페이지 끝에 "자주 묻는 것"을 한 섹션으로 둔다. 앞에 용어가 많으면 용어 그림 카드를 첫 섹션 가까이 빌린다.
- 추천 블록: [faq](../blocks/faq.md) 답글형, 용어 [thumb-cards](../blocks/thumb-cards.md), 핀 용어([diagram](../blocks/diagram.md) (g)). 구도는 Summary 또는 Canvas.

## 함께 자주 섞는 패턴

- 기능 소개의 마지막 섹션, guide의 막혔을 때, flow 앞의 용어 맞추기로.

## explanation 쓰는 곳

- 답 자체가 질문→답 구조라 explanation을 겹치지 않는다. 용어 카드 아래 `interpretation`(헷갈리는 두 용어의 차이) 하나까지만 쓴다.

## 추천 조합

용어 thumb-cards 또는 핀 용어 + question-answer + 못 찾았을 때 한 줄. 블록은 패턴이 소유하지 않는다. 다른 패턴 문서의 블록도 필요하면 그대로 빌린다([blocks.md](../blocks.md)).

## 페이지 주 패턴일 때 (자연스러운 깊이 질문 수만큼)

이 패턴이 페이지 대부분을 차지할 때의 출발점이다. 깊이는 참고값이고 섹션 수는 독자 질문이 정한다. 첫 화면 섹션은 그림이 필수이고, 그 아래 섹션은 핵심 구조가 있으면 그림을 권장한다. 아래를 전부 채우지 않는다.

header(문장형 리드) → ① 용어 그림 카드: thumb-cards(그림 + 용어 + 한 줄 비유) → ② 질문: [faq](../blocks/faq.md) 답글형(4~6, 질문 아래 답을 항상 노출, 질문→답 구조라 그림 없음). 범주가 둘이면 reply 묶음 위 소제목으로 나눈다(범주가 서로 다른 독자 질문이면 섹션을 나눠도 된다). "답을 못 찾았나요" 한 줄은 질문 섹션 맨 끝에 둔다. 구조 질문이 섞이면 ③으로 연결 그래프 하나.

용어가 6개 이상이면 카드를 3~5개로 줄이고, 나머지는 와이어프레임 위 번호 핀 용어(diagram 핀 오버레이, 핀마다 용어 한 줄)로 묶는다. 카드 + 질문 합계 10 이하는 이렇게 지킨다: 핀 용어 묶음 전체를 카드 1개로 세고, 카드 3~5 + 핀 묶음 1 + 질문 4~5로 맞춘다. 그래도 넘으면 주제별로 페이지를 나눈다.
핀 도식은 연동 동작이 기본이다. 범례 용어에 올리거나 Tab으로 가면 같은 번호 핀과 영역이 켜진다([diagram](../blocks/diagram.md) (g) pins).

비유는 일상 사물로 든다. 예: "대기열은 은행 번호표와 같다."

## 문장 규칙

- 질문은 독자의 말로 쓴다. "환불 정책 안내"가 아니라 "환불받을 수 있나요?".
- 답의 첫 마디가 결론이다. "네, 7일 안이면 돼요." 다음에 조건을 붙인다.
- 답은 3문장 이내다. 넘으면 본문 페이지로 보낸다.
- 용어는 다른 용어로 풀지 않는다. 일상 사물 비유로 푼다.
- 같은 대상은 페이지 전체에서 같은 이름으로 부른다.

## 패턴 안티패턴

- 핵심 구조가 있는 섹션을 그림 없이 문단으로만 채우기, 질문 없이 추천 블록을 전부 채우기, 짧게 만들려고 이유·조건을 지우기.
- 질문 6개 초과(원칙 상한). 용어 카드와 질문을 합쳐 10개를 넘으면 주제별로 페이지를 나눈다.
- 답을 접어서 가림. FAQ는 reply로 모든 답을 항상 노출한다.
- 답이 배경 설명으로 시작하고 결론이 뒤에 나옴.
- 질문 하나에 답 여러 개, 또는 한 질문에 질문 둘을 묶음.
- 아무도 묻지 않는 홍보성 질문("왜 좋은가요?").
- 답을 못 찾은 독자의 다음 행동이 없음.
- 용어를 다른 용어로 설명.

## 경계

- 구조·흐름을 이해시키는 것이 목적이면 flow 섹션으로 답하고, 용어 카드는 그 앞에 빌려 둔다.
- "무엇인가요"에 길게 답해야 하면 본문 페이지(flow·preview)로 만들고 FAQ는 그 보완으로 둔다.

## 덱으로 낼 때

덱은 맞지 않는다. FAQ는 독자가 필요한 질문만 골라 찾는 문서이고, 덱은 정해진 순서로 넘기며 보는 형식이라 쓰임이 반대다. 기본은 page다.
발표에서 용어를 먼저 맞춰야 하면 다른 패턴 덱의 앞쪽 1~2장으로 용어 그림 카드(`breakdown`)를 빌린다.
단독으로 낸다면 `<main class="d0-deck" data-pattern="faq">`, 규칙은 [deck](../output/deck.md).

스토리라인(5장, 표지 다음 제목 목차는 공통이라 생략):
왜 이 말들을 맞추나 → 용어 지도 → 자주 헷갈리는 쌍 → 가장 많이 묻는 질문 → 더 볼 곳

| 장 | `data-kind` |
| --- | --- |
| 왜 이 말들을 맞추나 | `cover` |
| 용어 지도 | `breakdown`(용어끼리의 관계, diagram 핀) |
| 자주 헷갈리는 쌍 | 근거(두 용어를 같은 축으로 그린 그림 + 요점) |
| 가장 많이 묻는 질문 | `assertion`(답 한 문장) |
| 더 볼 곳 | `closing`(`action`: 다음 행동) |

Impact: 가장 많이 묻는 질문의 답(`assertion`) 한 장.
