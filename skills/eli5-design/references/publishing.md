# publishing — 파일과 게시

게시를 요청받았거나 호스트 지침이 게시를 기본으로 요구할 때만 읽는다.

## 파일

- 결과는 외부 요청 없는 단일 HTML 파일이다. CSS·SVG·JS는 인라인이고, 폰트는 `scripts/subset_font.py`로 페이지 글자만 담은 서브셋을 인라인한다. 도구가 없으면 폰트 링크 하나를 남기고, 외부 요청 1건과 시스템 폰트 대체 가능성을 사용자에게 알린다.
- 로컬 파일은 게시 여부와 관계없이 늘 남긴다. 게시 도구가 없으면 파일만 낸다.
- 한 artifact 안에서 여러 페이지를 탭으로 보여 주면 같은 artifact의 다른 파일을 iframe `src`로 부르지 않는다. 페이지 HTML을 base64 JSON으로 내장하고 `TextDecoder`로 풀어 `iframe.srcdoc`에 넣는다. iframe은 `sandbox="allow-scripts"`이고 `allow-same-origin`은 주지 않는다. 새 탭 열기는 같은 HTML의 Blob URL이고, 막히면 안내 문구를 보여 준다.
- 호스트 게시 도구가 자체 디자인 지침(다크 모드 재정의 등)을 요구해도 이 스킬의 라이트 온리·명시적 배경·day0 토큰을 따른다.

## 게시

- 게시 기본값은 호스트 지침을 따르고, 공개 범위는 도구의 비공개 기본값을 따른다. 결과로 링크를 준다.
- 게시가 기본이어도, 민감하지 않은 것이 분명하고 [final-review.md](final-review.md)의 렌더 검토를 마쳤을 때만 묻지 않고 게시한다. 아래 중 하나라도 해당하면 파일만 만든 뒤 게시할지 묻는다.
  - 인증 정보(비밀번호·API 키·접근 토큰·쿠키), 개인정보·개인 식별 정보
  - 비공개 코드·내부 구조, 고객 내부 데이터, 보안 취약점·보안 사고
  - 계약·재무·인사 정보, 공개 전 제품·일정 정보, 기밀·비공개 표시가 있는 내용
  - 실제 조직·인물을 흉내 내는 내용, 판단이 애매함
- **같은 링크 갱신.** 독자·공개 범위·민감도·문서 목적이 모두 같을 때만 이미 게시한 링크를 갱신한다. 하나라도 다르면 새 링크를 만든다. 민감도가 오른 문서는 기존 링크에 덮어쓰지 않는다.
