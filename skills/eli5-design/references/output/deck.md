# deck — 한 장씩 넘기는 발표 덱 출력

출력 형식은 두 가지다. 기본은 한 장짜리 페이지(`page`)이고, 이 파일은 한 장씩 넘기는 발표 덱(`deck`) 규칙이다.
패턴(compare·flow·preview·report·guide·timeline·incident·faq)과 공용 블록이 **무엇을 말할지** 정하고, 출력 형식은 **어떻게 보여 줄지** 정한다.
page와 deck은 Pattern·Block을 공유할 수 있지만, 정보 구조·밀도·구도는 출력 형식에 맞게 다시 구성한다(예: evidence는 `evidence` 슬라이드, closing은 마지막 장, explanation은 발표자의 말).
덱은 스토리라인이 하나여야 하므로 스토리라인을 이끄는 주 패턴 하나를 고르고, 그 패턴 파일의 독자 질문과 "덱으로 낼 때" 스토리라인을 따른다.
page처럼 다른 패턴의 내용도 섞는다. 루트 `data-pattern`은 주 패턴의 이름표일 뿐이고, 다른 패턴의 질문은 장 단위로 넣는다(그 패턴 "덱으로 낼 때" 표의 장 하나를 빌려 스토리라인 순서에 끼운다). 레시피로 짠 덱이면 레시피의 덱 메모를 함께 본다.

마크업·CSS·JS(16:9 한 장 보기, 네비, 키보드, 인쇄, 좁은 화면)와 크기 게이트의 정본은 [slide-deck](../blocks/slide-deck.md)다.
구도·강조 3단계·밀도 리듬은 [composition](../composition.md)이 정본이다. 이 파일은 덱의 구성과 의미 검사를 정한다.

## 언제 deck인가

- 요청 신호: "발표 자료", "슬라이드로", "장표", "덱 만들어줘", "화면 공유용", "한 장씩 넘기며", "보고 발표", "제안 발표", "기술 발표", "쉽게 보는 발표 슬라이드".
- 발표·화면 공유처럼 한 장씩 넘기는 슬라이드가 필요하면 deck, 한 장짜리 문서면 page다. 신호가 없으면 page다.
- 혼자 읽히는 게 주목적이면 page를 쓴다. 발표자 없이 전달될 덱이면 필요한 맥락과 출처를 덱 안에 남긴다(별도 모드 아님).
- 출력 형식은 패턴 선택을 바꾸지 않는다. 옵션을 고르는 발표는 compare deck, 흐름을 설명하는 발표는 flow deck이다.

## 독자가 다 보고 답할 수 있어야 할 질문 (덱 공통)

주 패턴의 독자 질문에 아래를 더한다.

- 첫 장만 봐도 결론과 결정할 것을 아는가?
- 슬라이드 제목만 이어 읽어도 하나의 이야기(주장 → 근거 → 할 일)가 되는가?
- 각 주장의 근거는 무엇이고, 그 근거에서 무엇을 읽어야 하는가?
- 그래서 누가 언제까지 무엇을 하는가?

## 루트 마크업

```html
<main class="d0-deck" data-pattern="report" data-variant="status">
```

- `data-pattern`은 필수이고 패턴 8개 중 하나(덱의 주 패턴)다. 다른 패턴의 장이 섞여도 주 패턴 하나만 단다(장에는 패턴 이름표를 달지 않는다). 레시피로 짠 덱이면 `data-recipe`를 더한다(선택).
- `data-variant`는 그 패턴의 기존 변형 이름표다([patterns.md](../patterns.md#이름표) 이름표 목록). 변형이 없는 패턴이면 생략한다.
- 패턴·레시피·변형은 이름표일 뿐 스타일을 바꾸지 않는다. 슬라이드 마크업은 [slide-deck](../blocks/slide-deck.md)을 따른다.

## Audience × Purpose: 독자와 목적부터

**누가 보는가 → 무엇을 이해·판단·결정해야 하는가 → Deck Type → 슬라이드 순서**로 정한다.
주제나 발표 형식만으로 유형을 고르지 않고, 독자에게 필요한 답을 한 문장으로 쓴 뒤 아래 표에 대응한다.

- 내부 팀 기술 발표 × 라이브러리 선택 → Decision → 선택 기준 → 선택지 근거 → 추천 → 결정 요청.
- 경영진 × 분기 현황 공유 → Executive Update → 분기 결론 → 성과 근거 → 리스크 → 다음 행동.

## 밀도 표

발표자가 함께 있다는 전제로 짧은 문장, 큰 그림, 한 장 한 주장으로 보여 주고 남는 설명은 말로 한다.

| 기준 | 값 |
| --- | --- |
| 장당 텍스트(정본) | 몸의 본문(`p`·`li`·`dd`) 합계 렌더 3줄 이내, 불릿 3개 이하. 제목·보조 줄(`__sub`)·쪽수·출처, stat의 큰 숫자·기준 줄(`.d0-slide__stat`·`.d0-slide__base`)과 그림 해석 줄(`figcaption.d0-slide__note`, 따로 1줄 이하)은 세지 않는다. evidence 근거 변형(`.d0-mlist`·`.d0-barlist`·`.d0-tiles`) 안 값·라벨은 그림 라벨이라 세지 않고, 주석 목록 `ol.d0-annot__notes`의 `li`는 불릿으로 센다 |
| 그림 비율(정본, 권장 하한, 1280×800 한 장 모드에서 잰다(슬라이드 폭 730px 미만의 1열 배치는 제외)) | 그린 그림 ÷ 몸 영역: 대칭 장(전체 폭 evidence·breakdown) 65%, screenshot 55%(Impact screenshot 포함), 근거 split·비대칭(`data-layout="asym"`) 45%. 비대칭 장은 종류(evidence·breakdown)와 무관하게 레이아웃 기준 45%를 받는다. 권장 하한이라 미달이 곧 HARD 실패는 아니다. 미달이면 그림이 그 장의 근거인지 보고 열 비율·viewBox·구도를 고친다. 재검토 후 그대로 두면 이유 한 줄을 남긴다(그 장의 HTML 주석 또는 결과 보고) |
| 본문 크기 | 1280×800 한 장 모드에서 20~24px, 좁은 화면 15px(해석 13px, evidence·breakdown·stat 해석은 15px) |
| 근거 밀도(정본) | 빈 공간을 채우려고 더하지 않는다. 제목이 주장하는 근거(비교 기준·분모·관계)만큼은 화면에 둔다. 판정은 Slide Gate [Evidence]이고 빈 면적 % 기준은 두지 않는다. `stat`은 기본형(숫자 + 기준 줄 + 근거 그림, 비대칭)이 기본이고, 순수 Impact stat은 짧은 덱에서 보통 0~1장, 연속 금지(권장). 요약 근거 장은 덱당 1~2장 권장 |

그림 비율은 **그린 그림의 렌더 box ÷ 몸 영역** 하나로, 1280×800 한 장 모드에서 잰다(슬라이드 폭 730px 미만의 1열 배치는 제외).
- 분자 = 실제로 그려진 그림 요소의 box: `figure` 안 `svg`·`img`, screenshot은 `.d0-shot__screen`, evidence 근거 변형은 근거 요소(`.d0-mlist`·`.d0-barlist`·`.d0-tiles`). `figure` box(해석 줄·주석·빈 칸 포함)가 아니다. 그래서 그림을 줄이면 비율도 준다.
- 분모 = 몸 영역 = 슬라이드 안쪽 폭(패딩 제외) × 몸 행 높이(머리·발·행 간격 제외). 그래서 제목 줄 수와 보조 줄(`__sub`)이 하한 판정을 흔들지 않는다.
  비대칭 장은 머리가 몸 행 안에 들어가므로 몸 영역 = 안쪽 폭 × 첫 행 높이다.
- 권장 하한만 둔다(상한 없음). split의 SVG는 그림 열 폭을 채운다(정본: [slide-deck](../blocks/slide-deck.md) 그림 면적).
1280 한 장 모드 실측 참고(제목 한 줄 / 두 줄 / 보조 줄, 측정마다 ±2): evidence 75·74·75%, breakdown 76·75·75%, screenshot 화면 71·64·66%, split 53·53·53%. 그림을 30% 폭으로 줄이면 16~28%로 모두 하한 아래다. 열 비율은 [slide-deck](../blocks/slide-deck.md) 그림 면적이 정본이다.
커버는 대표 도식의 의미 있는 면적을 보고, 그림 예외 장은 비율 검사에서 뺀다.
덱은 표지·제목 목차·섹션 장 포함 5~12장이고 한 번에 한 장씩 본다.

## Deck Type과 패턴

Deck Type은 덱의 쓰임을 부르는 문서용 이름이다. 속성으로 쓰지 않고, 루트에는 패턴·변형을 단다.

| Deck Type | 패턴(변형) | 언제 |
| --- | --- | --- |
| Decision | compare `decision` | 선택지를 놓고 결정을 받는다 |
| Proposal | report `proposal` | 아직 적용 전인 변경·기능을 제안한다 |
| Executive Update | report `status`·`executive` | 진행 상태와 리스크를 위로 보고한다 |
| Explainer | flow, preview | 구조·흐름이나 결과물을 이해시킨다 |
| Demo | preview, guide | 제품이 쓰이는 장면을 보여 준다 |
| Retrospective | incident | 사건을 돌아보고 재발을 막는다 |

장마다의 순서(스토리라인)는 각 패턴 파일의 "덱으로 낼 때" 절이 출발점이다.
순서의 항목 수가 12장을 넘으면 두 항목을 한 장에 묶지 말고 독자 질문에 덜 필요한 항목을 뺀다.

### 폐기된 slides 변형

예전 slides 전용 변형 이름표는 쓰지 않는다. 아래로 옮긴다.

| 예전 | 지금 |
| --- | --- |
| `report`(업무 보고) | `data-pattern="report" data-variant="status"` |
| `proposal`(제안) | `data-pattern="report" data-variant="proposal"`. 제품 소개 제안이면 preview Demo 스토리라인 |
| `strategy`(전략) | 방향을 제안하면 report `proposal`, 선택지 중 하나를 고르면 compare `decision` |
| `tech`(기술 발표) | `data-pattern="flow"`(구조 변경의 전/후 수치가 주인공이면 report `results`) |

## 덱 구성 (5~12장, 표지·제목 목차 포함)

1. **표지 = 결론**(`cover`). h1은 독자가 알아야 할 덱 전체의 결론 문장이다. `비교 발표` 같은 유형·메타 정보는 크게 쓰지 않고 필요하면 작은 eyebrow에만 둔다. 주 패턴 대표 도식을 side·bottom·center·contrast·map 중 알맞은 위치에 둔다. 요약은 도식·리드에 흡수하고 결정할 것만 0~1행으로 남긴다. 메타 행은 제목·그림 해석 줄을 되풀이하지 않고, 다른 정보(필요한 것·결정할 것·입력/결과·다음 단계)가 없으면 뺀다.
2. **제목 목차**(`toc`). 모든 슬라이드 제목을 순서대로 작은 점 불렛으로 나열한 `ul`이고 항목은 그 슬라이드로 가는 링크다. 목차에는 번호와 쪽수를 표시하지 않는다.
   이 목록만 읽고 논리가 이어지지 않으면 슬라이드보다 제목부터 고친다. 목차 장 자신의 제목(`제목만 읽기` 같은 안내)은 결론 제목 규칙의 예외이고, 목차 항목은 각 장 제목을 그대로 옮긴 것이라 한 사실 반복으로 세지 않는다.
   목차는 구도 연속·밀도 리듬 계산에서 뺀다(표지 다음 첫 본 슬라이드부터 센다). 표지는 h1이 결론 문장이어야 하므로 결론 규칙을 따르고 리듬 계산에서는 뺀다.
3. **본 슬라이드.** 한 장 = 주장 하나 = 근거 하나 = 해석 한 줄. 주 패턴 스토리라인 순서를 따른다.
   **섹션 장**(`section`, 선택)은 8장 이상이고 챕터가 2~3개로 뚜렷할 때만 챕터 앞에 한 장씩 둔다. 큰 번호 + 챕터 제목만 있고, 제목은 챕터 이름이나 질문이어도 된다(결론 제목 규칙의 예외).
4. **핵심 수치**(`stat`, 선택). 숫자가 주장인 장이다. 결론 수치(`47%`)와 지켜야 할 규칙 숫자(`3일 전`) 모두 된다. 결론 수치를 두면 page의 히어로 자리를 이 장이 대신한다. 숫자 하나에 한 장이고, 같은 숫자를 다른 장에서 크게 되풀이하지 않는다.
   기본형은 숫자 + 그 숫자를 읽게 하는 근거 그림 하나다(왼쪽 큰 숫자와 작은 기준 줄, 오른쪽 근거 그림, 아래 출처 줄). 숫자만 남기는 순수 Impact stat은 숫자 자체가 결론일 때만 쓴다. 아래 [stat과 Impact](#stat과-impact).
5. **마지막 장**(`closing`). 큰 마무리 한 문장을 세로 중앙에 둔다. 구분선 아래 작은 `dl` 메타 2~3칸에 이미 나온 사실만 적는다(앞 장을 가리키는 자리라 같은 숫자 반복 셈에서 뺀다. 숫자 대신 담당·행동어로 쓸 수 있으면 그쪽이 낫다). 스토리라인에서는 `Closing:decision`처럼 `종류:세부`로 적는다.

## 슬라이드 종류 (`data-kind`)

| `data-kind` | 무엇 | 그림 | 대응 블록 |
| --- | --- | --- | --- |
| (생략) 근거 | 결론 제목 + 그림 + 요점 2~3개 나란히(split) | 필수 | [diagram](../blocks/diagram.md) |
| `cover` | 결론 h1 + 대표 도식 + 요약 0~1행 | 대표 도식 | [header](../blocks/header.md) 요약 행 |
| `toc` | 제목 목차(`nav.d0-slide`) | 예외 | — |
| `assertion` | 주장 한 문장만 | 예외 | Impact 기본 |
| `evidence` | 결론 제목 + 차트 + 해석 한 줄 | 차트 | diagram 막대·비율, [kpi-cards](../blocks/kpi-cards.md) 막대 변형 |
| `screenshot` | 실제 화면 + dim + spotlight + 짧은 주석 | 화면 | [mockup-frame](../blocks/mockup-frame.md)의 `figure.d0-shot` |
| `breakdown` | 전체 → 구성 요소 | 도식 | diagram 연결 그래프·와이어프레임 |
| `stat` | 기본형: 큰 숫자 + 기준 줄 + 근거 그림 하나 + 출처(비대칭). 순수 Impact stat: 숫자 하나 + 뜻 한 줄 | 기본형은 근거 그림 필수, 순수 Impact stat은 큰 숫자가 그림 | [hero](../blocks/hero.md)의 수치 해부, [slide-deck](../blocks/slide-deck.md) 핵심 수치 |
| `summary` | 참고용 정리 목록 3행 이내 | 예외 | [checklist](../blocks/checklist.md) |
| `closing` | 큰 마무리 한 문장 + 구분선 + 작은 `dl` 메타 행. `data-closing`: decision·request·action·criteria·takeaway | 예외 | [slide-deck](../blocks/slide-deck.md) 마지막 장 |

그림 예외는 `toc`·`summary`·`closing`·`assertion`뿐이다. 커버에는 대표 도식을 둔다.

### 마지막 장 `closing`

공용 [closing](../blocks/closing.md) 블록의 덱 형태다. 종류·메타 라벨 정의는 closing.md와 같다.

| `data-closing` | 주 패턴 기본 | 마지막 장이 하는 일 |
| --- | --- | --- |
| `decision` | compare, report, timeline | 결정을 받는다 |
| `request` | (도움·승인을 구하는 덱) | 요청을 받는다 |
| `action` | preview, flow, faq | 독자가 해 볼 행동을 정한다 |
| `criteria` | guide | 끝났는지 볼 기준을 남긴다 |
| `takeaway` | incident | 다시 지킬 것을 남긴다 |

기본은 출발점이고 덱의 목적이 다르면 바꾼다. 모두 구도는 같다.

### 새 종류 다섯

- **assertion.** 앞뒤 근거를 잇는 주장 한 문장만 크게 둔다. 그림·불릿·카드가 없고 기본이 Impact 면이다. 덱의 전환점(문제 제기, 추천, 결론)에 쓴다.
- **evidence.** 제목이 결론 문장이고, 그 결론을 증명하는 차트 하나와 "그래서 무엇을 뜻하나" 한 줄이 붙는다. 강조할 계열 하나만 blue다. 표보다 그래프가 나은 정보는 여기서 그래프로 그린다.
- **screenshot.** 실제 화면(목업 또는 이미지)을 크게 두고, 봐야 할 곳만 spotlight로 남긴 뒤 나머지를 흐린 막으로 덮는다. 주석은 번호를 맞춘 짧은 한 줄이다. 마크업은 mockup-frame의 `.d0-shot`(`.d0-shot__spot`, `.d0-shot__note`)이다.
- **breakdown.** 전체 모양을 먼저 그리고 그것을 이루는 부품 2~5개로 나눈다. 부품마다 이름 한 마디, 지금 이야기하는 부품만 blue다.
- **section.** 챕터를 넘길 때 숨을 고르는 장이다. 큰 번호(`02`) + 챕터 제목만 두고, 진한 면을 쓸 수 있다. 목차에도 항목으로 들어가고 구도·밀도 리듬 계산에서는 뺀다.

### stat과 Impact

- **Impact**는 일부러 비워 두고 한 주장·숫자를 강하게 보여 주는 장이다. **stat**은 숫자가 주장인 장이고, 기본은 숫자 + 그 숫자를 읽게 하는 근거 그림 하나다. 둘을 같은 것으로 보지 않는다.
- **기본형.** 숫자는 왼쪽 큰 글자, 바로 아래 작은 기준 줄(`출시 전 18%에서`), 근거 그림은 오른쪽(비대칭 격자), 아래 출처 줄이다. 흰 면이고 Impact로 세지 않는다. 마크업·CSS는 [slide-deck](../blocks/slide-deck.md) 핵심 수치 절이 정본이다.
- **순수 Impact stat.** 숫자 자체가 결론일 때만 숫자만 남긴다. 짧은 덱에서 보통 0~1장이고 두 장을 잇달아 두지 않는다(권장, HARD 아님). 그때도 비교 기준이 있으면 숫자 옆 작은 글자로 둔다.
  패턴 파일 스토리라인의 `Impact:` 줄은 Impact로 둘 장만 적고, 거기 나온 `stat`은 숫자 자체가 결론일 때의 순수 Impact stat이다. 제목이 변화·비교를 주장하면 기본형으로 두고, Impact 비율은 `assertion` 등 다른 장으로 맞춘다.
- **근거 그림 고르는 순서.** 위에서부터 내용에 맞는 첫 번째다. 기존 차트 CSS와 근거 변형을 쓰고 새 블록을 만들지 않는다.
  1. 같은 기준·0에서 시작하는 전/후 막대: 값이 전/후 두 개뿐이고 크기 차이를 읽어야 할 때. 보조값 `18% → 5% · −13%p` 허용.
  2. slope·dumbbell: 변화 방향 자체가 핵심일 때.
  3. line·sparkline: 실제 시계열 값이 3개 이상일 때만(두 점으로 추세선을 긋지 않는다).
  4. 100% 막대·점 격자: "전체 중 몇 %"라는 구성비 자체가 핵심일 때.
  5. `metric-list`: 서로 관련된 숫자가 여러 개일 때.
- **값.** 근거 그림·출처 줄의 값은 덱의 근거 자료(같은 주제 page 등)에 있는 사실만 쓴다. 없는 기간·출처를 지어내지 않고, 출처가 없으면 출처 줄을 뺀다.

### 요약 근거 장(evidence overview)

숫자 보고·성과 요약처럼 동시에 봐야 가치가 있는 정보에만 쓴다. 새 종류가 아니라 `evidence` 장 + `metric-list` 변형이다.

- **구성.** 결론 제목 → 주인공 차트 하나(`svg.d0-mlist__chart`) + 지표 목록 2~4행(같은 기간·같은 맥락, 단위는 행마다 적는다) → 짧은 해석 한 줄 → 출처.
- **가드레일.** 한 장은 주장 하나, 시각적 주인공 하나이고 나머지는 보조다. 카드로 감싸지 않아도 구분되면 카드를 쓰지 않는다. 작은 글자로 밀도를 높이지 않는다(밀도 표의 본문 크기·덱 글자 하한 유지). 대시보드처럼 카드·pill을 늘어놓지 않는다. 덱당 1~2장 권장.

## 강조·색·면적

- **강조 순서.** 크기 → 위치 → 여백 → 무게 → 색. 색은 마지막 수단이다. 세부는 [composition](../composition.md).
- **Impact**(`data-emphasis="impact"`). 슬라이드 전체 면을 `var(--d0-blue-light)`로 채우고 글자는 grey-900, 강조 숫자는 blue-dark다.
  안에는 문장 하나, 숫자 하나, 그림 하나 중 하나만 둔다. 카드 금지. Impact 면을 어둡게 칠하지 않는다.
  Impact는 글자 크기가 아니라 한 주장에 시선을 모으는 장이다. 면 안의 하나(문장·숫자·그림)가 장면의 주인공일 때 성립하고, 요점·카드·두 번째 그림이 섞이면 blue-light 면이어도 Impact로 세지 않는다.
  제목 크기는 그 하나에 따른다. 그림 없는 순수 Impact(`assertion`)만 제목이 약 66px(6cqi)이고, 그림·숫자가 있는 Impact(screenshot·evidence·breakdown·근거·순수 Impact `stat`)는 일반 장 제목 크기(약 39px)다. `stat` 기본형은 Impact가 아니고 asym 제목이다. 비대칭(`data-layout="asym"`) 장은 Impact여도 asym 제목(약 35px)이다. 그림 비율 권장 하한은 Impact라고 따로 낮추지 않는다.
  덱의 Impact 슬라이드는 전체의 20~30%다(8장이면 2장, 12장이면 3장). `quiet`는 받쳐 주는 장에 쓴다.
- **진한 면**(`data-surface="dark"`). 표지·섹션·마무리 장에만, 덱당 1~3장 쓰는 blue-dark 풀블리드 면 + 흰 큰 글자다. 진한 면은 내용을 담는 기본 배경이 아니라 장면을 전환할 때만 쓴다. Impact로 세지 않고 Impact 비율에도 들지 않으며, 색 면적 경고 비율에서도 뺀다(장면 수로 관리). 대비와 CSS는 [slide-deck](../blocks/slide-deck.md) 진한 면 절(#fff 5.50, blue-light 4.94).
- **색 면적은 lint Warning.** 첫 화면 진한 포인트 채움 <1%는 "강조가 너무 약한지 확인", 1~15%는 정상, >15%는 "포인트 색이 배경처럼 쓰이는지 확인"이다. 게이트를 맞추려고 색 면적을 늘리지 않는다. 옅은 면은 경고 비율에서 빼며 Impact 장수는 따로 판정한다. 대비·WCAG 2.2 AA·의미색 글자 금지는 Hard로 유지한다. 정본은 [shell.md](../blocks/shell.md) 색 절이다.
- **그림 면적.** 커버는 대표 도식이 의미 있는 면적을 쓰는지 확인한다. 근거·evidence·breakdown·screenshot 장의 그림 비율(그린 그림 ÷ 몸 영역 하한)은 밀도 표(정본)를 따른다. 기본 배치는 그림 + 요점 split이고,
  그림만 전체 폭이면 무대 좌우가 비지 않을 때(가로로 긴 도식)만 쓴다.
- **구도.** 같은 구도를 연속으로 두지 않고 밀도를 저 → 중 → 고 → 저로 엇갈린다([composition](../composition.md)).

## 덱의 리듬과 박자

레퍼런스 덱에서 가져올 것은 장식이 아니라 **장마다 실루엣은 다른데 같은 덱으로 보이는 것**과 **덱 전체의 박자**다. 아래 숫자는 권장이고 게이트가 아니다. 판정은 Slide Gate의 의미 검사로 한다.

- **같은 덱으로 보이게.** 제목 문법(작은 머리 줄 → 결론 제목, 결론어 하나만 굵게)과 크롬(섹션 태그·쪽번호·출처 푸터)의 자리를 모든 장에서 같게 둔다. 크롬은 장마다 2개 이하가 기본이다.
- **실루엣은 다르게.** 이웃한 장의 구도를 바꾼다(split → evidence 전체 폭 → 비대칭 → stat). 비대칭은 그림이 핵심인 장에만, 덱에 1~3장 권장.
- **박자.** 표지 → 목차 → [섹션 → 본 장 2~4장]… → 마무리. 진한 면은 1~3장, Impact는 20~30%로 두고 둘이 연달아 오지 않게 한다.
  표지는 진한 면의 기본 후보다. 마무리(closing)는 바로 앞 장이 Impact가 아닐 때만 진한 면으로 두고, 앞 장이 Impact면 흰 면으로 둔다. 섹션 장은 진하게 하면 그 덱의 섹션 장을 모두 같게 둔다.
- **한 장에 하나.** 진한 면, 비대칭, 주석, 큰 숫자, 근거 변형 같은 특징을 한 장에 몰아넣지 않는다. `stat` 기본형의 큰 숫자 + 비대칭 + 근거 그림은 한 벌의 구도라 하나로 세고, 여기에 주석·진한 면을 더하지 않는다.
- **제목 강조.** 제목마다 강조 구간 1개, blue 1개까지다. blue는 그림의 강조와 같은 뜻일 때만 쓴다.

## 대표 도식

슬라이드마다 그 주장의 근거 하나다. 전/후는 막대 두 개, 구조는 연결 그래프, 순서는 단계 도식, 화면은 `screenshot` 또는 와이어프레임이다.

- 데이터는 근거다. 차트 위에 결론 문장이 있고 강조할 계열 하나만 blue, 나머지는 grey다.
- 축 눈금·범례·격자선은 읽는 데 필요한 것만 남긴다. 값 라벨을 막대 끝에 달면 범례와 눈금을 지운다.
- 선 거의 없이 숫자·문구·객체 하나를 크게 보이는 장면은 diagram editorial 장르(`data-genre="editorial"`)를 쓴다.

## 문장 규칙

- **결론 제목.** 제목은 주제명이 아니라 결론 문장이다. `-다`체 서술어(`-다`, `-했다`, `-한다`)로 끝난다. 덱 제목·본문·해석은 `-다`체로 통일하고, 마지막 장 요청 문장만 독자에게 직접 부탁하는 `-주세요`를 쓸 수 있다(SKILL.md 말투).
  표지·목차의 예외: 표지 h1은 결론 문장이고, 목차 장의 제목은 안내 문구라 이 규칙에서 뺀다.
  `시장 규모` ✕ → `혼자 쓰는 팀이 이미 절반을 넘었다` ○. `현황`, `개요`, `분석 결과`, `Q&A` 같은 명사 제목은 실패다.
- 제목은 한두 줄(약 40자 이내)이다. 제목이 길면 보조 한 줄(`__sub`)로 나눌 수 있다(그림 비율은 몸 영역 기준이라 영향 없음). 보조 한 줄은 제목을 되풀이하지 않고 범위·조건을 더한다(`지난 8주, 팀 A 기준`).
- 본문은 슬라이드당 3줄, 불릿 3개까지다. 남는 말은 발표자가 말로 한다.
- 숫자에는 해석을 붙인다. 해석 줄은 "그래서 무엇을 뜻하나" 한 문장, 출처 줄은 원자료(page·사용자 자료)에 있는 출처만 `출처: …` 한 줄로 짧게 쓰고, 출처가 없으면 줄을 생략한다(지어내지 않는다).
- 용어는 처음 나오는 슬라이드에서 괄호 속 짧은 비유로 푼다.

## page 원칙 중 덱에서 바뀌는 것

원칙 4번 섹션 규칙, 원칙 2·3번 첫 화면 규칙, 원칙 6번 explanation 설명, Page Depth Gate, 원칙 9번 히어로·h1 32/h2 20 고정 타이포·섹션 사이 64px,
본문 축·폭 단계·2열·줄 길이 규칙, 720px 프레임, page 도식 라벨 렌더 13~20px 게이트 대신 이 파일의 구성과 Slide Gate, [slide-deck](../blocks/slide-deck.md)의 덱 규칙·덱 게이트를 따른다.
결론 수치는 히어로 대신 `stat` 슬라이드에 둔다. 나머지(글은 적게, 한 사실은 한 번(제목 목차·closing 메타 반복은 빼고 센다), 시맨틱, 토큰, 색, 접근성)는 그대로다.

## Slide Gate (의미 검사 우선)

Audience × Purpose와 Story부터 통과한다. 마크업·크기 검사보다 먼저 보고, 하나라도 걸리면 덱 구성부터 고친다.

### [Story]

- [ ] 누가 보는 덱인지 독자가 명확하다
- [ ] 독자가 무엇을 이해·판단하고 어떤 결정을 내리거나 행동해야 하는지 명확하다
- [ ] 제목만 이어 읽어도 논리가 이어진다(제목 목차를 소리 내어 읽어 본다. 섹션 장 제목은 이어 읽기의 구분점으로 본다)

### [Slide]

- [ ] 한 장에 핵심 주장이 하나다
- [ ] 제목이 주제명이 아니라 결론이다: `매출 현황` ✕ → `재구매 고객이 매출 성장을 이끌었다` ○; `장애 원인` ✕ → `타임아웃 설정 변경이 장애를 일으켰다` ○; `안 A vs 안 B` ✕ → `안 B가 운영 복잡성을 줄인다` ○
- [ ] 본문·차트·도식이 제목의 결론을 증명한다
- [ ] 앞 장이 다음 장을 필요하게 만든다(빼도 이야기가 안 끊기는 장은 뺀다)
- [ ] 표지·목차 포함 5~12장이고 장당 텍스트와 본문 크기는 밀도 표를 지킨다

### [Visual]

- [ ] 그림은 근거이고 장식이 아니다. 텍스트를 가려도 구조가 보이며 정보 없는 도형·아이콘이 없다
- [ ] 숫자마다 단위·기간·맥락·출처와 그 숫자의 해석이 있다
- [ ] 차트에서 읽어야 할 결론이 보인다. 추세·크기 비교·비율처럼 그래프가 나은 정보를 표로 두지 않았다
- [ ] 상태·범주는 색만으로 구분하지 않고 모양과 라벨도 함께 쓴다
- [ ] 화면 캡처에는 봐야 할 위치가 표시되어 있다(`screenshot`의 spotlight·번호 주석)
- [ ] 커버는 독자가 알아야 할 결론 문장과 주제의 실체를 보이는 대표 도식이다. 유형·메타 정보는 작은 eyebrow에만 있고, 도식 위치·비율은 주 패턴에 맞으며 요약은 0~1행이고 제목·해석 줄을 되풀이하지 않는다(마무리 메타도 제목의 기한·대상을 되풀이하지 않는다)
- [ ] 그림 비율(그린 그림 ÷ 몸 영역, 1280×800 한 장 모드에서 잰다(슬라이드 폭 730px 미만의 1열 배치는 제외))이 밀도 표(정본)의 권장 하한 이상이다(미달이면 근거·구도부터 다시 보고, 그대로 두면 이유 한 줄을 HTML 주석이나 결과 보고에 남긴다). 좁은 그림 하나만 전체 폭에 두어 좌우를 비우지 않는다
- [ ] 진한 면은 장면을 바꾸는 표지·섹션·마무리에만 있고 내용을 담는 장의 배경으로 쓰지 않았다. 마무리가 진한 면이면 바로 앞 장이 Impact가 아니다. 섹션 장은 챕터가 실제로 나뉠 때만 있다
- [ ] 비대칭·주석·근거 변형·converge는 그 장의 내용이 그 모양일 때만 썼다(converge는 문제들이 실제로 한 곳에 닿는다, tiles는 같은 단위·성격이다). 한 장에 특징을 몰아넣지 않았다(`stat` 기본형의 숫자 + 비대칭 + 근거 그림은 한 벌로 센다)
- [ ] Impact 슬라이드가 전체의 20~30%이고, 각 Impact 면 안에 문장·숫자·그림 중 하나만 있으며, 그 하나가 주인공이다(순수 Impact만 큰 제목, 그림·숫자가 있는 Impact는 제목 일반 크기). 구도는 연속 반복하지 않고 밀도 리듬을 둔다

### [Evidence] 근거 밀도

빈 면적 % 기준은 두지 않는다. 제목이 무엇을 주장하는지에서 출발해 필요한 근거가 화면에 있는지 본다.

- [ ] 제목이 변화·비교·추이·차이를 주장하면 비교 기준이 화면에 보인다(해석 줄 속 작은 글자에만 숨기지 않는다)
- [ ] 제목이 비율을 주장하면 분모·비교 기준이 필요한지 확인했다
- [ ] 제목이 원인·효과를 주장하면 그 관계를 뒷받침하는 근거가 있다
- [ ] 숫자 하나만 있을 때 기준·기간·출처 중 필요한 맥락이 있다
- [ ] 인접한 두 장이 같은 주장을 나눠 보여 줄 뿐이면 한 장으로 합칠지 검토했다
- [ ] `stat`은 기본형(숫자 + 기준 줄 + 근거 그림)이 기본이고, 순수 Impact stat은 숫자 자체가 결론인 장에만 있다(권장: 짧은 덱 0~1장, 연속 금지). 근거 그림은 고르는 순서(전/후 막대 → slope → line(값 3개 이상) → 100% 막대·점 격자 → metric-list)를 따랐다
- [ ] 요약 근거 장은 주인공 차트 하나 + 지표 2~4행 + 해석 + 출처이고, 카드·pill을 늘어놓거나 글자를 하한 아래로 줄이지 않았다(덱당 1~2장 권장)
- [ ] 약한 경고: Impact·표지·섹션·마무리가 아닌 장에 큰 빈 영역이 있으면 빠진 근거가 있는지 먼저 본다(빈칸을 채우려고 그림을 더하지 않는다)

### [Ending]

- [ ] 마지막 장이 `data-kind="closing"`이고 `data-closing`(decision·request·action·criteria·takeaway)이 덱의 목적과 맞다. 요청한 결정·행동·기준을 명확히 하는 전용 구도다. 큰 요청·결정 한 문장 + 구분선 + 작은 `dl` 메타 2~3칸이며, 메타는 덱에 나온 담당·기한·다음 행동만 쓴다. 같은 무게의 불릿 목록이나 Impact를 두지 않는다

## 안티패턴

- 명사 제목만 있는 덱(`배경`, `현황`, `결론`). 제목 목차를 읽어도 이야기가 안 된다.
- 한 슬라이드에 문제·기능·장점·화면·성과·일정을 전부 넣기.
- 문서를 붙인 덱: 여러 줄 문단을 넣거나 불릿 4개 이상·표 전체를 붙여 넣기.
- 의미 없는 아이콘·도형·그라디언트·3D·사람 일러스트, 모든 계열을 다른 색으로 칠한 차트.
- 그래프만 있고 결론 문장이 없음, 결론과 그래프가 다른 말을 함.
- 좁은 그림 하나만 전체 폭 무대에 올려 좌우가 빈 근거 슬라이드.
- 표지가 제목·날짜뿐이라 첫 장만 보고는 결정할 것을 모름.
- 모든 장이 Impact이거나 Impact가 하나도 없는 덱, 본문 장·Impact의 어두운 배경(진한 면은 표지·섹션·마무리만, 덱당 1~3장).
- 장식용 초대형 숫자·연도를 기본 요소로 쓰기(숫자가 주장 자체일 때만 `stat`).
- 비교를 주장하는 제목 아래 숫자 하나만 크게 두고 비교 기준을 작은 해석 줄에 숨기기(`stat` 기본형으로 기준 줄과 근거 그림을 둔다). 두 점으로 그은 추세선.
- 요약 장을 대시보드처럼 꾸미기: 카드·pill 나열, 주인공 없는 차트 여럿, 하한 아래 작은 글자.
- 큰 원 안에 숫자를 넣어 원 크기로 값 비교하기(정확도가 낮고 템플릿 냄새가 난다. 막대·bar-list로).
- 그라디언트·글래스·사진 배경·3D·두꺼운 그림자(진한 면에서도 금지).
- 로고·회사명·브랜드 표식을 크롬이나 표지에 두기.
- 모든 장을 좌우 번갈아 비대칭으로 놓기, 크롬 셋을 매 장 강제하기, 한 장에 진한 면·비대칭·주석·큰 숫자 몰아넣기(`stat` 기본형의 숫자 + 비대칭 + 근거 그림 한 벌은 예외).
- 슬라이드 13장 이상(나누거나 독자 질문에 덜 필요한 장을 뺀다).
