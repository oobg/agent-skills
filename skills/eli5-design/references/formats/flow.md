# flow — 절차·구조 설명

## 독자가 다 읽고 답할 수 있어야 할 질문

- 처음부터 끝까지 어떻게 흘러가는가?
- 각 단계에서 누가 무엇을 하고, 무엇이 나오는가?
- 지금 어느 단계에 있는가(해당할 때)?
- (구조 설명이면) 어떤 부품이 있고 서로 어떻게 연결되는가?

## 요청 신호

"어떻게 돌아가", "흐름 설명", "프로세스", "구조 그려줘", "아키텍처 쉽게", "개념 설명".

## 권장 구성 예시 (예시일 뿐, 순서를 강제하지 않는다)

header → flow-line(전체 흐름 한 줄) → step-columns(단계 3~5) → 필요하면 diagram → callout(한 줄 요약).

diagram은 두 가지 중 하나를 고른다.

| 형 | 보여 주는 것 | 예 |
| --- | --- | --- |
| 흐름형 | 시간 순서 | 요청 → 확인 → 처리 → 알림 |
| 레이어형 | 구성요소 관계 | 화면 / 서버 / 저장소 세 층 |

개념·구조 설명 요청도 이 프리셋에서 다룬다. 용어가 많으면 faq의 용어 카드만 빌려 온다.

합성 예: "주문 내보내기가 파일로 만들어지기까지", "팀 A의 검토 요청 흐름".

## 프리셋 안티패턴

- 6단계 이상(원칙 상한 5, 넘으면 큰 단계로 묶고 하위 페이지로 나눈다).
- 정보 없는 장식 그림.
- 추상 3D·홀로그램·네온 비주얼.
- 단계 이름만 있고 단계마다 "누가·무엇이 나오나"가 없음.

## 경계

- 날짜가 붙으면 timeline, 순서만 있으면 flow.
- 독자가 직접 따라 하며 체크해야 하면 guide, 이해만 하면 flow.
