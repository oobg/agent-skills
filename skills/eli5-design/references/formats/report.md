# report — 보고서

보고서는 한 일의 기록이 아니다. 읽는 사람이 지금 상황을 이해하고 판단하거나 움직이게 만드는 문서다.
순서는 항상 **결론·현재 상태 → 근거 → 문제·위험 → 다음 행동**이다.

## 독자가 다 읽고 답할 수 있어야 할 질문

- 지금 상태는 어떤가(정상·위험·차단·완료)?
- 무엇이 달라졌나(한 일이 아니라 달라진 결과, 가능하면 숫자)?
- 무엇이 막히거나 위험한가, 그래서 어떻게 하나(영향과 대응)?
- 누가 다음에 무엇을, 언제 또는 무엇 뒤에 하나?

## 요청 신호

"보고서", "상태 보고", "진행 상황", "주간 리포트", "결과 정리", "분석 결과 쉽게", "지표 요약", "윗선 보고용 요약".
아직 적용 전인 변경 제안·설명("이렇게 바꾸려 해요", "개편안 설명")도 report로 만든다(아래 변형 표의 제안).

## 변형

| 변형 | 언제 | 무게 중심 |
| --- | --- | --- |
| 상태 보고(기본) `status` | 진행 중인 일의 주간·프로젝트 보고 | 상태 배지 + 달라진 것 + 위험 + 다음 단계 |
| 결과·지표 보고 `results` | 측정이 끝난 실험·개선의 결과(예: 버전별 실측 비교) | 히어로 수치 + 전/후 도식 + 어떻게 했나 |
| 상위 보고 요약 `executive` | 의사결정자에게 올리는 짧은 요약 | 결론·영향 먼저, 목적·배경은 한 줄로 압축 |
| 제안(적용 전) `proposal` | 아직 적용하지 않은 변경 설명 | 예상치 + 결정 필요 |

## 대표 도식

전/후 막대(diagram bars), kpi-cards 막대 변형, 원인·범위가 핵심이면 연결 그래프(diagram graph).
수치 비교가 없는 상태 보고는 **완료 범위 비율 막대**(diagram `data-variant="ratio"`, 예: 전체 12건 중 9건 완료)나
**일정 시간 막대**(timeline `data-variant="timebar"`)를 첫 섹션 그림으로 쓴다. 상태 보고도 글만으로 만들지 않는다.

## 머리 (header)

[header.md](../blocks/header.md) 요약 행 변형을 쓴다. 위에서부터 이 순서다.

1. **작업 라벨 + 상태 배지 1개.** 라벨 옆 `.d0-pill`에 상태를 글자로 쓴다. 상태를 문장 속에 숨기지 않는다.

   | 상태 | 배지 글자 | `data-tone` |
   | --- | --- | --- |
   | 계획대로 진행 | `정상` | `green` |
   | 일정·범위가 흔들릴 수 있음 | `위험` | `orange` |
   | 외부 요인으로 멈춤 | `차단` | `red` |
   | 끝남 | `완료` | `green` |

   배지 글자는 grey-900이고 의미색은 배경·점에만 쓴다([shell.md](../blocks/shell.md) 배지 절). 제안 변형은 상태가 아직 없으므로 배지를 생략한다.
   **배지는 가장 나쁜 위험 행보다 좋을 수 없다.** 차단 행이 있으면 배지는 `위험` 또는 `차단`이고 `정상`·`완료`는 쓰지 않는다.
   이렇게 하면 상태 배지와 위험 행을 합쳐도 의미색이 2가지를 넘지 않는다(정상+위험 행 = green·orange, 위험·차단 = orange·red).
   다음 단계 체크리스트의 완료 green은 체크해야 나타나는 상호작용 표식이라 이 셈에 넣지 않는다.
2. **h1 = 결론 한 문장.** 지금 상태나 달라진 결과를 말한다(`검색 누락 오류 14건이 모두 정상 처리돼요`). 작업명(`검색 API 수정`)을 제목으로 쓰지 않는다.
3. **히어로(수치가 있을 때).** h1 바로 아래 [hero](../blocks/hero.md) 1개. 예상치면 뜻 줄에 글자 라벨 `(예상치)`.
4. **요약 행 3행 이하.** 라벨·h1·요약 행 첫 줄만 읽어도 현재 상황을 알아야 한다(첫 3줄 규칙).
   - 행 라벨 기본값(스킬이 문구를 정할 때만): 상태 보고 `지금 / 달라진 점 / 결정 필요`, 결과·지표 보고 `이전 / 현재 / 결정 필요`,
     상위 보고 요약 `목적 / 영향 / 결정 필요`, 제안 `지금 / 바꾸면 / 결정 필요`. 사용자가 행 문구를 직접 주면 라벨까지 그대로 쓴다.
   - 결정이 아니라 도움이 필요하면 내용에 요청을 쓰고 라벨은 `결정 필요` 그대로 둔다(SKILL 게이트가 이 라벨로 callout 중복을 잡는다).
     필요한 것이 없으면 세 번째 행을 빼고 2행으로 둔다. `없음` 행을 만들지 않는다.
   - 값은 데스크톱 한 줄(약 35자 이내). 결정이 둘이면 `결정 필요` 칸에 짧은 `ol`(최대 2개), 셋 이상이면 가장 중요한 1개만 두고 나머지는 다음 단계로 보낸다.
     문구가 고정이거나 결정자·시점이 다른 두 번째 결정은 요약 행 아래 보조 줄 한 줄 + 다음 단계 행으로 둔다([header.md](../blocks/header.md)).

## 권장 구성 (섹션 2~4개, 앞쪽 핵심 섹션은 그림 필수)

권장 구성은 출발점이다. 독자 질문에 필요한 섹션만 만들고, 아래를 전부 채우지 않는다.

header → ① 달라진 것 → ② 진행 중·일정(있을 때) → ③ 이슈·위험 → ④ 다음 단계.

- **① 달라진 것(완료).** 한 일이 아니라 달라진 결과를 보여 준다. 전/후 막대, kpi-cards 막대 변형, 완료 범위 비율 막대 중 하나. 그림 필수.
  섹션 제목도 결과로 쓴다(`어디서 줄었나`, `무엇이 이제 되나`).
- **② 진행 중·일정.** 마일스톤이나 기한이 있을 때만 둔다. timeline 시간 막대(`data-variant="timebar"`)로 끝난 구간·지금·남은 구간을 그린다.
  결과·지표 보고에서는 이 자리에 **어떻게 했나**(연결 그래프 또는 와이어프레임)를 둔다.
- **③ 이슈·위험.** [diff-rows](../blocks/diff-rows.md)의 위험 행 변형(`data-variant="risk"`): 배지(`위험`/`차단`) + 위험 한 문장 + `영향` / `대응`.
  3행 이내, 그림 없음. 위험은 발견한 보고에서 바로 올린다. 다음 보고로 미루지 않는다. 위험이 없으면 섹션을 만들지 않는다.
  한계·참고처럼 대응이 필요 없는 항목만 있으면 기존 배지 행 변형을 쓴다.
- **④ 다음 단계.** [checklist](../blocks/checklist.md) 담당 변형(`data-variant="owner"`). 행마다 주체(`.d0-check__owner`)를 두고,
  기한 날짜나 시작 조건(`.d0-check__when`, 예: `백엔드 배포 확인 뒤`) 중 하나를 붙인다. 그림 없음.
  report에서는 `data-meta="none"` 행을 두지 않는다. 담당이 아직 없으면 담당을 정할 사람을 주체로 하고 할 일을 `담당 정하기`로 쓴다.
- **대응과 다음 단계는 한 번만.** 위험 행 `대응`에는 주체 + 짧은 구만 쓰고, 언제까지 무엇을 하는지는 ④의 행 하나가 정본이다.
  같은 문장을 두 곳에 쓰지 않는다.
- **나란히.** ①과 ②는 데스크톱에서 [shell.md](../blocks/shell.md)의 `.d0-split`으로 나란히 둘 수 있다. 내용이 먼저다.
  한쪽 높이가 다른 쪽의 1.5배를 넘으면 위아래로 쌓는다. 레이아웃 균형을 위해 내용을 다른 섹션으로 옮기지 않는다.

### 상위 보고 요약의 압축

목적 → 배경 → 접근 → 핵심 결과 → 영향 → 다음 단계를 섹션 순서로 옮겨 적지 않는다. 결론이 먼저다.

| 내용 | 놓는 곳 |
| --- | --- |
| 핵심 결과 | h1 한 문장 + 히어로 수치 |
| 목적 · 영향 | 요약 행 `목적` · `영향` 각 한 줄 |
| 결과 근거 | ① 섹션 그림 |
| 배경 · 접근 | ② 섹션 하나(배경은 섹션 설명 한 줄, 접근은 연결 그래프) |
| 위험(있을 때) | ③ 위험 행 |
| 다음 단계 | ④ checklist 담당 변형 |

### 공통 수치 규칙

- **한 사실은 한 번.** 결론 수치는 히어로에만 크게 둔다. 예: 히어로가 `26분 → 10분`이면 요약 행은 `PR 검사 시간 단축`, 섹션 제목은 `어디서 줄었나`처럼 숫자 없이 쓴다.
- **KPI.** 숫자 + 막대(`전`/`후` 라벨과 값)만. 증감 배지는 달지 않는다([kpi-cards.md](../blocks/kpi-cards.md)).
- **막대 수.** diagram 전/후 막대는 비교 쌍 2개까지. 3쌍 이상이면 kpi-cards 막대 변형을 쓴다([diagram.md](../blocks/diagram.md)).
- **비율 막대 위치.** 비율 막대는 근거 섹션 ① 안에 둔다.
- **예상치.** `예상치` 배지는 정보가 있는 태그라 페이지당 1회 허용한다(수치 섹션 머리나 그림 옆, [section-head.md](../blocks/section-head.md)).
  다른 수치는 글자 라벨 `(예상치)`로 단다. 측정값과 한 그림에 섞지 않는다.
- **결정.** 요약 행 또는 callout 하나로만 말한다.
- 차트마다 "그래서 무엇이 보이는가"를 한 줄 주석으로 단다.

합성 예: "팀 A 주간 상태: 정상 · 처리 대기 건수 감소 · 다음 주 배포는 백엔드 확인 뒤".

## 문장 규칙

- 문단·섹션 설명의 첫 문장이 결론이다. 배경은 뒤에 둔다.
- 한 문장에 한 가지만 말한다.
- "많이·거의·대부분·상당히" 대신 수치를 쓴다(`대부분 처리` → `14건 중 13건 처리`).
- "추후·예정·조만간"만으로 다음 행동을 쓰지 않는다. 주체와 조건을 쓴다
  (`추후 배포 예정` → `프론트엔드 팀이 백엔드 배포 확인 뒤 프로덕션에 배포해요`).
- 문서만 읽어도 설명 없이 이해되게 쓴다. 회의에서 들은 맥락, 내부 약어를 가정하지 않는다.

## report 전용 게이트

SKILL.md 출력 게이트에 더해 확인한다.

**코드로 확인**

- [ ] 제안 변형이 아니면 `.d0-header__meta` 안 `.d0-pill`이 정확히 1개이고, 글자가 `정상`·`위험`·`차단`·`완료` 중 하나, `data-tone`이 위 매핑과 맞는다
- [ ] `ul.d0-rows[data-variant="risk"] > li`마다 `dl` 안에 `dt` `영향`과 `대응`이 있고 각 `dd`가 비어 있지 않다
- [ ] `ul.d0-rows[data-variant="risk"]` 안에 `차단` 배지가 있으면 상태 배지가 `정상`·`완료`가 아니다
- [ ] 다음 단계 `.d0-check[data-variant="owner"] .d0-check__row`마다 비어 있지 않은 `.d0-check__owner`가 있고 `data-meta="none"` 행이 없다
- [ ] 렌더 텍스트에 `추후`·`조만간`·`많이`·`거의`·`대부분`·`상당히`가 없다(걸리면 수치·조건으로 바꾸거나, 고유 명칭 등 예외 사유를 보고에 적는다)
- [ ] 다음 단계 행 글자가 `예정`으로 끝나면 그 행에 `<time>` 기한이나 `.d0-check__when` 조건이 있다

**눈으로 확인**

- [ ] 라벨·배지, h1, 요약 행 첫 줄만 읽어도 현재 상황을 말할 수 있다
- [ ] h1과 ① 섹션이 "무엇을 했다"가 아니라 "무엇이 달라졌다"를 말한다
- [ ] 위험마다 영향과 대응이 있고, 대응과 다음 단계 행이 같은 문장을 되풀이하지 않는다
- [ ] 다음 단계 행마다 누가, 언제 또는 무엇 뒤에 하는지 보인다
- [ ] 읽은 사람이 "그래서 지금 어떻게 된 거예요?"라고 다시 묻지 않아도 된다

## 프리셋 안티패턴

- 작업 로그 나열(`API 수정`, `회의 진행`, `문서 작성`)로 ①을 채우기, 작업명 h1.
- 상태를 배지 없이 문장 속에 숨기기, 차단 위험이 있는데 `정상` 배지.
- 문제만 있고 영향·대응이 없는 위험 행, 위험을 다음 보고로 미루기.
- "추후 예정", "검토 중"처럼 주체·조건 없는 다음 단계, 담당 칸을 비운 행.
- 모호 수량어("많이", "대부분"), 회의 맥락 없이는 이해되지 않는 약어.
- 그림 없이 글 블록만 쌓기, 권장 구성의 블록을 전부 채운 5개 이상 섹션.
- 해석 없는 차트 나열, 0이거나 근거 없는 숫자로 채운 빈 차트, 예상치를 측정값처럼 표기.
- 높이 비가 1.5를 넘는 두 섹션을 나란히 놓아 생긴 빈 영역, 균형을 맞추려고 내용을 다른 섹션으로 옮기기.
- 결론이 맨 끝에만 있음, 상위 보고 요약을 목적 → 배경 순서 그대로 늘어놓아 결과가 아래로 밀림.
- 같은 숫자를 히어로·요약 행·섹션 제목·KPI에 되풀이(같은 숫자 문자열 3회 이상), 거대 숫자 장식(뜻 없는 KPI).

## 경계

- preview는 결과물의 모양, report는 그로부터 알게 된 것과 지금 상태.
- 사건 하나의 경위와 원인이면 incident.
- 날짜 순서 자체가 주인공이면 timeline, 지금 상태와 다음 행동이 주인공이면 report(일정은 ② 섹션 시간 막대로 빌린다).
