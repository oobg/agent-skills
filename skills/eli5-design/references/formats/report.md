# report — 보고서

## 독자가 다 읽고 답할 수 있어야 할 질문

- 결론이 무엇인가?
- 근거는 무엇인가(숫자·비교)?
- 위험과 한계는 무엇인가?
- 다음에 누가 언제까지 무엇을 하는가?

## 요청 신호

"보고서", "결과 정리", "주간 리포트", "분석 결과 쉽게", "지표 요약".

## 권장 구성 예시 (예시일 뿐, 순서를 강제하지 않는다)

callout(결론 한두 줄, 맨 위) → kpi-cards(3~5, 전 기간 대비) → 차트 1개 + 한 줄 해석 → 상위 N 표 → 위험·한계 → callout(다음 할 일: 담당·기한).

차트는 인라인 SVG 하나로 충분하다. 차트마다 "그래서 무엇이 보이는가"를 한 줄로 단다.

합성 예: "팀 A 주간 처리 현황: 전주 대비 처리 시간 감소".

## 프리셋 안티패턴

- 해석 없는 차트 나열.
- 0이거나 근거 없는 숫자로 채운 빈 차트.
- 결론이 맨 끝에만 있음.
- 거대 숫자 장식(뜻 없는 KPI).

## 경계

- preview는 결과물의 모양, report는 그로부터 알게 된 것.
- 사건 하나의 경위와 원인이면 incident.
