# report — 보고서

## 독자가 다 읽고 답할 수 있어야 할 질문

- 결론(또는 제안)이 무엇인가?
- 근거는 무엇인가(측정한 숫자·비교, 적용 전이면 예상치)?
- 위험과 한계는 무엇인가?
- 다음에 누가 언제까지 무엇을 하는가?

## 요청 신호

"보고서", "결과 정리", "주간 리포트", "분석 결과 쉽게", "지표 요약".
아직 적용 전인 변경 제안·설명("이렇게 바꾸려 해요", "개편안 설명")도 report로 만든다. 요약 행 헤더를 쓰고,
수치는 측정값이 아니므로 `예상치`로 표기한다.

## 대표 도식

전/후 막대(diagram bars), 또는 kpi-cards 막대 변형. 원인·범위가 핵심이면 연결 그래프(diagram graph).

## 권장 구성 (섹션 3~4개, 앞쪽 핵심 섹션은 그림 필수)

권장 구성은 출발점이다. 독자 질문에 필요한 섹션만 만들고, 아래를 전부 채우지 않는다.

header(요약 행) → ① 얼마나 달라졌나: 전/후 막대 또는 kpi-cards 막대 변형(제목이 숫자를 말한다) → ② 어떻게 했나: 연결 그래프 또는 와이어프레임 → ③ 알아둘 점: diff-rows 배지 행 3개 이내(그림 없음) → ④ 할 일: checklist 담당 변형(그림 없음).

- **요약 행.** **행 라벨.** 사용자가 행 문구를 직접 주면 라벨까지 그대로 쓴다. 스킬이 문구를 정할 때만 기본 `이전 / 현재 / 결정 필요`, 적용 전 제안은 `지금 / 바꾸면 / 결정 필요`를 쓴다.
- **그림.** ①·②는 그림 필수, ③·④는 목록 섹션이라 그림 없이 둔다.
- **막대 수.** diagram 전/후 막대는 비교 쌍 2개까지. 3쌍 이상이면 kpi-cards 막대 변형을 쓴다([diagram.md](../blocks/diagram.md)).
- **비율 막대 위치.** 비율 막대는 근거(수치) 섹션 ① 안에 둔다. 레이아웃 균형을 위해 내용을 다른 섹션으로 옮기지 않는다.
- **나란히.** ①과 ②는 데스크톱에서 [shell.md](../blocks/shell.md)의 `.d0-split`으로 나란히 두어 첫 화면에 그림 두 개를
  함께 보여도 된다. 내용이 먼저다. 한쪽 높이가 다른 쪽의 1.5배를 넘으면 나란히를 포기하고 위아래로 쌓는다([shell.md](../blocks/shell.md) 높이 기준).
- **할 일.** [checklist](../blocks/checklist.md)의 담당 변형(`data-variant="owner"`: 행 끝에 담당·기한, 없으면 생략)을 쓴다.
  시간·기한 열이 일부 행에만 있으면 그 열을 빼고 해당 행 설명 줄에 넣는다.
- **결정.** 요약 행 또는 callout 하나로만 말한다. 결정이 둘이면 `결정 필요` 칸에 짧은 `ol`(최대 2개), 셋 이상이면
  가장 중요한 1개만 요약 행에, 나머지는 ④ 할 일로 보낸다. 문구가 고정이거나 결정자·시점이 다른 두 번째 결정은
  요약 행 아래 보조 줄 한 줄 + ④ 할 일 행으로 둔다([header.md](../blocks/header.md)).
- **예상치.** `예상치` 배지는 정보가 있는 태그라 페이지당 1회 허용한다(수치 섹션 머리나 그림 옆, [section-head.md](../blocks/section-head.md)).
  다른 수치는 글자 라벨 `(예상치)`로 단다. 측정값과 한 그림에 섞지 않는다.
- 차트마다 "그래서 무엇이 보이는가"를 한 줄 주석으로 단다.

합성 예: "팀 A 주간 처리 현황: 전주 대비 처리 시간 감소".

## 프리셋 안티패턴

- 그림 없이 글 블록만 쌓기, 권장 구성의 블록을 전부 채운 5개 이상 섹션.
- 해석 없는 차트 나열.
- 0이거나 근거 없는 숫자로 채운 빈 차트, 예상치를 측정값처럼 표기.
- 높이 비가 1.5를 넘는 두 섹션을 나란히 놓아 생긴 빈 영역, 균형을 맞추려고 내용을 다른 섹션으로 옮기기.
- 결론이 맨 끝에만 있음.
- 거대 숫자 장식(뜻 없는 KPI).

## 경계

- preview는 결과물의 모양, report는 그로부터 알게 된 것.
- 사건 하나의 경위와 원인이면 incident.
