# compare — 시안·옵션 비교

## 독자가 다 읽고 답할 수 있어야 할 질문

- 후보는 몇 개이고 각각 무엇이 다른가?
- 무엇을 추천하며, 왜인가?
- 고르면 무엇이 달라지고, 무엇을 포기하는가?
- 누가 언제까지 무엇을 정해야 하는가?

## 요청 신호

"A안 B안 비교", "어느 쪽이 나아", "옵션 정리", "결정 문서", "바뀌는 점만", "전후 비교".

## 변형

| 변형 | 언제 | 핵심 블록 |
| --- | --- | --- |
| 시안 | 화면을 눌러 보며 고른다 | side-by-side 시안 변형(미니 프로토타입) |
| 결정 | 숫자·정책·방식을 고른다 | side-by-side 결정 변형 + callout(결정 요청) |
| 전/후 | 이미 정한 변경을 보여 준다 | diff-rows |

## 권장 구성 예시 (예시일 뿐, 순서를 강제하지 않는다)

- 시안: header → section-head → side-by-side(2~3안, 직접 눌러 봄) → 고르면 달라지는 점 한 줄씩 → callout(결정 요청).
- 결정: header → callout(문제 한 줄) → side-by-side(옵션 2~3: 장점·비용·위험) → 추천과 이유 → 트레이드오프 → callout(결정 요청: 결정자·기한).
- 전/후: header → flow-line(어디가 바뀌나) → diff-rows(바뀐 행만) → 다음 할 일.

합성 예: "주문 내보내기 화면의 버튼 위치 A안·B안", "알림 주기 매일 vs 매주 결정".

## 프리셋 안티패턴

- 후보 간 크기·정보량 불균형(추천안만 크고 자세함).
- 이유 없는 추천 배지.
- 차이를 문단으로만 설명(나란히 놓인 행이 없음).
- 고른 뒤의 결과를 보여 주지 않음.
- 옵션 4개 이상(원칙 상한 3, 넘으면 1차로 걸러서 나눈다).

## 경계

- 화면을 눌러 고르면 시안 변형, 숫자·정책을 고르면 결정 변형.
- 고를 것이 없고 바뀐 내용 기록이면 timeline(변경 내역)이 맞다.
