# compare — 시안·옵션 비교

## 독자가 다 읽고 답할 수 있어야 할 질문

- 후보는 몇 개이고 각각 무엇이 다른가?
- 무엇을 추천하며, 왜인가?
- 고르면 무엇이 달라지고, 무엇을 포기하는가?
- 누가 언제까지 무엇을 정해야 하는가?

## 요청 신호

"A안 B안 비교", "어느 쪽이 나아", "옵션 정리", "결정 문서", "바뀌는 점만", "전후 비교".

## 변형

| 변형 | 언제 | 핵심 블록 |
| --- | --- | --- |
| 시안 | 화면을 눌러 보며 고른다 | [mockup-frame](../blocks/mockup-frame.md) 2개(나란히 눌러 보는 프레임) |
| 결정 | 숫자·정책·방식을 고른다 | 전/후 막대 + side-by-side 결정 변형 |
| 전/후 | 이미 정한 변경을 보여 준다 | 와이어프레임·막대 + diff-rows |

## 대표 도식

시안 변형은 화면 와이어프레임 SVG 2장([diagram](../blocks/diagram.md) (d)) + 나란히 놓은 같은 크기 프로토타입 프레임 2개([mockup-frame](../blocks/mockup-frame.md)).
mockup-frame은 HTML 목업이라 SVG 게이트를 채우지 않는다. 와이어프레임 SVG(① 또는 프레임 위)가 그 게이트를 채운다.
결정 변형은 옵션별 전/후 막대(diagram bars).

## 권장 구성 (섹션 3~4개, 앞쪽 핵심 섹션은 그림 필수)

권장 구성은 출발점이다. 독자 질문에 필요한 섹션만 만들고, 아래를 전부 채우지 않는다.

- 시안: header(문장형 리드) → ① 무엇이 다른가: 화면 와이어프레임 2장 나란히(diagram wireframe) → ② 직접 눌러 보기: mockup-frame 2개 → ③ 고르면 달라지는 점: diff-rows 3행 이내 + callout(결정 요청).
- 결정: header(요약 행: 문제 / 추천 / 결정 필요) → ① 옵션별 비용·시간: 전/후 막대(diagram bars) → ② 옵션 비교: side-by-side 결정 변형(장점·비용·위험) → ③ 고르면 생기는 일: 연결 그래프(diagram graph, 영향받는 곳만 블루).
- 전/후: header(요약 행: 이전 / 현재 / 결정 필요) → ① 어디가 바뀌나: 와이어프레임 또는 연결 그래프 → ② 얼마나: 전/후 막대 → ③ 바뀐 행: diff-rows.

앞쪽 ①·②는 그림 필수다. diff-rows만 있는 목록 섹션은 그림 없이 둔다.
요약 행에 `결정 필요`가 있으면 결정 callout을 두지 않는다. 결정 세부는 요약 행 아래 보조 줄로.
결정이 둘 이상이면 [header.md](../blocks/header.md) 요약 행 규칙(`ol` 최대 2개)을 따른다.

합성 예: "주문 내보내기 화면의 버튼 위치 A안·B안", "알림 주기 매일 vs 매주 결정".

## 프리셋 안티패턴

- 그림 없이 글 블록만 쌓기, 권장 구성의 블록을 전부 채운 5개 이상 섹션.
- 후보 간 크기·정보량 불균형(추천안만 크고 자세함).
- 이유 없는 추천 배지.
- 차이를 문단으로만 설명(나란히 놓인 행이 없음).
- 고른 뒤의 결과를 보여 주지 않음.
- 옵션 4개 이상(원칙 상한 3, 넘으면 1차로 걸러서 나눈다).

## 경계

- 화면을 눌러 고르면 시안 변형, 숫자·정책을 고르면 결정 변형.
- 고를 것이 없고 바뀐 내용 기록이면 timeline(변경 내역)이 맞다.
- 고를 옵션이 없고 아직 적용 전인 변경 제안·설명이면 report(요약 행 헤더, 수치는 `예상치`).
