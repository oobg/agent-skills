# preview — 결과물 미리보기

## 독자가 다 읽고 답할 수 있어야 할 질문

- 받으면 어떤 모양인가(파일·화면·표)?
- 각 칸(열)은 무엇을 뜻하는가?
- 어디서부터 어디까지가 예시이고, 실제와 무엇이 다를 수 있는가?

## 요청 신호

"결과물 어떻게 생겨", "엑셀 양식 미리보기", "출력 샘플", "받으면 뭐가 와", "리포트 양식".

## 대표 도식

미니 격자 썸네일(diagram grid) + 실물 같은 결과물 목업(tab-preview). 받는 화면이 있으면 [mockup-frame](../blocks/mockup-frame.md).

## 권장 구성 (섹션 3개, 앞쪽 핵심 섹션은 그림 필수)

권장 구성은 출발점이다. 독자 질문에 필요한 섹션만 만든다.

header(문장형 리드) → ① 무엇을 받나: flow-line 한 줄 + 미니 격자 그림 카드(thumb-cards) + 단계 주석(step-columns) → ② 받은 파일 모양: tab-preview(시트 탭 + 표 목업 + 열 주석) → ③ 받는 화면(해당할 때): mockup-frame.

tab-preview에는 반드시 `예시 데이터` 또는 `미리보기` 표시를 둔다.

합성 예: "주문 내보내기 파일: 요약 시트와 상세 시트", 값은 `상품 1`, `팀 A`, 둥글지 않은 작은 합성 수치.

## 프리셋 안티패턴

- 그림 없이 글 블록만 쌓기, 권장 구성의 블록을 전부 채운 5개 이상 섹션.
- 열 7개 초과(원칙 상한). 그 이상은 시트를 나눈다. 가로 스크롤이 생기면 실패다.
- 실제 개인 데이터처럼 보이는 값(실명·연락처·실제 상호).
- 열 의미 설명 없음.
- 미리보기와 실제 결과물의 구분이 없음.

## 경계

- preview는 결과물의 **모양**, report는 그 결과물로 **알게 된 것**.
