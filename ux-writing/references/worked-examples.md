# 화면 단위 윤문 예시

한 줄짜리 예시로는 안 보이는 것들 — 빈 문장 제거, 충돌 우선순위, 다음 행동
힌트 — 은 여러 요소가 같이 있는 화면에서 드러난다. SKILL.md의 원칙을 실제
화면에 어떻게 겹쳐 적용하는지 보여주는 예시 모음이다.

## 업로드 실패 다이얼로그

```
[BEFORE]
제목:  오류가 발생하였습니다
본문:  파일 업로드를 진행하는 과정에서 알 수 없는 오류가 발생하여
       작업이 정상적으로 완료되지 못하였습니다. 다시 시도해 주시기 바랍니다.
버튼:  확인

[AFTER]
제목:  파일을 못 올렸어요
본문:  잠깐 문제가 있었어요. 인터넷 연결을 확인하고 다시 올려 주세요.
버튼:  다시 시도
```

무엇을 바꿨나

- **제목**: `명확` 먼저(무슨 일인지), 그 위에 `숨은 감정 공감`(딱딱한 "오류
  발생" 대신 사용자 입장). 충돌 우선순위대로 명확이 먼저, 감정은 그 위에.
- **본문**: 번역투(`진행하는 과정에서`)와 잡초(`정상적으로`) 제거, 같은 말
  반복(제목과 본문이 둘 다 "오류") 정리. 막연한 "다시 시도" 대신 **할 수 있는
  다음 행동**(연결 확인)을 줌.
- **버튼**: `다음 화면 예고`. "확인"은 누르면 뭐가 되는지 모름 → "다시 시도".

원인을 모를 땐 본문을 `잠깐 문제가 있었어요. 다시 시도해 주세요.`로 줄인다.
없는 원인을 지어내지 않는 게 `Respect`다.
