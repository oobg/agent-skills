# 번역투 세부 패턴 — 문법 단위

`AI가 쓴 티 빼기` 표의 번역투 행("~를 통해", "~에 대해", "~에 있어서", 이중
피동, "가지고 있다")보다 한 단계 더 세밀한, 문법 구조 단위의 번역투다.
한국 번역학계에서 정리해 온 영어 직역 패턴 계보를 따른다 (출처 성격은
`references/about.md`의 `학술·출처 근거` 참고).

## 언제 이 파일을 여나

SKILL.md 본문 표로 안 잡히는데 문장이 어색하면 연다. **긴 산문 전용인
`ai-tells.md`와 달리, 여긴 문장 하나, 짧은 UI 카피에도 적용된다** — 문법
구조라 길이와 무관하게 나오기 때문이다.

## 패턴

### 영어 대명사 직역

한 단락에 "그/그녀/그것/그들"이 3회 이상 나오면 십중팔구 영어 대명사를
그대로 옮긴 것이다. 한국어는 원래 주어·목적어를 생략하는 언어다.

```
❌ 사용자가 버튼을 누르면, 그것은 모달을 연다. 그는 그 안에서 설정을 바꾼다.
✅ 사용자가 버튼을 누르면 모달이 열린다. 그 안에서 설정을 바꾼다.
```

처방: 절반 이상을 생략하거나, 정 필요하면 호칭·명사구로 바꾼다.

### 좌향 관형구 (관계절이 명사 앞에 쌓이는 구조)

영어 관계절(who, which)을 앞으로 욱여넣으면 명사 앞에 수식어가 3어절 이상
쌓인다. 한국어는 이게 쌓일수록 읽기 어렵다.

```
❌ 어제 회의에서 논의했던 예산 문제를 해결할 새로운 방안을 제시했다.
✅ 어제 회의에서 예산 문제가 나왔다. 그걸 해결할 새 방안을 제시했다.
```

처방: 문장을 분리하거나, 관형구를 뒤로 돌려 동격절로 푼다("X를
만났는데, 그 X는 …").

### 이중 조사

"~에서의", "~으로의", "~에로의", "~에의", "~으로부터의" — 조사 두 개를
겹쳐 붙인 형태. 영어 전치사구를 명사구로 직역할 때 나온다. 단순한
"~의"는 여기 해당하지 않는다.

```
❌ 시장에서의 경쟁력 확보를 위한 전략으로의 전환이 필요하다.
✅ 시장 경쟁력을 확보하려면 전략을 바꿔야 한다.
```

처방: 조사를 하나로 줄이거나, 절이나 구로 풀어쓴다.

### "~에 의해" 피동 (행위자 삭제)

영어 수동태(by 이하)를 그대로 옮기면 행위자가 뒤로 밀려나 문장이
흐릿해진다.

```
❌ 새 정책이 정부에 의해 발표되었다.
✅ 정부가 새 정책을 발표했다.
```

처방: 행위자를 주어로 끌어와 능동으로 바꾼다.

### 사역·인지 동사 직역

"suggest / show / indicate / reveal"류 영어 동사를 "~을 시사한다 / ~을
보여준다"로 기계적으로 옮기면 티가 난다. 사역("때문에")도 같은 계열.

```
❌ 이 데이터는 사용자 이탈이 증가하고 있음을 시사한다.
✅ 이 데이터에 따르면 사용자 이탈이 늘고 있다.

❌ 가격 인상이 이용자 감소를 야기했다.
✅ 가격을 올리자 이용자가 줄었다.
```

처방: "~에 따르면 ~이다", "~으로 ~이 드러났다"처럼 근거와 결론을
분리하거나, 사역은 "~때문에/덕분에/로 인해" 부사절로 바꾼다.

### have/make/take/give + 명사 직역

영어의 "have a meeting", "make a decision", "take a break"류 관용 표현을
동사 그대로 옮기면 "~을 가지다/만들다/취하다"가 된다. 한국어는 이런 걸
동사 하나로 표현한다.

```
❌ 오늘 팀과 회의를 가졌다.       ✅ 오늘 팀과 회의를 했다.
❌ 그 자리에서 결정을 만들었다.   ✅ 그 자리에서 결정했다.
❌ 잠시 휴식을 취했다.           ✅ 잠시 쉬었다.
```

처방: "명사 + 가지다/만들다/취하다" 구조가 보이면 그 명사를 동사로
바꿀 수 있는지 먼저 확인한다.

### "-들" 복수 표지 기계적 부착 (판단형 — 확신 없을 땐 건드리지 않음)

영어 복수형(-s)을 기계적으로 "-들"에 대응시키면, 원문에 없던 뉘앙스가
생긴다. "도서관에 책이 많다"와 "도서관에 책들이 많다"는 둘 다 영어로는
"There are many books"로 옮길 수 있지만, 뉘앙스가 다르다 — 전자는
그냥 양이 많다는 느낌이고, 후자는 여러 종류가 다양하게 있다는 느낌을
준다. 무정물·추상명사에 "-들"을 무조건 붙이면 이런 미세한 의미가
왜곡될 수 있다.

```
❌ 새로운 아이디어들과 방법들이 있다.
✅ 여러 가지 남다른 생각과 방법이 있다.
```

**주의**: 이 패턴은 다른 항목들보다 판단이 더 필요하다. "-들"이 실제로
잘못 쓰였는지는 문맥에 따라 갈리고, 무조건 빼는 게 항상 자연스러운 것도
아니다. 확신이 안 서면 건드리지 않는다 — 이건 "고치는 게 나을 때"보다
"과도하게 고치지 않아야 할 때"가 더 많은 패턴이다.

## 밀도 신호 — 연결어미 뒤 쉼표

이건 단어가 아니라 구두점 습관이다. "-고/-며/-지만/-아서/-어서" 뒤에
바로 쉼표를 찍는 게 **한두 번은 자연스럽지만, 한 글에 6회 이상 몰리면**
기계적 리듬의 신호다. `ai_lint.py`가 ADVISORY로 세어 보여준다(밀도
판단이라 0일 필요는 없다).

```
❌ 파일을 올리고, 이름을 정하고, 공유 버튼을 누른다.
✅ 파일을 올리고 이름을 정한 뒤 공유 버튼을 누른다.
```

## 주의

- 위 다섯 패턴 모두 **판단형**이다: 스크립트로 자동 검출하지 않고 사람이
  읽고 짚는다. (마지막 밀도 신호만 예외적으로 스크립트가 센다.)
- 여기도 원칙은 같다: **의미는 그대로, 구조만 편다.** 문장 하나를 통째로
  다시 쓰지 않고, 걸리는 구절만 수술적으로 고친다.
- 격식체/평어체 같은 어체(register)는 그대로 유지한다. 구조를 펴는 것과
  톤을 바꾸는 건 다른 일이다.
