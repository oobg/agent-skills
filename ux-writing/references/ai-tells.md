# AI가 쓴 티 — 전체 패턴 카탈로그

위키피디아 [Signs of AI writing](https://en.wikipedia.org/wiki/Wikipedia:Signs_of_AI_writing)
(WikiProject AI Cleanup)의 24개 패턴을 한국어 기준으로 옮긴 것이다. 영어
원문을 그대로 직역한 게 아니라, **한국어 글에서 실제로 같은 질감이 나는
지점**으로 다시 잡았다.

## 언제 이 파일을 여나

평소 단건, 짧은 UI 문구는 SKILL.md 본문의 표만으로 충분하다. 이 파일은
**긴 산문을 손볼 때** 연다 — README, 가이드, 블로그/릴리스 노트, 소개글,
챗봇 답변 윤문처럼 여러 문단이 이어지는 글. 산문에서만 드러나는 티(의미
과장, 3의 법칙, 부정 병렬, 뻔한 결론 등)가 여기에 다 들어있다.

쓰는 법은 SKILL.md와 같다. **의미는 그대로, 질감만 손본다.** 티가 보이는
구간만 수술적으로 고치고, 멀쩡한 문장은 두는 게 원칙이다. 아래 ❌→✅는
정답 템플릿이 아니라 패턴 예시다 — 맥락이 다르면 원칙으로 돌아간다.

## 중요 — 이건 금칙어 목록이 아니다

아래 패턴과 신호는 **하나하나가 'AI가 쓴 증거'가 아니다.** 사람도 늘 쓴다 —
`또한` 한 번, 대시 한 개, 셋짜리 나열 하나는 멀쩡한 글에도 있다. AI 질감은
이런 신호가 **한 문단에 여럿 겹칠 때** 생긴다. 그러니 단어를 하나씩 기계적으로
지우지 말고, **신호가 몰려 있는 구간**을 본다.

반대 방향 함정도 있다. 수식을 다 걷어내 **밋밋하고 감정 없는 중립문**으로
만들면, 그 무미건조함 자체가 **또 다른 AI 티**다. 의도해서 살린 보이스(따뜻한
빈 상태 문구, 일부러 넣은 카피의 리듬)는 티가 아니라 자산이다. 목적은 덜어내기가
아니라 **사람이 쓴 것처럼 들리게 하기**다 — 덜어내다 사람 냄새까지 지우면
과윤문이다.

- 언어 패턴 (7–12)

## 내용 패턴

실제 정보 대신 **분위기와 중요성**으로 채우는 패턴. 사실이 빈약할수록 더
자주 나온다.

### 1. 의미 과장 (Significance inflation)

근거 없이 "역사적", "획기적"이라 띄운다. 무엇이 왜 중요한지는 안 쓴다.

```
❌ ~의 역사에 길이 남을 중요한 전환점이 되었다.
✅ 1989년에 지역 통계를 모으려고 만들어졌다.
```

신호: `획기적인`, `혁신적인`, `~의 역사에 남을`, `중요한 이정표`, `새로운 지평을 연`

### 2. 권위 끌어오기 (Notability name-dropping)

유명 매체, 기관 이름을 근거 없이 나열해 권위를 빌린다.

```
❌ NYT, BBC, FT가 모두 주목한 인물이다.
✅ 2024년 NYT 인터뷰에서 그는 ~라고 말했다.
```

매체를 언급할 거면 **무엇을, 언제, 어떤 맥락에서** 다뤘는지 구체적으로.

### 3. 겉도는 `~하며` 분석 (Superficial analyses)

`상징하며`, `반영하고`, `보여주는` 식으로 의미를 부여하는 척하지만 근거가
없다.

```
❌ 시대정신을 상징하며, 사회 변화를 반영하고, 새 가능성을 보여주는 작품이다.
✅ (근거 있는 한 가지로 좁히거나, 출처를 달거나, 통째로 뺀다)
```

### 4. 홍보성 미사여구 (Promotional language)

여행 브로슈어 같은 형용사. 정보가 아니라 광고다.

```
❌ 숨막히는 절경 속에 고즈넉하게 자리잡은 매력적인 마을이다.
✅ 곤다르 지역에 있는 마을이다.
```

신호: `아름다운`, `매력적인`, `자리잡은`, `~을 자랑하는`, `완벽한`, `독보적인`

### 5. 막연한 출처 (Vague attributions)

"누가" 없이 "전문가들은", "~로 알려져 있다"로 권위를 만든다.

```
❌ 전문가들은 이 기능이 핵심적 역할을 한다고 본다.
✅ 2019년 ○○ 조사에 따르면 사용자의 절반이 이 기능을 매주 썼다.
```

출처가 없으면 단정하지 말고, 출처를 찾거나 주장을 뺀다 (Respect).

### 6. 정형화된 역경 서사 (Formulaic challenges)

"여러 어려움에도 불구하고 꾸준히 성장" — 구체적 어려움은 없는 빈 서사.

```
❌ 여러 어려움에도 불구하고 꾸준히 성장하고 있다.
✅ 2022년 공급망 차질로 출고가 3개월 밀렸지만, 이후 물량을 회복했다.
```

## 언어 패턴

문장 단위에서 나오는 기계적 질감. 한국어 AI 글은 대부분 여기서 걸린다.

### 7. AI 상투어 (AI vocabulary)

특정 단어가 **반복, 군집**되어 통계적으로 과하게 나온다. 한 번 쓰는 건 문제가
아니다 — 한 문단에 몰릴 때가 신호다.

```
❌ 또한 이 기능은 사용자 경험의 지평을 넓히는 산물입니다.
✅ 이 기능은 ○○할 때 쓸 수 있어요.
```

신호: `또한`, `결론적으로`, `~의 산물`, `지평`, `~을 제공합니다`, `원활하게`,
`손쉽게`, `효율적으로`

### 7-1. 변환 공식 ("A에서 B로")

패러다임 전환을 표현할 때 거의 자동으로 등장하는 슬로건 형태.

```
❌ '규모의 경쟁'에서 '전략의 경쟁'으로.
✅ 이제는 규모보다 전략이 승부를 가른다.
```

변환 공식을 직접 단언으로 푼다. 한 문서에 이런 슬로건형 표현은 많아야
한 번.

### 7-2. "즉" 남발

보충 설명이 필요할 때마다 "즉"을 앞에 붙인다. 영어 `i.e.` 직역에 가깝다.

```
❌ AI 대중화, 즉 경제성 측면에서 접근할 필요가 있다.
✅ AI가 널리 쓰이려면 결국 경제성이 관건이다.
```

"곧", "말하자면", "다시 말해"로 바꾸거나 아예 생략하고 쉼표로 잇는다.
한 문서에 "즉"은 두 번 이하로.

### 8. 계사 회피 (Copula avoidance)

`~이다`/`~이 있다`로 쓰면 될 걸 굳이 거창한 동사로 바꾼다.

```
❌ 이 컴포넌트는 트리거 역할을 수행하며, 다양한 옵션을 갖추고 있습니다.
✅ 이 컴포넌트는 동작을 시작하는 버튼이에요. 옵션이 여러 개 있어요.
```

신호: `~역할을 한다`, `~역할을 수행한다`, `~을 갖추고 있다`, `~을 자랑한다`,
`~로 기능한다`

### 9. 부정 병렬 (Negative parallelisms)

"단순한 X가 아니라 Y다" 구문. 대비를 만들어 깊어 보이게 하지만 빈 수사다.

```
❌ 이건 단순한 업데이트가 아니라, 일하는 방식의 혁명입니다.
✅ 이번 업데이트로 일괄 처리와 오프라인 모드가 추가됐어요.
```

신호: `단순한 ~가 아니라`, `~를 넘어 ~로`, `~이 아닙니다. ~입니다.`

### 10. 3의 법칙 (Rule of three)

뭐든 꼭 세 개로 묶는다. 한 번이면 리듬이지만 반복되면 티가 난다.

```
❌ 빠르고, 강력하고, 직관적인 경험을 제공합니다.
✅ 작업이 평균 30% 빨라졌어요. (실제로 잰 한 가지로)
```

항목이 둘이면 둘, 넷이면 넷으로. 억지로 셋을 맞추지 않는다.

### 10-1. 문단 3단 공식 (먼저·반면·결국)

문단 시작마다 "먼저 ~ / 반면 ~ / 결국 ~"처럼 순서 접속사가 고정 배치된다.
3의 법칙(10번)이 내용을 억지로 셋으로 묶는 거라면, 이건 **문단을 여는
방식** 자체가 공식화된 것이다.

```
❌ 먼저 인프라 비용이 줄었다. 반면 운영 인력은 늘었다. 결국 손익은 비슷했다.
✅ 인프라 비용은 줄었지만 운영 인력이 늘어서, 손익은 결국 비슷했다.
```

3개 중 2개는 지우고 접속사 없는 문단도 섞는다.

### 10-2. 대칭 대구 ("A인가, B인가")

같은 글에서 이항 대립을 평행구로 3회 이상 반복한다.

```
❌ 확장인가, 집중인가. 속도가 중요한가, 안정성이 중요한가. 누가 더 빠른가, 누가 더 정확한가.
✅ 확장이냐 집중이냐를 놓고 의견이 갈린다. 결국은 속도와 안정성 중 뭘 우선할지의 문제다.
```

3개 중 2개는 비대칭으로 바꾼다 — 한쪽은 질문형, 한쪽은 서술형으로 섞거나
분량을 다르게 한다.

### 11. 동의어 돌려막기 (Synonym cycling)

같은 대상을 매번 다른 말로 바꿔 부른다. 글이 다양해 보이려는 강박.

```
❌ 주인공은 ... 이 등장인물은 ... 중심 인물은 ... 우리의 영웅은 ...
✅ 주인공은 ... 주인공은 ... (가장 명확한 한 단어를 반복)
```

같은 걸 가리키면 같은 단어를 써도 된다. 반복이 혼동보다 낫다.

### 12. 가짜 범위 (False ranges)

"A부터 Z까지"로 포괄성을 가장한다. 실제론 둘 사이가 비어 있다.

```
❌ 빅뱅부터 암흑물질까지 우주의 모든 것을 다룹니다.
✅ 별의 일생, 블랙홀, 은하 충돌을 다뤄요.
```

다루는 걸 그냥 나열한다.

### 15-1. 대시로 라벨 가르기, 대시로 뜻 감싸기

15번(인라인 헤더 목록)의 구두점 판. 구조를 그대로 두더라도 **구분자를 대시로
쓰는 것 자체**가 티다. 대시는 영어 조판 습관이고, 한국어에는 그 자리에 쓰는
부호가 따로 있다.

**리스트 라벨은 콜론으로 가른다.**

```
❌ - 개발 문서, 코드 주석 — 어투보다 정확성이 먼저다.
✅ - 개발 문서, 코드 주석: 어투보다는 정확성이 먼저다.
```

**뜻풀이는 괄호로 감싼다.**

```
❌ 사고 — 생각하다 — 한다
✅ 사고(생각하다)한다
```

**콜론의 자리는 정반대다.** 리스트 항목 *안*의 콜론은 자연스럽지만, 문장을
끝내고 목록을 여는 콜론은 사람이 잘 안 쓴다.

```
❌ 모든 문구에 기계적으로 적용하지는 않는다:
✅ 모든 문구에 기계적으로 적용하지는 않는다.
```

`ai_lint.py`가 `리스트 라벨 대시`, `대시로 뜻 감싸기`, `문장 끝 콜론`으로 각각
센다.

**나열을 압축할 때 특히 샌다.** 문장을 개조식으로 줄이며 `A, B, C`를 `A·B·C`로
붙이기 쉬운데, 셋 이상은 사슬이라 HARD다. 압축 뒤 `ai_lint`를 꼭 다시 돌린다.

### 7-3. 의인화된 무생물 주어

무생물이나 추상 개념이 사람처럼 "말하고 시사하는" 구조. 영어 논문투
("This study suggests…")를 그대로 옮기면 나온다.

```
❌ 이 연구는 사용자 이탈이 늘고 있음을 시사한다.
✅ 이 연구에 따르면 사용자 이탈이 늘고 있다.

❌ 데이터가 말해주는 것은 명확하다.
✅ 데이터를 보면 분명하다.
```

주어와 서술어를 같이 본다. `연구·데이터·결과·시스템·AI` 같은 주어에
`시사한다·보여준다·말해준다·드러낸다`가 붙으면 신호다. 사람을 주어로
되돌리거나("연구진은 ~라고 본다"), 근거와 결론을 분리한다("~에 따르면 ~이다").

`ai_lint.py`가 ADVISORY로 센다. 다만 단어 목록 기반이라 놓치는 게 많으니
참고 신호로만 쓴다.

### 덤. 형식명사 종결 · 진행형 남발

번호 매긴 24패턴만큼 흔하진 않지만 자주 걸리는 두 가지.

**"것이다" 종결** — 말할 내용을 형식명사로 한 번 감싸고 끝맺는다. 종결어미로
바로 끝내면 되는데 굳이 에두른다.

```
❌ 이번 변화가 크다는 것이다.
✅ 이번 변화가 크다.
```

**"~고 있다" 남발** — 진행형을 기본값처럼 쓴다. 단순 현재/과거로 충분한
자리에도 습관적으로 붙인다.

```
❌ 사용자는 이 화면에서 설정을 확인하고 있다.
✅ 사용자는 이 화면에서 설정을 확인한다.
```

실제로 진행 중인 동작이면 그대로 둔다 — "지금 업로드하고 있어요"처럼
현재진행이 의미상 맞을 땐 문제가 아니다.

**경어법 일관성 손실** — 한 글이나 대화 안에서 해요체·합쇼체·해라체가
섞인다. `register.md`가 "어느 어체를 쓸지 정하는" 문제라면, 이건 **정한
어체를 끝까지 지켰는가**를 보는 자체 점검이다.

```
❌ 도와주시겠습니까? (다음 문장) 도와줘? / 이 기능은 편리합니다. (다음 문단) 편리하다.
✅ 도와주시겠어요? / 도와줄래요? (한 단계로 통일)
```

같은 문서·대화 안에 격식 단계가 2단계 이상 섞이면 신호다. 어느 단계가
맞는지는 `register.md`를 따르고, 여기선 그 선택이 끝까지 유지됐는지만
본다.

## 스타일 패턴

겉모양에서 나는 티. 시각 장식과 서식 습관.

### 13. 대시 남발 (Em dash overuse)

`—`를 문장마다 끼워 넣어 호흡을 끊는다.

```
❌ 제도가—사람이 아니라—문제인데—그런데도 계속된다.
✅ 사람이 아니라 제도가 문제인데, 그런데도 계속된다.
```

쉼표나 마침표로 충분하다.

### 14. 볼드 남발 (Boldface overuse)

강조가 너무 많으면 아무것도 강조되지 않는다.

```
❌ **OKR**, **KPI**, **BMC**를 **모두** 관리하세요.
✅ OKR, KPI, BMC를 관리하세요.
```

### 15. 인라인 헤더 목록 (Inline-header lists)

`**항목:** 설명` 형태를 줄줄이 늘어놓는다. 같은 말을 두 번 한다.

```
❌ **성능:** 성능이 개선되었습니다. **안정성:** 안정성이 좋아졌습니다.
✅ 이번 버전은 더 빠르고 덜 멈춰요.  (산문으로 풀기)
```

### 16. 제목 대문자 (Title Case Headings)

**영어 전용 — 한국어 거의 해당 없음.** 한국어엔 단어별 대문자 개념이 없다.
한국어 대응으로는, 제목의 모든 단어를 굳이 한 단계씩 띄우거나 과하게
멋부린 한자어로 채우는 습관 정도가 비슷한 인상을 준다.

```
❌ 전략적 협상 및 파트너십 구축에 관하여
✅ 협상과 파트너십
```

### 17. 이모지 (Emojis)

문서, UI 문구에 장식용 이모지를 흩뿌린다.

```
❌ 🚀 출시 단계  💡 핵심 인사이트  ✅ 완료
✅ 출시 단계 / 핵심 인사이트 / 완료
```

사용자가 먼저 썼거나 톤상 분명히 맞을 때만 남긴다.

### 18. 곱슬따옴표 (Curly quotes)

**한국어 거의 해당 없음.** 한글 본문에선 따옴표 종류가 티로 잘 안 걸린다.
다만 영문을 섞을 때 `"` `"`(곱슬)와 `"`(직선)가 한 문서에 섞이면 통일한다.

## 커뮤니케이션 패턴

대화형 AI 특유의 군말. UI, 문서에 그대로 새어 나오면 가장 티가 난다.

### 19. 챗봇 흔적 (Chatbot artifacts)

도움 제안, 마무리 인사 같은 대화 잔여물.

```
❌ 도움이 되셨길 바라요! 더 궁금한 점이 있으면 언제든 말씀해 주세요!
✅ (통째로 제거)
```

### 20. 컷오프 면피 (Cutoff disclaimers)

"제공된 자료로는 알 수 없지만" 식의 자기 변명.

```
❌ 제공된 자료에는 정보가 제한적이지만, 아마도 ~일 것으로 보입니다.
✅ (자료를 찾아 채우거나, 모르면 그 문장을 뺀다)
```

### 21. 아부조 (Sycophantic tone)

"좋은 질문이에요!", "정확히 보셨어요!" 같은 과한 호응.

```
❌ 정말 좋은 질문이에요! 완전히 맞는 방향으로 보고 계세요!
✅ (바로 본론으로)
```

## 군더더기, 완곡

문장을 늘이고 흐리는 패턴. SKILL.md의 `잡초 제거`, `소리 내어 읽기`와
겹치지만, AI 글에서 특히 자주 나온다.

### 22. 군더더기 어구 (Filler phrases)

짧게 쓸 수 있는 걸 길게 늘인다.

```
❌ 작업을 완료하기 위해서는 / 시간이 부족하다는 사실로 인해
✅ 작업을 끝내려면 / 시간이 부족해서
```

신호: `~하기 위해서는`, `~라는 사실로 인해`, `~에 있어서`, `~와 관련하여`

문법 구조 단위(대명사 직역, 좌향 관형구, 이중 조사, "~에 의해" 피동)까지
파고들려면 `references/translation-ese.md`를 본다.

### 23. 과도한 완곡 (Excessive hedging)

완곡 표현을 겹쳐 쌓아 아무 말도 안 하게 된다.

```
❌ 어쩌면 ~할 수도 있을 것으로 보이는 측면이 있습니다.
✅ ~할 수 있어요.   (확실치 않으면 한 번만: ~할 수도 있어요)
```

완곡은 한 겹이면 충분하다.

### 24. 뻔한 결론 (Generic conclusions)

"앞으로가 기대된다"류의 내용 없는 마무리.

```
❌ 앞으로의 전망이 밝으며, 가능성은 무궁무진합니다.
✅ 다음 분기에 모바일 버전을 출시할 계획이에요.   (구체적 계획·사실)
```

빈 결론은 차라리 없는 게 낫다. 더 할 말이 없으면 거기서 끝낸다.

## 문단 통째 예시

한 줄 예시로는 안 보이는 것들 — 여러 패턴이 한 문단에 겹쳐 나오는 모습.

**Before (AI가 쓴 티):**

> 이번 소프트웨어 업데이트는 혁신을 향한 회사의 변함없는 의지를 보여주는
> 산물입니다. 또한 매끄럽고, 직관적이며, 강력한 사용자 경험을 제공하여—
> 사용자가 목표를 효율적으로 달성할 수 있도록 보장합니다. 이것은 단순한
> 업데이트가 아니라, 생산성을 바라보는 방식의 혁명입니다. 업계 전문가들은
> 이번 업데이트가 기술 지형 전반에 오래 남을 영향을 미칠 것으로 보고 있습니다.

여기 겹친 티: 의미 과장(1), AI 상투어(7), 3의 법칙(10), 부정 병렬(9), 막연한
출처(5), 대시 남발(13), 뻔한 결론(24).

**After (사람이 쓴 듯):**

> 이번 업데이트로 일괄 처리, 단축키, 오프라인 모드가 추가됐어요. 베타
> 테스터 반응은 좋은 편이고, 대부분 작업이 더 빨라졌다고 했어요.

사실(추가된 기능)과 근거(테스터 반응)만 남기고, 분위기 잡는 수식은 다
걷어냈다. 짧아졌지만 정보량은 오히려 늘었다.

## 글 전체 — 게슈탈트 점검

단어를 다 걷어내도 사람이 보면 "AI가 썼네" 싶을 때가 있다. 그 느낌은 단어가
아니라 글의 **모양**에서 나온다. 24패턴이 문장 단위라면, 이건 글 전체 단위다.
긴 글에만 본다.

네 갈래인데, **둘은 편집으로 고치고 둘은 작성자만 줄 수 있다.** 이 경계가
핵심이다. 없는 걸 지어내면 막연한 출처(5)와 권위 끌어오기(2)를 되살리는
자기모순이다.

**편집으로 고치는 것 (Claude가 함)**

1. 고른 리듬을 변주한다. AI는 문장 길이가 다 비슷하다. 일부러 짧게 툭 끊고
   다음은 길게 늘인다. 한 문단 안에서 호흡을 바꾼다. **반대 극단도 티다** —
   짧은 단문만 줄줄이 이어지고 복문·중문이 거의 없으면, "간결하게"를 의식한
   AI 특유의 리듬이다. 이웃한 단문 두세 개를 연결어미나 관형절로 묶어 일부러
   섞는다.
2. 과한 대칭을 깬다. 항목 셋을 똑같은 분량과 구조로 다루면 그 균등함이
   신호다. 중요한 하나를 길게 쓰고 나머지는 짧게, "나머지도 비슷해요"로
   접어도 된다.

**작성자가 줘야 하는 것 (지어내지 않는다)**

3. 관점이 없다. AI 글은 마찰 없이 친절하기만 하고 편애나 솔직한 한마디가
   없다. 이건 작성자의 실제 의견이라 없으면 *지어내지 말고 물어본다*. "여기
   본인 의견이나 추천을 한 줄 넣을 수 있나요?"
4. 구체성이 가짜다. "많이 쓰는 분"은 그럴듯하지만 일반적이다. 사람은 이상하게
   구체적이다("매일 톨게이트를 두 번 지나가는데"). 이런 실제 경험이나 수치는
   작성자에게서 온다. 없으면 *비워두거나 묻는다*, 채워 넣지 않는다.

**천장을 정직하게 말한다.** 1번과 2번까지가 윤문이 닿는 끝이다. 거기까지 해도
"정보는 맞는데 사람 냄새가 옅다" 싶으면, 그건 윤문 실패가 아니라 원문에
작성자의 관점과 경험이 없어서다. 그 사실을 알리는 게, 있지도 않은 목소리를
흉내 내는 것보다 정직하다.

**어디에 쓰나.** 사람 목소리가 중요한 글(후기, 에세이, 설득, 브랜드 카피)에
주로 쓴다. 설명서나 절차 같은 레퍼런스성 글에선 대칭이 오히려 독자에게
친절하니, 억지로 비대칭으로 만들지 않는다.

**평탄화 주의.** 리듬을 흔든다고 문장을 무작정 토막 내거나, 비대칭을 만든다고
멀쩡한 정보를 버리지 않는다. 게슈탈트 점검은 *더해서* 사람 글에 가깝게 하는
것이지 더 깎는 게 아니다.
