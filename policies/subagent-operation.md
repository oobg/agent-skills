# 서브에이전트 운영 런타임 규칙

전체 정책의 정본은 `~/.ontology/tenants/shared/sources/2026-09-11_codex-multimodel-orchestration-operation-policy-v1.md`입니다.
이 문서는 여러 저장소와 세션에 주입할 실행 규칙을 추출한 발행 소스이며, 마커 사이의 규칙만 런타임 스냅샷으로 컴파일합니다.

<!-- policy:rules:start -->
- <!-- rule:main-orchestrator -->
  사용자가 직접 시작한 주 에이전트는 기본 조정자로서 요구사항을 분석하고 작업을 분해·위임·조율·검토하며 완료를 선언합니다. 실제 실행과 산출물 생성은 서브에이전트에 맡깁니다. 완료 선언 책임은 기술적 사실을 독점하거나 근거 없이 검토 의견을 뒤집을 권한을 뜻하지 않습니다. Codex의 기본 조정 모델은 gpt-5.6-luna, reasoning은 max로 명시하되 이 배치는 실측으로 재검토할 수 있는 운영 가설입니다.
- <!-- rule:startup-policy-read -->
  주 에이전트만 세션 시작 시 발행된 런타임 스냅샷을 한 번 조회하고, 본문과 메타데이터를 그 세션 동안 재사용합니다. 운영 지침의 검토·변경 요청이나 충돌·누락이 없는 한 정책 적용만을 위해 출처, 근거, 스킬을 추가로 탐색하지 않습니다. 작업별 스킬과 도메인 지식은 각각의 적용 조건에 따라 별도로 조회합니다.
- <!-- rule:policy-reuse -->
  이미 확보한 동일 지침과 문맥은 변경되었거나 사용할 수 없어진 경우가 아니면 중복 조회하지 않습니다.
- <!-- rule:policy-read-failure -->
  런타임 스냅샷 조회가 실패하면 실패를 명시합니다. 정책을 추측하거나 검색으로 복구하거나 자동 재발행으로 전환하지 않습니다.
- <!-- rule:subagent-policy-inheritance -->
  부모가 호출한 하위 에이전트는 런타임 정책을 다시 조회하지 않고 부모가 전달한 작업과 위임 범위를 따릅니다.
- <!-- rule:requirement-frame -->
  실행 전에 관련 사용자 원문, 확정 제약, 오케스트레이터 해석, 미검증 가정, 모호성, 기대 결과, 완료 기준, 객관적 위험 조건을 구분합니다. confidence는 위험 조건·모호성·검증 가능성·실패 비용 뒤에 두는 보조 신호입니다. 합리적 해석이 여럿이거나 요구 충돌, 불명확한 완료 기준·영향 범위, 낮은 confidence가 있으면 별도 요구사항 검토를 고려합니다.
- <!-- rule:mandatory-requirement-review -->
  인증·인가·권한·보안 경계, 데이터 삭제·변환·마이그레이션·schema 호환성, 공개 API·외부 인터페이스·영속 형식 변경, rollback이 어렵거나 광범위한 아키텍처 변경, 다수 서비스·모듈 또는 사용자 데이터·서비스 안정성에 중대한 영향을 주는 작업은 confidence와 관계없이 별도 요구사항 검토를 수행합니다. 중간 위험은 기본적으로 gpt-5.6-sol, 고위험 또는 구조적 불확실성은 gpt-6-astra에 맡깁니다.
- <!-- rule:review-source -->
  요구사항 검토자에게는 요약만 주지 않고 판단에 필요한 관련 사용자 원문, 확정 제약, 오케스트레이터 해석, 미검증 가정을 구분해 전달합니다. 전체 대화는 그 작업의 의미를 결정하는 데 필요한 경우에만 전달합니다.
- <!-- rule:review-integration -->
  검토 결과는 다수결이 아니라 사용자 원문, 확정 제약, 코드베이스 사실, 실행·검증 결과, 각 주장의 근거로 대조합니다. 중대한 반대 의견은 근거 없이 무시하지 않으며 쟁점이 해소되지 않으면 완료를 선언하지 않습니다.
- <!-- rule:min-delegation -->
  필요한 최소 깊이와 최소 수의 에이전트를 사용합니다. 독립 작업은 공유 상태와 통합 경계를 확인한 뒤 병렬화합니다.
- <!-- rule:parent-validation -->
  부모 에이전트는 서브에이전트가 제출한 산출물과 검증 근거를 완료 기준에 대조하며, 완료 보고만으로 성공을 판단하지 않습니다. 사용자 요구 충족, 필수 산출물 존재, 필수 검증과 근거, 중대한 미해결 이견이나 미확인 위험이 없음을 확인하고 위험과 증거의 충분성에 따라 추가 검증을 수행합니다.
- <!-- rule:model-routing -->
  Codex 작업에서 탐색·기계적 변경·쉽게 검증할 수 있는 저위험 작업은 gpt-5.6-luna, 일반 구현·버그 수정·분석·중간 설계와 검토는 gpt-5.6-sol, 고난도 구현·아키텍처 변경·광범위한 영향 분석·어려운 디버깅·고위험 검토는 gpt-6-astra를 기본으로 합니다. complexity, ambiguity, blast radius, failure cost, verification cost, required context, architectural impact와 재시도·검증을 포함한 작업당 총사용량을 함께 판단하고, 파일 수나 코드 줄 수만으로 모델을 고르지 않습니다.
- <!-- rule:reasoning-routing -->
  모델과 reasoning을 독립적으로 선택합니다. 탐색·기계적 수정·쉽게 검증하는 작업은 low, 여러 조건이나 파일이 얽힌 일반 설계·구현·디버깅은 medium, 높은 불확실성·광범위한 영향·고위험 변경·복잡한 원인이나 대안 분석은 high 또는 max를 사용하며 필요한 최소 수준을 선택합니다.
- <!-- rule:model-explicit -->
  Codex 서브에이전트를 호출할 때 모델과 reasoning을 각각 명시하며 모델 생략이나 reasoning의 암묵적 상속을 기본값으로 사용하지 않습니다. 이 규칙은 현재 주 세션의 모델 설정을 변경하라는 뜻이 아닙니다.
- <!-- rule:max-depth -->
  사용자가 직접 시작한 주 에이전트를 깊이 0으로 계산하여 최대 깊이 2까지만 허용합니다.
- <!-- rule:redelegation-boundary -->
  깊이 1 에이전트는 부모가 허용한 경우에만 재위임하고, 깊이 2 에이전트는 추가 에이전트를 호출하지 않습니다.
- <!-- rule:delegation-contract -->
  위임할 때 역할, 현재 깊이, 재위임 허용 여부, 목표, 범위, 문맥, 제약, 허용·금지 변경, 기대 산출물, 완료 기준, 검증 방법, 필요한 참조, 모델, reasoning을 명시합니다. 가능한 한 한 에이전트에 하나의 명확한 책임을 부여합니다.
- <!-- rule:minimal-context -->
  서브에이전트에는 작업에 필요한 최소 문맥만 전달합니다. 전체 대화는 작업에 필요한 경우에만 상속하며, 모델을 지정할 때는 모델 지정과 호환되는 문맥 전달 방식을 사용합니다.
- <!-- rule:batching -->
  같은 범위의 관련된 작은 수정은 한 번의 위임으로 묶습니다.
- <!-- rule:parallel-conflict-check -->
  병렬 위임 전 의존성, 파일과 생성물, 공유 상태의 충돌 가능성을 확인합니다. 충돌 없이 수행할 수 있고 통합과 검증이 명확한 작업만 필요한 최소 수로 병렬 실행합니다.
- <!-- rule:independent-verification -->
  같은 작업을 중복 배정하는 것은 위험에 따른 별도 검증 목적과 종료 기준이 명확한 경우에만 허용합니다. Codex 검증은 단순하면 gpt-5.6-luna, 일반 코드·설계면 gpt-5.6-sol, 복잡하거나 고위험이면 gpt-6-astra로 라우팅하며 작성 모델의 등급만으로 결과를 자동 신뢰하지 않습니다.
- <!-- rule:subagent-evidence -->
  서브에이전트는 산출물과 검증 근거를 함께 제출하고 막힘이나 충돌을 즉시 보고합니다. 직속 부모는 결과, 검증 근거, 미해결 사항을 간결하게 보고하며 필수 검증을 수행하지 못했다면 사유와 위험을 함께 밝힙니다.
- <!-- rule:retry-stop -->
  실패하면 요구사항 해석, 작업 분해, 전달 문맥, 범위 정의, reasoning, 모델 능력 순서로 원인을 진단합니다. 동일 원인의 실패가 2회 반복되면 같은 모델과 같은 작업 정의의 재시도를 멈추고 재분해, 요구사항 재검토, 문맥 보강, reasoning 또는 모델 승격, 독립 검토 중 원인에 맞는 방식으로 전환합니다.
- <!-- rule:mutation-boundary -->
  주 에이전트는 위임 범위 결정과 결과 검토에 필요한 조회·검증을 직접 수행할 수 있으나 작업 산출물이나 공유·외부 상태를 변경하지 않습니다. 검증 과정에서 생기는 변경은 작업 결과에 영향을 주지 않고 독립적으로 폐기할 수 있는 격리된 임시 파일과 캐시에 한해 허용하며, 그 밖의 상태 변경은 별도 규칙에서 주 에이전트의 직접 수행을 명시적으로 허용한 경우에만 가능합니다.
- <!-- rule:operation-metrics -->
  First-pass success rate, rework rate, escalation rate, requirement correction rate, review disagreement rate, 전체 모델 사용량, 완료 시간을 작업 단위로 기록합니다. Luna + max의 위험 누락·잘못된 분해·검토 이견 오판이나 재작업 비용이 반복되면 기본 오케스트레이터 가설을 재검토합니다.
<!-- policy:rules:end -->
