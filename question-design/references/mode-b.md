# MODE B. 다단계 리뷰 사이클 (오케스트레이션 상세)

> question-design 스킬의 MODE B 상세 절차. 리뷰 요청·구조적 문서 입력 시 이 파일을 읽고 진행한다.
> 공통 규칙(애매하면 먼저 질문, 침묵 디폴트)은 SKILL.md "핵심 원칙"을 따른다. 개별 confirm 지점의 디폴트는 그 원칙의 구체화다.

사용자가 "리뷰 돌려줘", "검토해줘", "더 날카롭게 만들어줘" 등을 요청하거나,
구조적 문서(기획안, 전략서, 분석 등)가 입력되면 자동 제안한다.

파이프라인은 5개 역할로 구성된다:

| 순서 | 에이전트 | 역할 | 사이클 |
|------|---------|------|--------|
| AGENT 0 | domain-knowledge-reviewer | 도메인 사실·표준·최신성 검증 (필요시 리서치 + 인지과학·심리학 렌즈) | Full·Lite |
| AGENT 1 | adversarial-reviewer | 1차 적대적 리뷰 (논리·구조·약점) | Full·Lite |
| AGENT 2 | genius-thinker | 천재적 사고 강화 (관점 전환·재설계) | Full |
| AGENT 3 | adversarial-reviewer | 재적대적 리뷰 | Full·Lite |
| AGENT 4 | flow-synthesizer | 전체 흐름 정리 + 최종 통합 | Full·Lite |

> **역할 분담 원칙**: AGENT 0·1·3(리뷰어)은 **진단만**(STATUS + 이슈 + 보완 방향). AGENT 2는 강화안을 낸다. **최종 전문(全文) 통합은 AGENT 4(flow-synthesizer)의 책임**이다. 즉 AGENT 2와 AGENT 4만 전문을 출력한다.

**접수·조립 규칙 (사이클 진입 전 1회):**
빠진 맥락(산출물 종류·목적·독자·형식·범위)만 물어 모은 뒤, `[리뷰 접수표]` 한 블록으로 조립해 보여주고 "이대로 진행할까요?"로 확인받는다. 확인 전 사이클에 진입하지 않으며, 확정된 접수표는 모든 에이전트 입력 패킷의 공통 헤더로 전달한다.

## 리뷰 사이클 선택 (Lite vs Full)

| 상황 | 권장 |
|------|------|
| 의사결정 영향도 큼(투자·전략·외부 공개) / 시간 1시간+ | **Full** |
| 산출물 5p+ 또는 이해관계자 3인+ 영향 | **Full** |
| 내부 공유·중간 점검·시간 제약 / 문서 1~2p | **Lite** |
| 초안 정렬·구조 점검 위주 | **Lite** |

```
Q. 리뷰 방식을 선택해주세요.
   A) Full 사이클 — 도메인 리뷰 → 적대적 리뷰 → 천재적 사고 → 재적대적 리뷰 → 흐름 정리 (깊고 느림)
   B) Lite 사이클 — 도메인 리뷰(경량) → 적대적 리뷰 → 재적대적 리뷰 → 흐름 정리 (빠르고 가벼움)
```

> **침묵 디폴트**: 사용자가 결정 위임("알아서")하면 **Lite**로 시작. 1차 리뷰 후 심화 필요하다고 판단되면 그때 Full로 승격 제안.

**MODE B 진입 직전 PII 가드레일 (1패스):**
이메일·전화·주민/사업자번호·카드번호·내부전용 마커·고객 실명+행위 조합을 1차 스캔. 발견 시 사용자에게 "마스킹 후 진행 / 그대로 진행 / 취소" 3지선다. 침묵 시 디폴트 = **마스킹 권장 + 그래도 답 없으면 취소**. 정규식 한계(특히 한국어 PII)는 LLM 휴리스틱 1패스로 보완하되 거짓 음성 위험은 사용자 책임으로 명시한다. PII·기밀 발견 시 AGENT 0의 **웹 리서치 하위 기능은 자동 보류**한다.

> **게이트 순서**: 이 PII 가드레일은 사이클 선택(Lite/Full)보다 우선한다 — 침묵 시 "취소"가 Lite 디폴트를 덮는다. 리서치 보류 여부도 여기서 오케스트레이터가 확정하며, AGENT 0은 그 결정을 따른다(자체 재판단하지 않음).

## 오케스트레이션 흐름

**Full 사이클:**
```
[입력: 초안 산출물]
       ↓
[AGENT 0: domain-knowledge-reviewer] ──(이슈 있음)──→ 보완 후 AGENT 0 재호출
       ↓ (STATUS: CLEAN)
[AGENT 1: adversarial-reviewer] ──(이슈 있음)──→ 보완 후 AGENT 1 재호출
       ↓ (STATUS: CLEAN)
[AGENT 2: genius-thinker]
       ↓
[AGENT 3: adversarial-reviewer] ──(이슈 있음)──→ 보완 후 AGENT 3 재호출
       ↓ (STATUS: CLEAN)
[AGENT 4: flow-synthesizer]  ※ 전체 흐름 정리 + 최종 전문 통합
       ↓
[최종 산출물 확정 → 사용자에게 전달]
```

**Lite 사이클:**
```
[입력: 초안 산출물]
       ↓
[AGENT 0: domain-knowledge-reviewer]  ※ 경량 — 치명적 사실오류·최신성만
       ↓ (STATUS: CLEAN)
[AGENT 1: adversarial-reviewer]       ※ 동일 에이전트, 다른 입력
       │  1차 호출: 원본 검증
       ↓  보완본 → 같은 에이전트 재호출(자기 재검증)
[AGENT 3: adversarial-reviewer]
       │  마지막 리뷰: 다음 리뷰 단계 없음 인지하고 종결 판정
       ↓ (CLEAN)
[AGENT 4: flow-synthesizer]  ※ 전체 흐름 정리 + 최종 전문 통합
       ↓
[최종 산출물 확정 → 사용자에게 전달]
```

## 에이전트 호출 규칙

- **AGENT 0 → 1 전환**: AGENT 0이 CLEAN 반환 시 (Full·Lite 공통)
- **AGENT 1 → 2 전환**: AGENT 1이 CLEAN 반환 시 (Full만)
- **AGENT 1 → 3 전환**: AGENT 1이 CLEAN 반환 시 (Lite — AGENT 2 건너뜀)
- **AGENT 2 → 3 전환**: AGENT 2 실행 완료 후 자동
- **AGENT 3 → 4 전환**: AGENT 3이 CLEAN 반환 시 (Full·Lite 공통)
- **AGENT 4 종료**: flow-synthesizer가 최종 통합본을 출력하면 사이클 종료. 이후 리뷰 단계 없음.
- **에이전트 입력 패킷** (호출자가 누락 항목을 채워 전달):
  - AGENT 0: `{원본 산출물, 산출물 종류, 사용자 의도, 사이클(Full/Lite)}`
  - AGENT 1: `{원본 산출물(AGENT 0 보완 반영본), 산출물 종류, 사용자 의도}`
  - AGENT 2: `{원본, AGENT 0·1 이슈 목록, AGENT 1 보완본}` — 이슈 의도 추적 위함
  - AGENT 3: `{원본, 이전 회차 이슈 목록, 이전 보완본, AGENT 2 강화본, 직전 회차에서 다루지 않은 점검 각도}`
  - AGENT 4: `{원본, 전 회차 이슈 목록(0·1·3), 각 보완 방향, AGENT 2 강화본, 미해결(잔여) 이슈, 사용자 의도·독자·형식}`
- **자기 재검증 점검 순서** (확증 편향 회피): 이전 회차 이슈가 보완본에서 해결됐는지 먼저 확인 → **이전 회차에서 다루지 않은 점검 항목을 우선 적용** → 신규 이슈 판정. 단, **수렴 판정 국면**(신규 이슈 0건 또는 동일 이슈 2회 연속 잔존)에 들어가면 새 점검 각도 추가를 멈춘다 — 무한 발굴(수직 깊이의 함정) 방지.
- **반복 상한**: 각 리뷰 에이전트 최대 5회 (가이드라인 — 무한 루프 방지용 안전장치). 실제로는 수렴 조건이 먼저 트리거되는 것이 일반적. flow-synthesizer는 반복 없이 1회 통합으로 종결한다.

**수렴 조건 (CLEAN 정의 — 형식화):**

다음 중 **하나라도** 충족되면 CLEAN.
- 직전 회차 대비 신규 이슈 0건
- 신규 이슈가 모두 "사소한 문구 수정" 수준 (구조적 결함 아님)
- 동일 이슈가 2회 연속 잔존(보완이 효과 없음 — 사용자 개입 권장 후 CLEAN 처리)

> **신호 vs 잡음 판별**: 절차 문서라면 산출물이 정의하지 않은 동작 분기를 1개 이상 발생시킬 수 있으면, 전략·기획 문서라면 결론·의사결정을 뒤집을 수 있으면 "신호(구조적 이슈)". 용어·문구·표현 수준이면 "잡음".

**적대적 리뷰의 본질적 한계 (메타 경고):**

> 매 회차 새 점검 각도를 추가하면 이슈는 무한히 발굴된다(수직 깊이의 함정). 따라서 CLEAN은 **"결함 0"이 아니라 "사용자가 정의한 종료 함수 통과"**임을 인지하라. 5회차에서도 ISSUES면 메인 오케스트레이터가 사용자에게 결정을 위임한다.

**에이전트 실패·형식 위반 폴백:**

| 상황 | 폴백 |
|------|------|
| 출력 형식 위반(STATUS 누락 등) | 1회 재시도 → 실패 시 호출자가 형식 보정 후 다음 단계 |
| 응답 비어 있음 | 1회 재시도 → 실패 시 "리뷰 불가" 라벨로 종료 |
| 매 회차 ISSUES만 반복(수렴 실패) | 수렴 조건(동일 이슈 2회 연속 잔존) 충족 시 CLEAN 처리. 그래도 신규 이슈만 계속 나오면 **반복 상한(5회)**에서 사용자에게 위임(아래 보고 형식). 미해결 이슈는 "잔여 위험"으로 AGENT 4에 전달·노출 |
| ISSUES인데 보완 방향 미첨부 | 1회 재시도 → 실패 시 이슈 목록만 보존 후 진입 |
| AGENT 0 리서치 불가(PII·네트워크·확정 실패) | 리서치 보류 → "확인 불가" 라벨로 이슈 보존, 사용자 검증 권장 |
| AGENT 4(통합) 비어 있음·형식 위반 | 1회 재시도 → 실패 시 직전 CLEAN 회차의 최선 보완본을 최종본으로 채택하고, 자동 통합 불가 사실을 사용자에게 알림 |

> AGENT 0/1/3의 출력은 **STATUS + 이슈 목록 + 보완 방향**만. 보완본 전문 출력은 형식 위반이며, 통합은 AGENT 4(flow-synthesizer)의 책임이다.
>
> **STATUS 예외**: genius-thinker(AGENT 2)는 STATUS를 출력하지 않는다(AGENT 2→3 자동 전환). 위 "STATUS 누락" 폴백은 AGENT 0/1/3에만 적용한다.

반복 상한 도달 시 보고 형식:
```
[반복 상한 도달]
에이전트: (이름) / 반복: 5회 완료
미해결 이슈: (목록)
선택해주세요:
   A) 현재 상태로 다음 단계 진행 (잔여 위험 노출)
   B) 사용자가 직접 이슈 판단 후 재시작
   C) 종료하고 종합 보고만 받기
```

## 에이전트 파일

위 파이프라인 표의 각 역할은 `agents/` 파일로 구현된다(AGENT 1·3은 adversarial-reviewer 공용). 파일 목록·역할 요약은 라우터 SKILL.md "구성 파일" 한 곳에서 관리한다.
